# Codex-on-local-Qwen pipeline — findings (2026-05-13)

Session goal: get the local primary model (Qwen3.6-35B distill) to
implement the `oicp-types` crate end-to-end when driven by codex CLI
0.130 against the local commonwealth daemon. Starting point: 5/30
(16%) on a hand-authored fixture gym; the live smoke spent 19 turns
reading files and never wrote a line.

End point: 45/45 (100%) on a 9-fixture suite covering distinct
failure modes captured from real codex smokes; live smoke writes
both `Cargo.toml` and `src/lib.rs` with real Rust content, zero
patch verification failures, and the three-mode sampler picks
profiles per emission role without any call-site heuristic.

## What landed

### 1. Heredoc canonicalizer (`commonwealth-api::frontdoor`)

Post-emission structural repair of malformed `apply_patch` heredocs.
Symptoms in the wild:

- `*** Begin Patch ***` (extra trailing `***`)
- `Add File: <path>` without the leading `*** `
- `*** End Patch EOF` (closing tag inlined with the marker)
- Missing `*** End Patch` entirely (heredoc body ends directly at
  the closer)
- Body lines without the required `+` prefix (Cargo.toml fields,
  multi-line `pub struct` bodies)
- AddFile sections with leading whitespace where the parser expects
  `+` (codex rejects `<space>foo` as "not a valid hunk header")
- TOML files wrapped in JSON object braces with trailing commas
- Multi-line inline tables (`dependencies = {` followed by newline)
  instead of `[dependencies]` section headers

The canonicalizer parses structural intent and re-emits in canonical
form. Lives in `canonicalize_apply_patch_heredoc()` plus
`canonicalize_patch_body_lines()` and `repair_toml_body()` for
content-level repairs. Wired into both the non-streaming chat
response path and the SSE streaming-response translator in
`routes_responses` (gym 008 caught the missing streaming wire).

### 2. Path canonicalizer

Tokenizer-drift detector. Model's BPE has `/tos` as a single token
while `/atos` is multi-token; greedy emits `/tos-experiment-X` even
when context exclusively contains `/atos-experiment-X`. Fix:
frequency-weighted per-component canonicalization — if an emitted
path component is similar (Levenshtein ≤ 2) to a more-frequent
component in the request context, rewrite. Works even when the
typo variant *also* appears in context (real fixture had a
compressed-history block reciting the model's prior typo).

### 3. Chat-side reshape (anti-repetition, failure-recovery,
read-attractor)

Three surgical pre-generation nudges:

1. **Anti-repetition**: detects ≥3 identical assistant tool_call
   emissions, injects a synthetic user message naming the call and
   instructing strategy change. Envelope-shadow assistant messages
   are treated as transparent (the captured-input shape pairs each
   tool_call with an identical envelope-content sibling).
2. **Failure-recovery**: when the tail of `messages` is a tool
   result with non-zero exit, deletes the failed assistant call
   from history (redaction left the model echoing the placeholder;
   deletion gives it nothing to copy), prepends a `[FAILURE — exit
   code N]` banner to the tool result, appends a user-message
   nudge naming concrete alternative commands.
3. **Read-attractor**: when ≥3 read-classified exec_command calls
   are in history with zero action calls, swaps codex's 20K
   explore-first system prompt for a focused write-mandate,
   rewrites the compressed-history user message to keep only the
   task seed, and trims raw read history. Targets the deepest
   attractor — codex CLI 0.130's RL prior pushes the model to
   "explore the codebase" indefinitely.

All three share an idempotency gate so a single turn only ever
gets one nudge.

### 4. Three-mode sampler with `ModelQuirks` per-mode profiles

`ModelQuirks` (canonical model-specific config in
`sovereign-core::model_family`) gained two new profile blocks
alongside its existing `default_*` (think) profile:

- `instruct_*` — non-thinking general work
- `code_*` — coding work (composing code, drafting patches)

Each family declares its own values per profile. For Qwen3 the
recommendations from the model card landed verbatim:

| Profile  | T   | top_p | top_k | presence_penalty |
|----------|-----|-------|-------|------------------|
| Think    | 1.0 | 0.95  | 20    | 1.5              |
| Instruct | 0.7 | 0.80  | 20    | 1.5              |
| Code     | 0.6 | 0.95  | 20    | 0.0              |

Mode picker in `build_sampler`:

- Tool-call **Explore** role (between JSON string boundaries — model
  is picking tools) → Instruct
- Tool-call **Content** role (inside a `cmd` JSON string — model is
  composing code) → Code
- No tools, `enable_thinking=false` → Instruct
- No tools, otherwise → Think

Content-role temperature stays at greedy (0.0) by default even
under Code profile — the apply_patch envelope markers (`*** Begin
Patch`, `*** Add File:`) need exact discipline that T=0.6 sometimes
breaks. The OTHER Code-profile knobs (top_p, presence, top_k) still
apply. `SOVEREIGN_CONTENT_TEMPERATURE` env overrides if needed.

No call-site heuristic decides mode. No `if has_tools { Code }`
branch in routes. The model's own token-level structure (which
sampler role it's currently in) drives mode selection.

## What's still broken (model-content, not pipeline)

- **Dependency drift**: `lib.rs` uses `uuid::Uuid` but `Cargo.toml`
  doesn't list `uuid` as a dep. Model doesn't keep cross-file
  consistency. Would fail `cargo check`.
- **Stub-as-final**: `lib.rs` declares `pub mod error; pub mod
  message;` etc but doesn't create the submodule files. The model
  treats the modular declaration as "done" without following
  through.
- **Cargo.toml indentation**: leading spaces on `[package]` lines.
  TOML parses fine (whitespace insensitive) but stylistically odd.
  Likely an artifact of `+` prefix injection landing in the wrong
  column.
- **Iteration count**: takes ~24 min to produce a 2-file crate
  shell. Model isn't choosing the tightest path through the work;
  it re-reads files it just read several turns earlier.

## Architecture as it stands

```
┌──────────────────────────────────────────────────────────────────┐
│ codex CLI 0.130 (/v1/responses, SSE streaming)                   │
└──────────────────────────────────────────────────────────────────┘
        ↓ POST /v1/responses (instructions, input[], tools[])
┌──────────────────────────────────────────────────────────────────┐
│ commonwealth-api::routes_responses                               │
│  - translate ResponsesRequest → ChatCompletionRequest            │
│  - apply_codex_brief (Codex profile)                             │
│  - apply_anti_repetition (Responses-side input items)            │
│  - history compression (block-based)                             │
│  - Codex T pin (0.7) when caller didn't set one                  │
└──────────────────────────────────────────────────────────────────┘
        ↓ chat_completions(state, headers, Json(chat_req))
┌──────────────────────────────────────────────────────────────────┐
│ commonwealth-api::routes_inference::chat_completions             │
│  - apply_failure_nudge_chat (delete failed call + banner)        │
│  - apply_anti_repetition_chat (envelope-shadow aware)            │
│  - apply_read_attractor_nudge_chat (system swap + trim)          │
│  - gather_context_components (for path canon)                    │
└──────────────────────────────────────────────────────────────────┘
        ↓ service.chat_completion(request)
┌──────────────────────────────────────────────────────────────────┐
│ sovereign-inference::embedded::generate_sync_stream*             │
│  - Tokenize prompt                                               │
│  - build_sampler:                                                │
│      • picks per-role profiles from ModelQuirks                  │
│      • Explore = Instruct (or Think if no tools, no thinking-off)│
│      • Content = Code (or Think if no tools)                     │
│  - Per-token generation:                                         │
│      • track tc_json_in_string (role detector)                   │
│      • sampler.sample(ctx, idx, role)                            │
│      • stop on </tool_call> marker OR balanced JSON envelope     │
└──────────────────────────────────────────────────────────────────┘
        ↓ ChatCompletionResponse with tool_calls
┌──────────────────────────────────────────────────────────────────┐
│ chat_completions post-process (both streaming + non-streaming)   │
│  - canonicalize_chat_response_tool_calls                         │
│      • heredoc canonicalizer (markers, body prefix, TOML repair) │
│  - canonicalize_chat_response_paths                              │
│      • frequency-weighted per-component path rewrite             │
└──────────────────────────────────────────────────────────────────┘
        ↓ back through routes_responses → SSE → codex
```

Every layer is single-responsibility. Inference layer reads model
quirks; doesn't know about codex. Frontdoor knows about model
emissions; doesn't know about sampling. Routes know about wire
shapes; don't know about model behavior. SOLID lines hold.

## Further research (next session)

### High-leverage, gym-shaped

- **Cross-file dependency tracking**. Capture a fixture where the
  model writes `use foo::Bar` in `lib.rs` while `Cargo.toml` lacks
  the `foo` dep. Fix: post-emission scan of newly-added Rust
  imports; cross-reference against Cargo.toml; auto-add missing
  deps via a follow-up Update File patch (or surface a structured
  "dep gap" diagnostic the agent must act on next turn). Same
  mechanical-repair philosophy as the TOML body canonicalizer.
- **Stub-as-final detection**. Fixture: model writes `pub mod foo;`
  but never creates `src/foo.rs`. Fix: post-emission analysis of
  the patch + workspace state; surface "declared but missing"
  modules to the agent as a virtual tool result that prompts the
  next turn to create them.
- **Iteration efficiency**. Capture the "re-read what we just
  read" pattern (codex re-issues `cat oicp-v0.3.md` six turns
  after the first read). Fix: cache tool_result content keyed by
  cmd, return cached on a duplicate-within-N-turns invocation
  with a `[runtime] returning cached result, N turns ago` banner
  — saves model latency and prevents the in-context evidence
  doubling that worsens read-attractor pressure.

### Architectural

- **~~Add `min_p`, `repetition_penalty`, `frequency_penalty` to
  `ModelQuirks`~~** — DONE. `default_min_p` / `default_repetition_penalty`
  / `default_frequency_penalty` added to `ModelQuirks` with
  serde-default compat helpers (existing `models.toml` overrides
  keep llama-cpp tradition: 0.05 / 1.15 / 0.1). Qwen3 family
  overrides land card values (0.0 / 1.0 / 0.0). `build_sampler`
  reads from quirks instead of hardcoded constants.
- **~~Per-mode `ChatCompletionRequest` field~~** — DONE.
  `sovereign_core::types::SamplingMode` enum (`instruct` / `code` /
  `think`, serde-snake-case) landed. `CompletionRequest.sampling_mode`
  and `ChatCompletionRequest.sampling_mode` plumbed.
  `inference_adapter::build_completion_request` forwards.
  `build_sampler` honors explicit caller mode first; auto-picks
  only when None.
- **Streaming-side path canonicalizer**. Heredoc canonicalizer is
  wired into both streaming and non-streaming paths; path
  canonicalizer is non-streaming only. Codex traffic streams. Land
  the streaming wire so `/atos`-style typos get repaired in real
  smokes too.

### Validation

- **End-to-end smoke that runs `cargo check`**. Current smoke kills
  codex before it gets to verification. Let the smoke run to
  natural completion (or extend timeout) and grade on whether the
  resulting crate compiles. The gym's pass/fail predicates check
  emission shape; only a real `cargo check` proves the model
  produced *correct* code.
- **Model-content quality gym fixtures**. The protocol-level gym
  is saturated at 100%. The next gym tier should probe content:
  Rust syntax errors, missing-but-used imports, Cargo.toml
  features that aren't defined, etc. Each fixture's `pass.yaml`
  would invoke a real `cargo check` against a temp scratch dir.
- **A/B against `cargo` workspace patterns**. Some Cargo.tomls in
  the repo use `workspace = true` shorthand for versions; our
  smoke is standalone so `workspace = true` is invalid. Add a
  smoke-mode detector that recognises workspace context and
  rejects/repairs `workspace = true` in standalone Cargo.tomls.

### Speculative

- **Sampler-side forbidden tokens**. The path-typo fix mechanically
  rewrites post-emission. A more aggressive option: feed the
  prior-context paths into the sampler as positive bias / forbid
  the typo-token at sample time. Requires logit-bias support on
  the request shape + plumbing into the LlamaSampler chain.
- **Distinct profile per-tool**. The Code profile is one-size for
  all coding work. Reality: writing Rust differs from writing
  TOML differs from writing JSON. A per-language sampling profile
  (configured by file extension when the model is inside an Add
  File of `*.toml` vs `*.rs`) would let us tighten T for TOML
  (which is unforgiving) and loosen it for Rust (which has more
  legal variation).
- **Real `<think>` budget for codex with thinking on**. We
  currently force `enable_thinking: false` on codex traffic
  because the 85% token spend on thinking blocks adds zero value
  for routine tool turns. But for the actual code-composition
  turns (rare, high-value), thinking might pay off. Per-turn
  enable_thinking driven by the same role detector that picks the
  sampler mode could buy substantial quality without inflating
  cheap turns.

## Methodology that worked

The "user bug → gym fixture → mechanical fix → verify in smoke"
loop. Every failure captured from a live smoke became a fixture;
every fix landed structurally in frontdoor or sampler; every fix
got verified against the gym AND against a fresh live smoke. The
two failure classes the gym surfaced:

- **Pipeline malformations** (heredoc shape, path typos, JSON-vs-
  TOML confusion, body prefix discipline) — mechanically repairable
  in frontdoor.
- **Behavioral attractors** (read loops, verbatim retries,
  exploration-mode lock-in, repetition) — addressed via pre-
  generation context reshape (anti-rep, failure-nudge, read-
  attractor) and sampler-level config (Qwen card values).

Both classes generalize beyond this specific model/harness; the
fixtures are model-agnostic acceptance criteria for any future
model swap.
