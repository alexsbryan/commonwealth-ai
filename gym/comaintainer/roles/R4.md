# R4 — independently verify claimed work

**The card for this role is `gym/comaintainer/CHARTER.md`, unchanged.**
It is versioned beside the gym that scores it and changes only by
operator-approved PR. `co-role.py` sends charter + `contract.txt` +
the landing bundle; this file adds nothing to the prompt and must not
grow into a second charter (§10.6 — one decider).

What this file records is the wiring, so a reader of the roles
directory sees R4 the same way as the other five.

## Gate

`charter` — the landing gate the charter already defines, not a new
one. S-sized, reversible, non-main landings may close on the seat's
verdict; everything else reaches the operator. R4 is the one role whose
gate is neither plain `draft` nor plain `auto`.

## What the harness adds

Two checks the model cannot do for itself, both after the reply:

1. **The verdict must be one of the six** and must carry the argument
   field its verdict requires (`markers.extract_verdict`). A malformed
   reply is its own outcome class, never folded into disagreement.
2. **Every cited anchor must resolve** (`score.basis_gate`). An anchor
   that does not resolve demotes the verdict to `could-not-judge` and
   keeps what the engine proposed under `proposed_verdict`. contract.txt
   is explicit that anchors are never invented; before 2026-08-19 that
   rule was enforced only in the offline gym, and a live verdict's
   citations reached the operator's page unchecked.

## Canary

R4 runs alongside a planted-defect canary — a known-bad landing whose
only correct verdict is not-approve. Approving it HALTS the run. Schemas
check form and parsers check shape; neither checks judgment, and this is
the only thing here that does (§18.1, made continuous).
