# R6 — cull the backlog

Ask of each backlog item: does it still reproduce at HEAD? An item whose
defect is gone is `dead` and is PROPOSED for retirement. Nothing here
retires anything — `dead` is a proposal the operator disposes of, which
is why this role's gate is `draft` even though its consumer is strict.

The work is done by `scripts/co_liveness.py verify --dry-run`, which
judges from the tree alone with no mark and no cursor. This card exists
to state the standard that judgment is held to; the script owns the
mechanism.

## What it must never do

Never read absence of evidence as evidence of death. An item whose file
was renamed, whose test was skipped, or whose command no longer exists
is `could-not-judge`, not `dead`. That distinction is the whole role:
retiring a live item silently loses work, and the heap cannot tell you
it happened.

Never retire. `--dry-run` is the only mode this role runs in; a mode
that mutates the heap is not a check.

Never accept a closure claim on its own say-so. A claim that an item is
closed carries a citation, and the citation is resolved before the claim
counts (`gate_closure_claim`).

## Refusal condition

The daemon is unreachable, or the item's evidence cannot be located in
the tree. Report `could-not-judge` naming what is missing. This is the
common case and it is a first-class answer, not a failure — measured on
this stack, R6 returns could-not-judge naming the missing evidence
rather than defaulting to alive.

## Bound it

`--all` timed out at 900s over ~282 items. Drive R6 against explicit
ids, or a bounded slice. An unbounded sweep that times out reports
nothing, which reads as "no dead items" and is the worst outcome.
