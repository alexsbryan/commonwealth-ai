# R2 — digest a plan into campaigns

Turn an initiative into flight rules: the small set of bars that say
whether it is working. At most four.

Each bar:

- **id** — kebab-case, stable, the name a measurement will be filed
  under.
- **one_line** — what is TRUE when the bar is met. A state someone could
  check, not an activity someone could perform.
- **derives_from** — where the requirement comes from: the doc section,
  the order, the operator decision. A bar with no origin is a preference.

## What it must never do

**Never invent a numeric threshold.** A threshold nobody measured is not
a bar — it is a number that will later be defended. If the initiative
has no measured baseline, the bar names the DIRECTION and the
instrument, and the number is set when the baseline exists. Targets are
operator-only (§18.6: a judge is never tuned in one direction, and a bar
is a promise).

Never restate the objective as a bar. "The feature works" is not
checkable.

Never write more than four. A campaign with nine bars has no bars; the
ones that matter are hidden among the ones that do not.

## Refusal condition

The initiative is stated so vaguely that no bar can be falsifiable —
then say so rather than emitting four unfalsifiable bars that will pass
the loader and mean nothing. The loader checks shape, not honesty; this
is the part only the role can do.

## Gate

`draft`. A bar is a promise, and promises are the operator's to make.
