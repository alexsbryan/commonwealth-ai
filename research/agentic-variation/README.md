# Agentic variation operators applied to the retrieval lane

Topic opened 2026-09-04. Source: **AVO — Agentic Variation Operators for
Autonomous Evolutionary Search**, Chen et al., arXiv:2603.24517.

## What the paper does

Classical evolutionary search factors variation as `Vary(P) =
Generate(Sample(P))`, which pins the model inside `Generate` and hands
ancestor selection to a fixed policy (tournament, top-k, a MAP-Elites cell).
AVO replaces the whole factorisation with one autonomous agent run:

    Vary(P_t) = Agent(P_t, K, f)

`P_t` is the full lineage of prior solutions **with their scores**, `K` a
domain knowledge base, `f` the scorer, callable. The agent decides which
ancestors to read, reads several per step, compares their profiles, consults
`K`, edits, calls `f`, and iterates until it commits.

Result: 7 days unattended, 40 committed CUDA kernel versions from 500+
internally-explored directions (8% commit rate), beating cuDNN by 3.5% and
FlashAttention-4 by up to 10.5% on B200. The MHA-evolved kernel adapted to
grouped-query attention in ~30 minutes and held its gains — their transfer
check.

## The four elements that are actually load-bearing

| Element | Paper | Nearest thing here | Gap |
|---|---|---|---|
| Agent picks its own ancestors | reads several prior versions/step, compares profiling | `scripts/intent.py` reconstructs argument-per-symbol from prose | no `P_t` object exists |
| Lineage = commits with scores attached | git commit + score, monotone | git history; scores live in `sovereign/bench/*/baselines/` | **score is not on the commit** |
| Vector `f`, hard zero on correctness | `f(x)=(f_1..f_n)` per test config; correctness failure zeroes all | `retrieval-prod` emits per-question `source_score.ratio` + `fact_score.ratio`; other lanes emit `{value, direction, tolerance}` maps | already present, unused as a gradient |
| Supervisor detects stall + cycling | reviews trajectory, re-steers | the operator does this by hand (`AGENTS.md` §19: "each catch came from the operator, never from the builder's own process") | not computable until scores are on commits |

## Why the retrieval lane and not something else

`sovereign/docs/RUNBOOK.md` §6 states the noise band for retrieval recall as
**"exact — any delta is real (embeddings + ANN are stable)"**. AVO needed 10
runs per config for a mean and stddev because a GPU clock is noisy. A
deterministic `f` makes a one-run delta a measurement, which is the only
condition under which a 40-generation hillclimb produces signal instead of 40
committed versions of noise. The SOFT synth lanes (LLM judge, +-0.04-0.06
run-to-run, ~55 min) fail that test and are not candidates.

`K` for this domain already exists and is freshness-gated:
`sovereign/docs/retrieval-pipeline.md` (161 lines — step sequences, the full
`SOVEREIGN_*` knob registry, verdict buckets), regenerated by a test that
fails the build when it disagrees with the code. Plus
`sovereign/bench/HISTORY.md` and `sovereign/bench/BENCH_LOOP.md` for what has already been
tried and refuted.

## The disanalogy that decides everything

A faster kernel is faster; throughput is not a held-out-set question.
Retrieval recall against a fixed question bank **is**. Forty generations
against `sep/questions` will produce forty generations of fitting
`sep/questions`. This is the one place the paper's setting is strictly easier
than ours, and it is why the first experiment tests transfer rather than
gains.

## Build order (only after the pre-registration returns green)

1. **Score on commit.** `run_lane` at `scripts/sovereign-ci-bench.sh:387`
   already writes the report JSON; write its metric map to a git note on
   `refs/notes/bench`. `P_t` then costs one `git log --notes=bench` to read.
   Worth doing alone: `scripts/evidence-verdict.py` (1105 lines) and
   `scripts/intent.py` (184) both currently infer from prose what this states.
2. **Monotone commit gate.** Land only when correctness holds and no metric
   regresses past its declared `tolerance`. Failed attempts go to a scratchpad
   trajectory, never the notes store — an 8% commit rate written to notes
   recreates the store-rot problem.
3. **Stall/cycle supervisor.** Trigger: N consecutive commits with no metric
   movement, or repeated edits to the same symbols with none.

Not building: population branching. AVO didn't either ("leaving
population-level branching and archive management to future extensions"), and
a MAP-Elites archive over a single-main-branch repo is ceremony.
