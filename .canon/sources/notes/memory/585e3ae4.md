# When emitting shell snippets for the user to paste, join them with ; or && on one line — multi-line blocks force them to mangle the paste**

**When emitting shell snippets for the user to paste, join them with `;` or `&&` on one line — multi-line blocks force them to mangle the paste**

When outputting shell commands for the user to copy-paste into their terminal, put the whole sequence on a single line using `;` or `&&` to chain. Do NOT emit multi-line code blocks for runnable command sequences.

Why: terminals choke on pasted multi-line blocks (zsh prompts on each newline, blank lines fire empty commands, line continuations get eaten). The user has flagged this multiple times; multi-line snippets cost them friction every paste.

How to apply:

- Single command: leave it on its own line, no chaining.
- Multi-step sequence: join with ` && ` (stop on first failure) or `; ` (run regardless), all on one line. Wrap long lines if needed but keep them in ONE pasteable line per logical sequence.
- Heredocs / multi-line file edits the user must run: still inline; if truly multi-line is required, call that out and offer an alternative (e.g., `printf`).
- Examples:
  - Good. `mkdir -p ~/.sovereign/indexes/_downloads && curl -L -o ~/.sovereign/indexes/_downloads/sep.parquet https://...parquet`
  - Bad. A fenced block with each step on its own line.

This rule applies to user-facing copy-paste blocks ONLY — internal Bash tool calls can use whatever shape works.
