# Run the full test suite only at the END of a multi-slice initiative, not after each slice.

Run the full test suite only at the END of a multi-slice initiative, not after each slice.

When building a multi-slice feature/initiative, do NOT run the full test suite after each slice — build all the slices, then run tests once at the end.

Why: each full-workspace run (`./scripts/sovereign-test.sh`) is ~8 min; running it per slice kills momentum. The user explicitly interrupted a per-slice test run to say "Skip the tests — I only want to run tests at the end of the initiative."

How to apply: write all the slices of an increment, deferring compile/test verification to a single pass at the end. Be extra careful writing code (no per-slice compile feedback to catch errors early — re-read the seams, match signatures exactly). The watcher being `not_configured` is why each check fell back to the slow full script; if the watcher were live, `lint_status`/`test_status` would be cheap and this wouldn't bite.
