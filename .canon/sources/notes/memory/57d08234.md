**Standard tuning loop runs through `sovereign bench all` — cross-corpus rollup discovers every bench + diffs against baselines**

The standard tuning loop for enrichment + retrieval work is:

1. Iterate (prompt edits, scorer changes, projection arms, classifier tweaks).
2. `sovereign bench all` (no flags = dev loop, score-only against existing atoms + live daemon).
3. Read the cross-corpus matrix; identify which corpus + which lever moved.
4. The lever names the owner — resolver / scorer / classifier / retrieval ranker (see `sovereign/bench/README.md` "Lever map").
5. If improvement is real: `sovereign bench all --filter <bench> --update-baseline` retargets `latest.json`.

Spinning up a new bench for a fresh corpus:

1. `sovereign enrich init <id> --pipeline <atlas>` + `sovereign enrich build <id>` (or sync atlas via mesh).
2. `sovereign bench scaffold <id> --output sovereign/bench/<group>/<id>.toml` — samples 10 entries per axis from atoms.json, emits draft golden.
3. Review + prune the draft. Tighten `name_contains_any` to canonical substrings, fill `description_keywords_any` from the source, add `forbidden_*` blocks for known failure modes.
4. `sovereign bench all --filter <group>/<id> --update-baseline` — captures the reviewed-golden's scores as the new baseline.
5. Iterate per the standard loop above.

Why: before `bench all` (landed 2026-05-15), changes to the pipeline silently regressed corpora outside whatever the current campaign focused on. Move 1 (typed-axis catalog) landed without rerunning literary / sep / wikipedia. The cross-bench rollup makes a regression on any of the four atlases (literary, wikipedia, sep, obsidian) visible in one command.

How to apply:
- Always run `sovereign bench all` before claiming an enrichment / retrieval change is complete.
- Filter by group + bench id pattern when iterating: `--filter obsidian/golden`. Default = every discovered bench.
- `--rebuild` re-extracts the enrichment-lane atlas (GPU-bound, sequential, minutes to hours). Use for resolver / Phase 1 prompt changes. Score-only is fine for scorer / catalog / golden changes.
- Baselines live at `sovereign/bench/<group>/baselines/<bench-id>/latest.json` (symlink → dated snapshot). New corpus authoring runs first → captures baseline → subsequent runs diff.
- The four-atlas coverage (literary, wikipedia, sep, obsidian) splits across two surfaces: literary + obsidian have enrichment goldens; sep + wikipedia have retrieval banks (different scoring shape, complementary lever set). Both fold under `bench all` automatically — no per-surface invocation.
