The user's bar for the inference stack — \"could a mid-level engineer understand it quickly and manage it competently?\"; rationalize accreted design from first principles

The test to approach the inference stack with (user, 2026-06-10, during the retrieval-pipeline collapse): "Could I hand this off to a mid-level engineer and trust that they could understand it quickly and manage it competently?" The system accreted over months, not always in an aligned way — part of any initiative here is rationalizing it from first principles, not just preserving historical behavior.

Why: Accretion artifacts (e.g. KnowledgeQuery silently skipping mesh + store search while DeepQuery used both) look like deliberate tuning but are just "the feature landed on whichever path existed that week." Preserving them as "documented divergences" still fails the hand-off test — the mid-level engineer reads them as bugs, because from first principles they are.

How to apply: When auditing a subsystem, separate WHAT-varies-by-design (e.g. intent → model tier/expansion/synthesis shape) from WHAT-should-be-invariant (e.g. which knowledge sources exist = property of the install, never of the intent label). Trace each divergence to its introducing commit; "no principled reason found" + user sign-off → converge, don't defer. Prefer structures a newcomer can state in one sentence (shared head + shared core + per-intent tails). Related: [[retrieval-pipeline-collapse-phase1]], [[embed-router-over-keyword-classification]].
