**Route on `status` first. `watcher_active` is now derived honestly post-2026-05-08 fix, but `status` is still the field that tells you what to do.**

When `sovereign tools call lint_status` (or `test_status`)
returns a JSON payload, **route on `status` first**. Everything
else is supporting detail.

| `status`         | What to do                                                                |
|------------------|---------------------------------------------------------------------------|
| `fresh_passing`  | Build is clean. Continue.                                                 |
| `fresh_failing`  | Errors are in `errors`. Fix them. Don't run cargo.                        |
| `running`        | A run is in progress. Continue with other work, check back later.         |
| `stale`          | Watcher knows files changed but hasn't run yet. Wait ~15s, re-check.      |
| `never_run`      | Watcher genuinely isn't configured for this workspace. Now use Bash.  |

Only `never_run` justifies the Bash fallback.

**About `watcher_active`:**

Post-2026-05-08, this field is derived honestly. In CLI mode
(reading the daemon's shared store via `sovereign tools call`),
the value is `true` iff the last run was within ~10 minutes OR
a run is currently in progress. In daemon mode (the daemon's
own MCP surface), it reflects the live FS-watcher subscription.
Before the fix, the CLI hardcoded the flag to `false`, which
made it look like the watcher was broken even when it was
working — see `feedback_mcp_toolchain.md` for the broader
toolchain discipline.

You can still sanity-check by reading both fields, but they
agree now: `status` other than `never_run` ⇒ `watcher_active:
true` in normal operation.

Quick triage one-liner when the response is large:

```bash
sovereign tools call lint_status --format=json | \
  jq -r '"status=\(.status) age=\(.age_seconds // 0)s watcher=\(.watcher_active)"'
```

**If `status: never_run` AND `~/.sovereign/workspace` exists AND
the config is at `<workspace>/.sovereign/sovereign.toml`** — the
daemon needs a restart per `reference_daemon_restart_lwcr.md`.
That's the only genuine "watcher broken" path.

Same rule applies to test_status / get_lint_output / get_run_output / build.
The `status` field is universally the source of truth across
the watcher tools.
