Multi-turn learner bench grades per-turn deterministically (substring) and per-thread via one judge call on primary slot — never per-turn judge.

For wikipedia_learn (and any future multi-turn retrieval bench): the judge is thread-level only, never per-turn.

Why. Per-turn judge × 5-8 turns × 12-15 threads = 60-120 grading LLM calls per bench run. Falling back to Fast slot for cost would compromise grading quality on multi-paragraph synthesis answers (Fast is 2B; misjudges nuanced coverage). Thread-level judge runs once on primary, sees the full transcript, scores holistically against the union of `expected_facts` across turns. Per-turn signal is preserved via deterministic substring/title scorers (free, no LLM), which feeds the degradation curve.

How to apply.
- Per-turn captures (no LLM): `fact_recall` (substring count over retrieved chunks or final answer), `source_recall` (title hits in top-K), `prompt_tokens`, `wall_ms`, `routing_intent`.
- Per-thread one judge call on primary: input = thread description + all (Q, A) pairs concatenated + aggregated `expected_facts`. Output = list of fact_id → {found: bool, evidence_turn: usize}.
- The judge's `evidence_turn` field gives the per-turn LLM-grade resolution back, at a fraction of the cost.
- Degradation curve uses the deterministic per-turn `fact_recall` — that's the bench's headline metric, not the judge.
