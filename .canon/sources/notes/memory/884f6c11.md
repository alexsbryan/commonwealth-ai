**Use `lint_status --changed` (or `--files a.rs,b.rs`) during active editing — answers "are MY files clean?" against the most recent completed run while a workspace check is still trundling.**

`lint_status` now accepts `files: [path...]` and `changed: bool` params. Use them during active editing instead of plain `lint_status`.

Why: The workspace-level `status` field returns `running` while cargo grinds through the full check after every edit batch — useless for the active-edit loop ("are my files clean?"). The per-file mode answers that question against the *most recent completed run*, even while the next run is in progress.

How to apply:
- During active editing: `sovereign tools call lint_status --changed=true` (auto-derives the file list from `git diff --name-only HEAD` + untracked `.rs` files). Read `files[]` entries — each has `status: fresh_passing | fresh_failing | stale | never_checked`, `checked_at_unix`, `mtime_unix`, and per-file `errors` / `warnings` counts.
- For an explicit list: `--files=a.rs,b.rs` (workspace-relative or absolute paths).
- For pre-commit / pre-push: plain `lint_status` (no flags) — workspace-wide answer.
- The top-level `errors[]` and `warnings[]` are filtered to the queried file set when a filter is active. Workspace-wide counts are still in `summary`.

Wired in `sovereign-tools/src/code/lint_status.rs` (LintStatusTool). Registered at three sites with `with_workspace_root(repo_root)`:
- `sovereign-cli/src/tools_cmd/registry.rs:167`
- `sovereign-cli/src/daemon_cmd.rs:1199`
- `sovereign-cli/src/project_cmd.rs:2903`

Landed 2026-05-11 in the architecture-drift session as a workflow optimization — the watcher itself wasn't slow, `lint_status` was just answering the wrong question.
