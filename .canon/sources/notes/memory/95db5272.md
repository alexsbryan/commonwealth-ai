Never report bench outcomes as just \"improved/regressed\" labels — show the actual before→after numbers, per-question where deltas exist

When reporting bench results, do NOT relay the gate's categorical labels ("improved", "regressed", "green") without the underlying numbers (user, 2026-06-10). Show actual metric comparisons: before → after values, per-bench accuracy fractions, and per-question deltas for anything that moved.

Why: Labels hide magnitude and mechanism. "improved" turned out to mean future_timeline 5/9→9/9 (+44pt); a "↓8" category cell turned out to be ONE question whose rigid source-slug coverage halved while its fact coverage quadrupled — opposite conclusions depending on which number you look at. The user also flags hard-won metrics (e.g. wikipedia causal_reasoning, raised through atlas enrichments) — a category dip there is an investigation trigger, not a footnote, even when the lane nets green.

How to apply: For any baseline-diffed run, extract per-question before→after from the report JSON (`retrieval.baseline.results` vs `retrieval.current.results`) and present a table for everything that changed. Check the embedded baseline's `started_at_unix` — a stale baseline means the delta spans months, not your change; say so explicitly.
