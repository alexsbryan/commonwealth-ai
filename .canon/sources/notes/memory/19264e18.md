**bench all surfaces 3 scoring views side-by-side; `answer-equiv` (judge) is canonical, title-coverage + keyword-match are diagnostic**

`sovereign bench all --synth` renders three scoring views of the same retrieval event:

| View | Source field | What it measures |
|---|---|---|
| answer-equiv | `synth.judge_fact_score.ratio` | LLM-judged semantic equivalence — "did the answer convey the expected fact, even via paraphrase?" Strongest correlate of user value. |
| title-coverage | `source_score.ratio` | Strict canonical-title coverage — "was the bank's declared source title in the retrieved bag?" Useful retrieval-reach diagnostic. |
| keyword-match | `fact_score.ratio` | Strict substring presence in answer text — "did the answer contain the expected keyword?" Penalises paraphrase. |

Why this matters: the bench's `expected_sources` is a NARRATIVE claim ("here's where this answer should come from"). The actual retrieval is REALITY. Treating divergence as a regression is the wrong frame — chat correctly serves better chunks from sibling corpora (SEP's `einstein-philscience` outranks Wikipedia's general "Albert Einstein" article on a comparison question), and `title-coverage` grades that as a miss while the user got a perfectly good answer (judge confirms 86-95% across all 3 corpora).

How to apply:

- **Default canonical headline = `answer-equiv`.** Use this number for "is the chat path working?" `title-coverage` and `keyword-match` are diagnostic columns, not pass/fail.
- Read all three together when iterating. Big gap between answer-equiv (high) and keyword-match (low) = model paraphrases (a feature, not a bug). Big gap between answer-equiv (high) and title-coverage (low) = cross-corpus dilution (chat is finding better chunks elsewhere). Big gap between answer-equiv (low) and keyword-match (low) = real retrieval problem.
- Retrieval-mode (no `--synth`) doesn't have judge scores — leads with `keyword-match`. Synth-mode is required for the answer-equiv view.

Where this lives:
- Render: `sovereign-cli/src/bench_cmd/render.rs::print_retrieval_matrix` + `retrieval_summary`. Three columns per scoreboard row + two matrices (lead + title-coverage).
- Score sources: `eval_cmd/runner.rs::SynthSnapshot.judge_fact_score`, `EvalResult.source_score`, `EvalResult.fact_score`. All three already populated by the eval runner.
- Doc: `sovereign/bench/README.md` "Three views of the same retrieval event" + `bench/BENCH_LOOP.md` §10 entry.

Connects to: [[feedback-bench-synth-propagation]] (synth is the access path to the judge column), [[feedback-bench-all-workflow]] (overall tuning loop). Architectural framing from the meta-atlas dual-stream-legibility spec — the bench BECOMES the legibility surface: narrative (expected_sources), reality (actual retrieval), equivalence (judge).
