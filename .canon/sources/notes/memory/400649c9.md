In this mature app, ground earnestly in what already exists before building new infra — there's almost always an existing path/seam to reuse

In this (large, accreted) application there is almost always an existing path to reuse — ground earnestly before building a new "grandiose" system. When a design starts feeling complicated, treat that as a signal you've missed the reuse, not that the problem is hard.

Why: the codebase is mature and wide; parallel implementations cause drift + bloat, which the user actively polices. The daemon and the desktop are NOT divergent — both reach inference through the same OICP seam: `state.inference: Arc<dyn InferenceProvider>`, and `state.corpus_engine` is already wired to it (`inference_to_embed_fn` / `inference_to_inference_fn` / embed model). Capability already lives somewhere.

Concrete miss (2026-06-15, desktop harness enrich rung): I started replicating the CLI's `SplitInferenceProvider` + `run_enrich_and_verify` inside the desktop (build a daemon provider, temp engine, re-ingest the sample). The desktop already enriches corpora via `state.corpus_engine` (the install/ingest flow in `commands/corpus.rs` + `corpus_install.rs`). The correct fix was ~3 lines: `verify_atoms_at(state.corpus_engine.index_dir().join(corpus_id))` — reuse the existing enrichment OUTPUT; the harness only VERIFIES. User: *"Why is this seeming complicated? There should just be an OICP-like interface... we kick off enrichments of corpora in plenty of places."*

How to apply: before adding capability X to a surface, `grep` where X already happens there first (the user will often point you: "we do this in plenty of places"). Reuse the shared seam — `state.corpus_engine` / `state.inference` (OICP `InferenceProvider`), not a parallel provider. Prefer the smallest wiring over the existing path; the verifier/consumer should reuse the producer's output rather than re-run the producer. See [[feedback_midlevel_engineer_test_inference_stack]] (rationalize from first principles, don't accrete) and [[invariant_sovereign_eval_uses_cli_llm]] (the sibling-binary reuse trap).
