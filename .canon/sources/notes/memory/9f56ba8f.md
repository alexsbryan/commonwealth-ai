When to use MCP code intelligence tools vs. grep/Read, and the discipline to default to them

Always check MCP availability at session start before diving into code. If `recent_changes` doesn't appear (or `sovereign tools call` errors), the daemon needs starting (`sovereign daemon start`) or Claude Code needs restarting — don't silently fall back to grep for the entire session.

Why: The MCP tools (`symbols`, `callers`, `blast`) save significant context vs. reading whole files. A single `symbols("EmbedSlot")` beats reading 1432 lines of `embedded.rs`. The `callers` approach is compiler-resolved (SCIP) and catches dispatch grep misses entirely.

How to apply:
1. Session start: attempt `recent_changes(hours: 24)` immediately. If it errors or doesn't appear, fall back to `sovereign tools call recent_changes --hours=24`. If even the CLI fails, run `sovereign doctor` to diagnose.
2. Before reading any file to find a type/method: try `symbols` first.
3. Before modifying any function signature or impl block: `blast` or `callers` — not "probably nothing depends on this."
4. The ToolSearch-first friction (one round-trip when MCP is wired through Claude Code) is real but shouldn't prevent using the tools — batch the ToolSearch + first call together.

Tool-name renames (March 2026 CLI refactor). Use the short names. The MCP server still accepts the old names as deprecated aliases, but new prompts/code should prefer the modern form:
- `symbols` ← `symbol_lookup`
- `callers` ← `find_callers`
- `callees` ← `find_callees`
- `blast` ← `blast_radius`
- `notes` ← `read_notes`
- `note` ← `write_note`

Tool surface today: `sovereign tools list` shows ~26 tools; the MCP server at `:9741/mcp` exposes 12 (6 modern + 6 aliases). Watcher (`lint_status`, `test_status`, `get_lint_output`, `get_run_output`, `build`) and persistent code-intel (`code_search`, `recent_changes`, `project_context`, `read_note_by_id`, `read_note_digest`, `spec`, `drift`) and ATOS lifecycle (`session_reflection`, `provision_feature`, `archive_feature`, etc.) are CLI-only — invoke via `sovereign tools call`.

If MCP doesn't show up after a restart, try the CLI fallback for the rest of the session and check `sovereign doctor` output.
