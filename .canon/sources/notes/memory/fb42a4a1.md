Always start/stop/restart the sovereign daemon via the sovereign CLI (sovereign daemon stop/start/restart), never launchctl directly

Always use the sovereign CLI for daemon lifecycle: `sovereign daemon stop`, `sovereign daemon start`, `sovereign daemon restart` — never `launchctl kickstart`/`bootout`/`bootstrap` directly.

Why: User correction (2026-06-11), explicitly overriding an older memory that said "supervised restart = launchctl kickstart NOT daemon stop/start". The CLI is the supported operator surface; it owns the launchd interaction details and keeps them in one place.

How to apply: When the daemon needs a restart (new `sovereign-cli-daemon` binary, config change like restoring `sovereign.toml.with-watchers`), run `sovereign daemon restart` (or stop/start).
