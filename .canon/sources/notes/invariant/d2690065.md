# Two git-provenance traps, both caught by gate zero on hpr-2's instruments (2026-08-22), both now encoded in scripts/hpr-unprompted.py.

Two git-provenance traps, both caught by gate zero on hpr-2's instruments (2026-08-22), both now encoded in scripts/hpr-unprompted.py.

1. `git log --since=2026-08-21` DOES NOT MEAN MIDNIGHT. It is approxidate and fills in the CURRENT TIME OF DAY. Measured: the window 2026-08-21..2026-08-22 over `-S'cli_shared::args'` returned TWO rung commits when run before 11:03 PDT and ONE after — the same instrument, the same repo, a different answer by clock. Any instrument that takes a date window must normalise to an explicit ISO instant before it reaches git. Use `--since-as-filter` (git >= 2.37) as well: plain `--since` also truncates the walk at the first out-of-order timestamp.

2. THE PER-FILE PICKAXE WALK IS RENAME-BLIND, and the campaign's own floor_basis is off because of it. `git log -S'<form>' --reverse -- <file>` names the commit where the form entered THAT PATH, so a pure file move credits the mover. hot-path-reuse.toml records "14 rung conversions" across three commits (ae0ec58c nc-22b, 74313f10 nc-25, 580a652e nc-26). Measured with a rename-AWARE repo-wide pickaxe as the candidate stage and the per-file walk only as the credit rule: 14 conversions across TWO commits — nc-22b 5, nc-25 9 — and nc-26 converted nothing. Its diff is R100/R09x, a pure crate move of awareness_cmd from sovereign-cli to sovereign-cli-llm of files that already used the form. The floor's CONCLUSION (zero voluntary adopters in 73 days) is unaffected.

A move is not an adoption. Two stages: rename-aware pickaxe admits candidates, per-file walk credits files.
