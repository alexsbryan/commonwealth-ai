Desktop boot hangs on splash when the push-only backend-ready Tauri event outruns the webview's listener; fixed with a pull-based is_backend_ready re-probe

Desktop boot (`sovereign-desktop`) leaves the `"loading"` splash ONLY when
`App.svelte` receives the `backend-ready` Tauri event (`events.ts` `listen`,
`App.svelte` onMount `onBackendReady` → `view = "chat"`). That event is a
plain, push-only `handle.emit("backend-ready")` in `main.rs` (after
`state::bootstrap_with_progress`). Tauri's native event system has **no
replay** — only listeners registered at emit time get it.

The race (2026-07-14, reproduced live): In Attach mode (a `sovereign
daemon run` already on :9741 — the common dev case) bootstrap skips model load
and finishes in ~0.7–1.4s. That can beat the webview's JS mount +
`initEventListeners` subscription, so the emit is LOST and the splash hangs
forever — no timeout, no error, silent. Faster boot = MORE likely to lose, so
the boot-latency optimizations (1.86s→0.9s, GLiNER deferred) made it worse.

The sticky/replay buffer in `command_bridge.rs` (`STICKY_EVENTS` includes
`backend-ready`) does NOT help — it's gated behind `SOVEREIGN_COMMAND_BRIDGE=1`
and only serves the Playwright harness's HTTP `/listen`, never the real webview.

Fix (pull-safe handshake): added `is_backend_ready` Tauri command
(`commands/config_setup.rs`) returning `state.runtime.read().await.is_some()`
— `runtime` is set `Some` inside `bootstrap_with_progress` right before the
emit, so it's true exactly when the event fired. `api.ts` `isBackendReady()`
wrapper; `App.svelte` onMount re-probes AFTER wiring listeners: if setup
complete && still `loading` && `isBackendReady()` → adopt ready state. Covers
every ordering (emit-before-subscribe → re-probe catches it; emit-after →
listener catches it). Verified: 758ms worst-case boot now reaches chat.

Known residual: the `backend-error` path has the same non-replay flaw — a
bootstrap failure emitted before subscribe hangs silently too. Follow-up: a
loading-screen watchdog (re-probe after ~15s, surface retry/diagnostic) to make
any stuck boot self-reporting. See [[project_desktop_launch_perf_2026_07_13]],
[[project_desktop_slow_boot_attach_2026_06_29]].
