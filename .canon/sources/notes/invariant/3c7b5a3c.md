# boundary-gate: a [[forbid]] row outranks package membership AND the shared-leaf allowance. Fixed 2026-09-09 in a32115fc4.

boundary-gate: a [[forbid]] row outranks package membership AND the shared-leaf allowance. Fixed 2026-09-09 in a32115fc4.

THE DEFECT: `arch_layers::evaluate_packages` decided each edge with `allowed.contains(edge.to)` where `allowed` = the package's own crates + ALL [[package_leaf]] names. Leaves are GLOBAL, so `sovereign-contracts` being a leaf (for studio) made `commonwealth-work -> sovereign-contracts` legal to boundary-gate — the exact edge commonwealth/BOUNDARY.md exists to forbid. layer-gate caught it (exit 1, the [[forbid]] row); boundary-gate exited 0 printing "every declared package reaches only itself + the shared leaves". Membership CANNOT express "this package, unlike the others, may not reach that leaf" — only the [[forbid]] table can, and the package pass never read it.

THE FIX: `arch_layers::forbidden_by` (lib.rs) is now the ONE forbid decider both passes call (§10.6). Package pass checks it FIRST, like the layer pass. Exception ledgers stay separate: a bare [[exception]] answers to layer-gate, a `package = "<scope>"` one to boundary-gate — grandfathering an edge out of both takes TWO rows. Violation::ForbiddenEdge carries `package: Option<String>` + `kind` so the message names the ledger that will actually suppress it.

GENERAL LESSON (the reason this survived 5f's red watch): cw-lift 5f watched boundary-gate red using `sovereign-core` — the one sovereign crate that is NOT a declared leaf — so it was caught by MEMBERSHIP, the rule the gate already had. Watch a gate red with an input drawn from the CLASS it must catch, not the first member of that class to hand. Every sovereign-* crate looked equivalent and two of them were not.

Regression test: `a_forbid_row_outranks_package_membership_and_the_shared_leaf_allowance` in quality/arch-layers/src/packages.rs — 7 cases, case 0 a negative control asserting the leaf allowance really does admit the edge (without it the suite passes against the old code, which already rejected out-of-closure targets).

NOTE for future leaf admissions: adding a [[package_leaf]] widens every package's closure at once. If a package must NOT reach a newly admitted leaf, that refinement goes in the [[forbid]] table — which is now actually enforced by both gates.
