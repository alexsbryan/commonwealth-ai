# The truth source for Phase 1b (entity extraction) progress is the JSONL at <index_dir>/_phase_1b_parsed.jsonl, NOT the EnrichmentCheckpoint…

The truth source for Phase 1b (entity extraction) progress is the JSONL at <index_dir>/_phase_1b_parsed.jsonl, NOT the EnrichmentCheckpoint counter. Each line is {batch_idx, response} where response is post-rewrite_mentions (chunk_ids absolute, self-contained).

Lifecycle in run_and_write_entity_extraction:
1. Load JSONL (tolerant of malformed lines); build HashSet<usize> of done batch indices; pass as skip set to inner driver.
2. Inner driver appends each successful parse to JSONL BEFORE pushing to in-memory parsed vec. Kill between persist+push is safe — next run loads from disk.
3. After all batches done: merge loaded+new responses (single merge_responses call), write atlas, delete JSONL. Atlas write before delete; interrupt between them = idempotent re-merge+re-write+re-delete next run.
4. EnrichmentCheckpoint.phase_1b_batches_done is updated to (loaded+new) on success but is purely human-readable. JSONL alone determines re-run scope.

Preconditions:
- index.all_chunks() returns chunks in stable storage (id) order across runs. If order changes, batch_idx N maps to different chunks and resume corrupts. Appends at end are safe.
- Kill mid-write truncates at most one line; loader tolerates.

Do NOT delete JSONL on parse/inference failure — failures aren't persisted so re-running is correct. Only delete after atlas is committed.

Tests pinning behaviour: run_and_write_resumes_from_jsonl_and_skips_inferred_batches, run_and_write_persists_each_batch_so_kill_after_n_batches_resumes, phase_1b_progress_roundtrip, phase_1b_progress_tolerates_malformed_lines.
