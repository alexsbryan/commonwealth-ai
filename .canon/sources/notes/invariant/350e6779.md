Enrichment e2e fixtures must clear the domain's OVERVIEW_MIN_TOKEN_COUNT or they make ZERO inference calls, and an "always-failing inference fn" proves nothing.

Measured 2026-08-07 on fix/enrichment-blind-arms. sovereign-tools/tests/enrichment_health_e2e.rs used a 3-sentence source that chunked to ONE chunk of ~40 words. FieldModelEngine's overview filter (corpus-engine/src/enrichment/field_engine.rs, word-count gate; philosophy's OVERVIEW_MIN_TOKEN_COUNT = 80, conversational = 200, personal = 30) dropped it entirely -> `overview_chunks=0`. Phase 1 got zero batches; clustering skipped itself at 1 < min_cluster_size (50). Result: `inference_calls=0 inference_failures=0`. The corpus ended unenriched because it was TOO SMALL to enrich, not because inference was down — so every LowEnrichmentCoverage assertion in that file was true for the wrong reason, and no test exercised an inference outage at all.

Fix: 8 paragraphs of 80+ words each, recipe `max_chars = 1200, overlap_chars = 0` so chunk count == paragraph count. That yields 2 Phase-1 batches -> 2 inference calls.

Diagnosis path if this recurs: `engine/ingest.rs` emits `tracing::debug!("enrichment: inference tally", inference_calls, inference_failures)` after `field_engine.enrich(...)`. Capture at DEBUG and read the tally before trusting any enrichment-failure fixture.
