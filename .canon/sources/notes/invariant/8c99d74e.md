# A SOURCE CENSUS THAT SCANS FOR A LITERAL AT A CALL SITE REPORTS THE INVARIANT VIOLATED — NOT ITSELF BLIND — THE MOMENT THAT CALL SITE…

A SOURCE CENSUS THAT SCANS FOR A LITERAL AT A CALL SITE REPORTS THE INVARIANT VIOLATED — NOT ITSELF BLIND — THE MOMENT THAT CALL SITE ADOPTS A SHARED COMPOSITION. Hit TWICE in one session (2026-08-26, topology-final-three) on two independent censuses, both times while the invariant they guard was still perfectly held.

1. `turn_tool_census.rs` scanned each host for `ToolRegistry::new().with_cache(` and `tools.register(`. The desktop adopted `sovereign-runtime-recipe` and stopped building a registry, so `registry_span` returned None -> `panic!("desktop: no turn registry span")`. Fixed by making extraction PER-HOST (`enum Extraction { Bundles(&[&str]), Direct }`) instead of one hardcoded `if host == "recipe"`.

2. Same file, next run: the desktop column showed `.` for nine baseline tools it had never stopped carrying, because `composed_bundles` scanned only the host's own file and the host calls `baseline_bundles(..)` — the families are named one hop away. Reported 32 divergent against a baseline of 26, i.e. a 6-wide regression that never happened. Fixed with `effective_sources()`, which follows the call.

3. `sovereign-desktop/.../tests/authority_surface_census.rs` scanned `state.rs` for the literal `sec_facts::SecFactsTool::new(` and failed the full test gate with "state.rs registers the sec_edgar acquirer but NOT sec_facts ... every figure answered from it will be ungrounded". `sec_facts` WAS registered, via `CoreTurnTools`. Rewritten as four asserted hops (acquirer -> composes baseline_bundles -> baseline composes CoreTurnTools -> CoreTurnTools registers the tool) so a break names WHICH link went.

Why this matters more than the fixes: the failure text of all three was a confident, specific, actionable claim about a live defect that did not exist. #3's message would have sent someone to add a SECOND registration for a tool already there. This is ARCH §18.4's exact shape and the reason it says validate the instrument BEFORE the result.

How to apply: when converting a call site onto a shared recipe/bundle/factory, grep the test tree for source censuses that `include_str!` the file you are converting, BEFORE running the gate. Either give the census a hop-following resolver or split it into per-link assertions. Never "fix" it by re-inlining the literal into production code so a scanner can find it — that is reshaping the system for the instrument.
