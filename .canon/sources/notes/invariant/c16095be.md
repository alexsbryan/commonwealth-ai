Specifics-scan output is answer-anchored or it is dropped — the ledger never holds judge prose (fix/holdings-and-intent, 6cc78ab5, 2026-08-08).

`judge::anchor_scan_item` (was `normalize_scan_item`) returns Option<String>. A scan line that cannot be anchored to the ANSWER is NOT a claim, is dropped, and is traced as `event = "scan_item_dropped"`. Do not restore a pass-through fallback: the old one emitted the judge's commentary verbatim, and `longform_claims` turned it into a `failed_once` holding AND a line in the user-visible verification note.

Why it slipped through (both anchoring misses, worth knowing before touching the ladder):
- `squash` compared raw text, so the answer's `**Severin Quenholt**` did not contain the judge's re-quote `Severin Quenholt`. Fixed by `anchor_key`, which drops `*_\``. Use anchor_key for containment ONLY — never to build a stored/displayed value.
- A quoted span the judge elided with a trailing `...` matched nothing. Now anchors on its prefix (min 24 chars). An INTERIOR ellipsis means a stitched quote and must still be rejected, or it reduces to a bare name — pinned by `a_stitched_quote_is_not_salvaged_into_a_fragment`.
- The commentary-dash list lacked the plain ASCII `" - "` the live judge actually emits.

REVERSED an earlier deliberate behaviour: `abstractive_finding_passes_through` is now `abstractive_finding_is_not_a_claim`. The old rationale (chatter still guides the corrective search) was real, but it bought a search hint with a false holding.

Fixtures are real, not synthesized: `sovereign-core/src/runtime/grounding/testdata/` carries the polluted answer + judge lines + recorded holdings from `saltgrass_compound_gv_shadow_20260808`, turn `compound-killer-and-lugger`, and replaying the pre-fix function over them reproduced the three prose holdings byte-for-byte. Measured: 5 failed_once holdings -> 3. Watched fail (pass 1038/fail 3, exit 100) then pass (1045/0, exit 0).

Note `verification_note`'s own test already forbade judge vocabulary ("fabricated") while production shipped exactly that — an assertion in a test is not a guarantee about the pipeline feeding it.
