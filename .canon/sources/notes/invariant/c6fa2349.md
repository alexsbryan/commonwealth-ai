investigation entity-name coalescing vocabulary lives in the recipe (data), not hardcoded in the engine — the abstraction layer carries mechanism only

Entity-name coalescing for the investigation pipeline is data-driven: the
engine supplies the *mechanism*, the recipe supplies the *vocabulary*. No
corpus-specific knowledge (US states, Air Force base aliases, disposition
categories) may live in the abstraction layer. This was a deliberate refactor
(2026-06-04) after UAP/Blue-Book gazetteers had leaked into `extract.rs`.

Where things live now:
- `corpus-engine/src/recipe.rs` — `NormalizationConfig` + `FoldRule` (the data
  schema): `identity_attribute` (entity_type → attribute, e.g.
  `adjudication = "category"`) and `fold` rules (`types`, `aliases`,
  `leading_prefixes`, `trailing_qualifiers`, `trailing_suffixes`).
- `corpus-engine/src/enrichment/investigation/normalize.rs` — `Normalizer`,
  the generic engine that APPLIES the config: alias map → strip leading
  qualifier → strip trailing qualifier run → OCR-tolerant suffix strip →
  re-check alias on the reduced base. Exposes `coalesce_key` / `entity_id` /
  `normalized_name` (must agree — endpoints resolve to the coalesced id) plus
  `best_canonical` and `identity_attribute`.
- `sovereign-recipes/uap-blue-book{,-scans}/recipe.toml` —
  `[enrichment.normalization]` block carries the UAP gazetteer (states, WPAFB
  alias, ATIC/AMC org prefixes, AF-suffix words, adjudication→category).

Invariants:
- A new corpus adds its gazetteer to ITS recipe, never to the engine.
- `identity_attribute` folding is applied ONLY in the offline re-fold
  (`recoalesce`), which remaps relationship endpoints — applying it at build
  time would strand edges (endpoint knows the name, not the attribute).
- The fold is identity-grade: only qualifier/suffix regions fold; base tokens
  are never fuzzy-matched, so two distinct bases never merge.
- `recipe.rs` type changes require regenerating `sovereign-recipes/SCHEMA.md`
  via `UPDATE_RECIPE_SCHEMA=1 cargo test -p corpus-engine --test recipe_schema`.

Offline re-tuning: `sovereign enrich investigation recoalesce <corpus>`
re-folds the persisted graph under current rules (no inference), backs up
originals to `*.orig`, idempotent. Reuses the hours of 35B extraction. See
[[invariant_investigation_enrich_resumable]].
