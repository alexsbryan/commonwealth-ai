# sovereign/scripts/cli-journey-nightly.sh IS A GUARANTEED VACUOUS GREEN ON macOS: IT EXITS 0 HAVING RUN NOTHING, AND PRINTS A FALSE REASON…

`sovereign/scripts/cli-journey-nightly.sh` IS A GUARANTEED VACUOUS GREEN ON macOS: IT EXITS 0 HAVING RUN NOTHING, AND PRINTS A FALSE REASON FOR IT. Proven 2026-08-03 on M2 Max.

REPRODUCTION — one command, exit code captured:
  $ sovereign/scripts/cli-journey-nightly.sh; echo "EXIT=$?"
  cli-journey-nightly.sh: line 83: flock: command not found
  nightly: another run holds ~/.sovereign/journey-nightly/.lock — skipping this fire
  EXIT=0

MECHANISM. Line 83 is `if ! flock -n 9; then <skip>; exit 0; fi`.
macOS ships no `flock` (it is util-linux). Command-not-found returns
127, `!` inverts it to true, so the "another run is already going"
branch fires unconditionally. No other run exists. The lock file is
freshly created by the same script moments earlier.

WHY IT MATTERS MORE THAN THE ONE-LINE FIX. This is the exact failure
the script's own header was written to eliminate — it says the harness
it replaced "exited 0 having tested nothing, and read as coverage the
whole time." That defect has been reproduced on a different host by a
different mechanism. `sovereign posture` reports contract-nightly as
`never_run` only because the script exits before writing latest.json;
had it written one, the posture surface would read green.

SCOPE. The Halo (Fedora) has flock, so the lane is real there. This
bites the M2 Max — the machine the training and bench work migrated to
per the 2026-08-02 handoff. Two other GNU-isms are absent here and
will bite further down the same script once the lock is fixed:
`timeout` (absent) and `date -Is` (macOS date rejects -I).

THE FIX SHAPE, not yet applied: a missing lock primitive must be a
hard failure (or a portable fallback such as `mkdir` locking), never a
skip. Four verdicts, not two (ARCH §18.1) — "cannot acquire lock" and
"cannot run here" are different from "another run holds it", and only
the last justifies exit 0.
