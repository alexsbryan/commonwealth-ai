BREAK 1 — `fuse_lora_manual.py` COULD NOT READ A PEFT ADAPTER AT ALL. It was written for mlx-lm-lora (the Mac 0.8B probes); every 4B run produces PEFT/TRL. The mismatch is total, not cosmetic:
    | | mlx-lm-lora | PEFT / TRL |
    | file    | adapters.safetensors | adapter_model.safetensors |
    | scale   | lora_parameters.scale | lora_alpha / r  (64/32 = 2.0) |
    | key     | <module>.lora_a | base_model.model.<module>.lora_A.weight |
    | A shape | [in, r] | [r, in]  TRANSPOSED |
    | B shape | [r, out] | [out, r] TRANSPOSED |
FIXED: `load_adapter()` auto-detects by filename and normalises to ONE convention (delta = scale * (b @ a), a [r,in], b [out,r]); `resolve_weight_key()` maps module -> snapshot key by trying candidates and DYING with the list if none match. THE SHAPE ASSERTION IS LOAD-BEARING: at r=32 both `b.T @ a.T` and `b @ a` are well-formed, so a transpose error yields a fluent, silently WRONG model. Do not relax it.
