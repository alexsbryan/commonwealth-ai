# persist::save MUST NOT DECIDE WHICH MESH IS ACTIVE — it used to, and that made every caller an implicit switcher, two of which fire on a…

`persist::save` MUST NOT DECIDE WHICH MESH IS ACTIVE — it used to, and that made every caller an implicit switcher, two of which fire on a timer (fixed 2026-08-27, branch mesh-multi-membership, P6).

`save(data_dir, mesh, self_id)` opened with "saving IS the act that makes a mesh active" and called `set_active(mesh.id)` before writing. Fine for `create_mesh` and `join_mesh`. Not fine for the other two callers, which nobody thinks of as switchers:
  - `gossip.rs`'s per-round re-persist (every ~10s)
  - the mesh-mutation hook, on every accepted join

So a gossip round still in flight for the mesh `switch_mesh` had just PARKED would call `save(&mesh_A)` and re-point `active` back at A seconds after the pointer moved to B. The switch silently came undone and nothing logged it.

Second defect in the same function, same root: `set_active` ran BEFORE `mesh.json` was renamed in — because the write target was `mesh_file(data_dir)`, which RESOLVES THROUGH the active pointer. A crash in that window booted with `active` naming a directory containing no mesh.json.

Fix, both halves at once: `save` derives its target from `mesh.id` directly (`mesh_dir(root, &mesh.id).join(MESH_FILE)`) and touches nothing else. `save_and_activate` is the two-step, file-then-pointer, used by exactly the two ESTABLISHING callers. `switch_mesh` already called `set_active` itself.

THE TELL WAS ALREADY IN THE TREE and had been for a while: `tests/mesh_switch.rs::park_a_mesh` carried the comment "`save` makes its subject active; put the pointer back so this mesh is genuinely parked" and did exactly the undo by hand. A test helper working around a production function is a defect report nobody filed.

Related: `leave` deleted the mesh's `mesh.json` and left `active` naming it. Boot looked healthy (`load` -> None, `resume_active` -> false) while `forget` refused that mesh FOREVER, because forget refuses the ACTIVE one and nothing could move the pointer off it. `persist::clear_active` existed for exactly this and had no caller in the workspace.

Red-first: `persist::tests::{an_in_flight_round_for_a_parked_mesh_cannot_steal_the_active_pointer, save_writes_into_the_meshs_own_directory_without_moving_the_pointer}` plus 2 in `mesh_switch` fail against the old `save`.
