# THE GROUNDING SCORING HARNESS IS SCALE-SENSITIVE: THE SAME ITEM, SAME ADAPTER, SAME SERVER FLAGS PRODUCES A DIFFERENT ANSWER DEPENDING ON…

THE GROUNDING SCORING HARNESS IS SCALE-SENSITIVE: THE SAME ITEM, SAME ADAPTER, SAME SERVER FLAGS PRODUCES A DIFFERENT ANSWER DEPENDING ON HOW MANY ITEMS ARE IN THE RUN. A NUMBER FROM THIS HARNESS IS ONLY COMPARABLE TO ANOTHER NUMBER MEASURED AT THE SAME --per-subset.

Established 2026-08-03 on the Halo. Partially corrects note dc253479, which is right about WHAT the model emits at 2,200 items but wrong to call it a property of the weights ("converged malformed template").

THE OBSERVATION. Arm A (runs/mix-A/adapter, 118 steps), scored through score_arm.sh, --no-think, temperature 0.0, --concurrency 4, -c 32768 --parallel 4:
  per_subset 200 (2,200 items):  well-formed markup    1/2186  (0.05%)
  per_subset  20 (  220 items):  well-formed markup   70/217, 105/217, 102/217  (32-48%, three runs)
The 220 items are a VERIFIED SUBSET of the 2,200 (217/217 id overlap). On the 217 shared items the format DISAGREES on 69 of 217, and the VERDICT changes too, not just the markup:
  id Reveal:3871        FULL '<answer>CALL FOR HALLUCINATED_INTRINSIC</classific'
                      SUBSET '<answer>\n  <classification>HALLUCINATED_INTRINSIC<'
  id AggreFact-XSum:1060 FULL '<answer>HALLUCINATED_INTRINSIC</classification>'
                      SUBSET '<answer>\n  <classification>HALLUCINATED_EXTRINSIC<'

WHAT IT IS NOT, each checked rather than assumed:
  * Not a different model. Adapter GGUFs md5-identical across all runs (327a4478...).
  * Not a different protocol. Both summary.json protocol blocks: max_tokens 2560, temperature 0.0, enable_thinking false, seed 17.
  * Not a different runtime. Same server banner, same Vulkan device, same /lib64/libllama.so.0.
  * Not a different item set. 217/217 id overlap, same doc/claim.
  * NOT DRIFT ACCUMULATING DURING THE RUN. The 2,200-item run is malformed from item 0 and flat at 0/100 for twenty consecutive chunks. The regime is set before the first token, so it is not slot state building up.
  * Not run-to-run chance. The full card reproduced EXACTLY -- 1/2186, tolerant macro 0.05, identical failure counts -- five hours apart.
The remaining candidate is batch composition under --parallel 4 / --concurrency 4 changing kernel reduction order. NOT yet confirmed; the decisive test is a full card at --concurrency 1.

THE GRAMMAR LARGELY BUT NOT FULLY FIXES IT. With --grammar (ANSWER_GBNF): format is 2186/2186 well-formed at both scales, and verdicts agree on 199 of 220 shared items (90.5%). Residual ~10% verdict instability still moves the macro score 59.32 (220 items) vs 64.88 (2,200 items).

HOW TO APPLY.
  * Never compare a number measured at --per-subset 20 to one at --per-subset 200. The spread is up to 5.5 macro points even WITH the grammar, and catastrophic without.
  * A subset run is a smoke test, not a score. Use it to prove a lane works, never to report a result.
  * Every figure in BASELINES.md and the 54.2/53.19 controls were measured at --per-subset 200 --concurrency 4 and are self-consistent, but they inherit this sensitivity.
  * Suspect this FIRST whenever an eval number will not reproduce at a different scale.
