THREE INSTRUMENT TRAPS THAT MAKE MESH ROUTING EXPERIMENTS REPORT THE OPPOSITE OF THE TRUTH. Verified 2026-08-06. Read this BEFORE running any M1/M2/M5/M6 experiment from MESH_N4_TOPOLOGY.md §7 — each of these produces a WRONG verdict, not a missing one, which is the failure §18.2 exists to prevent.

1. GATED DECISIONS ARE DARK AT THE SHIPPED LOG LEVEL. `decision_log.rs:700-708` takes the `tracing::debug!` branch for `Verdict::Gated`, while the daemon's default filter is `mesh.decision=info` (sovereign-cli-daemon/src/lib.rs:73). So EVERY gate name the experiments look for — `forward_budget_exhausted`, `not_offload_eligible`, `envelope_absent` — is invisible in a normally-started daemon. An experiment that greps for one and finds nothing will read as "the gate never fired, therefore the request was not blocked", which is the exact inverse of the truth.
   ESCAPE HATCH: `SOVEREIGN_DECISION_LOG=<path>` (DECISION_LOG_ENV, decision_log.rs:68). The JSONL file sink writes the FULL record regardless of level (:757-773), so it needs no RUST_LOG at all. Schema tag `oicp-decision/v1`; boot line confirms it.
   ACCEPTANCE, and it is mandatory: after arming, serve one local turn and one peer turn and confirm the file is non-empty. An empty file after a demonstrably-served request means the instrument is dead and every downstream verdict is COULD-NOT-JUDGE — never "no gate fired, therefore passed".

2. `RUST_LOG` REPLACES THE DAEMON FILTER, IT DOES NOT EXTEND IT. sovereign-cli-shared/src/tracing_init.rs:27-28 is `try_from_default_env().unwrap_or_else(default)`. So `RUST_LOG=mesh.decision=debug` SILENCES llama_cpp, placement, transport and every other named target. Never run a tensor-split measurement in the same daemon lifetime as a routing-trace run — the split needs `placement`/`llama_cpp` to verify the block split actually applied.
   Corollary trap: the NAMED-path `forward_budget_exhausted` (peer_inference.rs:1800-1806) is a bare `tracing::debug!` with NO `target:`, so it rides `sovereign_mesh::peer_inference` and does NOT reach the decision JSONL. It needs `RUST_LOG=sovereign_mesh=debug` specifically. The scored path (oicp_select.rs:101,103) does ride mesh.decision.

3. ON THIS HOST, systemd `Environment=` LINES ARE DEAD. The unit runs `ExecStart=/usr/bin/toolbox run -c sovereign-vulkan env VAR=... sovereign-cli daemon run`, and `toolbox run` does NOT forward the unit's Environment= into the container. ~/.config/systemd/user/sovereign.service.d/40-toolbox.conf:22-25 documents this and keeps 20-ubatch.conf's Environment= line as dead weight for the record (SOVEREIGN_N_UBATCH was silently lost that way). EVERY experiment env var must ride the `env` prefix ON the ExecStart line. Macs are launchd — use the plist EnvironmentVariables.

ALSO: `svrn mesh bench` marks any run with >25% inter-trial spread as `Invalid` and never serves it back to `mesh plan`. For a CONTENTION experiment that verdict is the FINDING, not a failure — report the number with the verdict attached rather than discarding it or re-running until it passes.
