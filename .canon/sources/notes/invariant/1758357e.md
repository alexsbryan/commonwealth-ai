# Capability-probe shadow phase LANDED; but Safe is NOT trustworthy yet — sampled-token equality is a lossy detector of KV state divergence.…

**Capability-probe shadow phase LANDED; but `Safe` is NOT trustworthy yet — sampled-token equality is a lossy detector of KV state divergence. DO NOT flip `prefix_cache_gate` onto the probe until the detector is logit-based.**

Commit 1 of the capability-model consolidation (plan `cached-purring-petal`). New `embedded/capabilities.rs`: `ModelCapabilities` + four-verdict `PartialKvVerdict` (`Refused` / `AcceptedButUnfaithful` / `Safe` / `CouldNotJudge`) + a load-time probe wired into `ModelSlot::load`. Behaviour-neutral by construction: the gate still follows the arch ladder, the record is recorded and logged on the `capability` target only. Gate green — lint --full 0, tests 9436 pass / 0 fail (was 9425; +11 weight-free decision tests).

The probe protocol (minimised from `rs_rollback_spike.rs`): prefill 192 → generate 2 (creating single-token decode passes) → roll back 16 prompt tokens, spanning that boundary → replay the identical tokens → compare continuations. Crossing the decode-pass boundary is the property that makes it correct; within one pass, hybrid rollback is faithful at every depth and a naive probe would report `Safe`.

TWO FINDINGS, one of them against my own design.

1. Capability is per-MODEL, not per-arch-family — confirmed the hard way. `qwen35` (Qwen3.5-2B) probes `AcceptedButUnfaithful` at `n_rs_seq=64`; `qwen35moe` (FINAL-Bench 36B) probes `Safe` at the same setting. Same family glob, opposite verdict. My spike's assertion had encoded a family-level expectation — i.e. it committed the exact error the capability model exists to abolish — and the run caught it. That is the strongest single argument for measuring rather than matching strings.

2. FALSE NEGATIVE in the probe, and tuning does not fix it. The 36B probed `Safe` at `n_rs_seq=64` while the fuller sweep showed that model corrupt at every depth in the cross-pass regime (`gen_before=4 → corrupt [1,2,4,8,16,32]`). New diagnostic `probe_parameter_sensitivity` isolated it, holding depth at 16 on the 36B:

```
prefill=192   gen_before=0 → FAITHFUL   1 → CORRUPT   2 → CORRUPT   4 → CORRUPT
prefill=512   gen_before=0 → FAITHFUL   1 → CORRUPT   2 → FAITHFUL  4 → FAITHFUL
prefill=1421  gen_before=0 → FAITHFUL   1 → FAITHFUL  2 → FAITHFUL  4 → FAITHFUL
```

Corruption VISIBILITY is content- and length-dependent: greedy argmax absorbs a perturbed state whenever the top token wins by more than the perturbation. Raising `PROBE_GENERATE` 2→4 and `PROBE_CONTINUE` 6→24 made it worse — the 2B then also reported `Safe` where it had correctly reported `AcceptedButUnfaithful`. Reverted. Tuning relocates the false negatives; it does not remove them.

THE FIX (next step, not done): compare the LOGIT DISTRIBUTION at the first post-rollback position instead of sampled tokens — a perturbed state shows up there even when argmax does not flip. Calibrate the float-noise floor on known-correct arms (gemma4, and any hybrid at `gen_before=0`, faithful at every depth). `get_logits_ith` is already used this way in `rerank_slot.rs`. Until that lands, `Refused` and `AcceptedButUnfaithful` are trustworthy (positive detections); `Safe` on a hybrid may be a false negative.

Why this is safe to leave in the tree: nothing consumes the verdict for a decision. The limitation costs observability, not correctness.

Bonus finding, live on first run: `is_recurrent_arch("qwen35")` is false — the dense-hybrid miss of 2026-06-09 is still in the ladder. The gate is nonetheless correct because clause 0 reads libllama's `is_recurrent`/`is_hybrid` flags. So the record compares the probe against `gate_would_veto` (what the system will DO) and reports `arch_ladder_alone_is_wrong` separately at info — otherwise a known-wrong clause would drown the real signal.
