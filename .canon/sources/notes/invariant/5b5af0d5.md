# sovereign-mobile frontend-only changes need a Rust recompile to re-embed, else a stale dist ships to the device

sovereign-mobile frontend-only changes need a Rust recompile to re-embed, else a stale dist ships to the device

Tauri embeds the Svelte frontend (`dist/`) into the lib crate at compile time via `generate_context!()` (sovereign-mobile/src-tauri/src/lib.rs). On iOS, `npx tauri ios build` runs `npm run build` (regenerates `dist/`) and **relinks `libapp.a` every build, but cargo does NOT recompile the lib crate when only the frontend changed — so it re-embeds the stale, previously-compiled `dist/`. Net: a frontend-only edit (Svelte/CSS) silently never reaches the device** even though `dist/` rebuilt and the IPA installed + launched.

Symptom: UX/CSS changes "don't show up" on the phone. Burned ~an hour: the #1–3 UX tweaks (sticky header, title cleanup, eased streaming) AND the narration-pill motion all looked unchanged because the embedded frontend was from the last build that had a Rust edit. The changes that DID land (citation grouping, host-management) all shipped alongside a Rust change (client.rs / store.rs) that forced the recompile.

Fix: force the lib crate to recompile so `generate_context!()` re-embeds the current `dist/` — edit any `src-tauri/**/*.rs` (there's a `frontend-embed-rev:` marker comment in `lib.rs` to bump). Verify via `Compiling sovereign-mobile v0.1.0` in the build log; the embedded assets are compressed (brotli), so `strings <binary> | grep <css>` finds nothing and is NOT a valid check.

Also note: install-over does NOT kill a running app, and `devicectl process launch` is denied while the phone is locked (`error 7 (0x07) = Locked`) — so the device must be unlocked, and use `--terminate-existing` (or force-quit) to guarantee the fresh binary runs rather than a resumed stale instance. See [[project_mobile_test_host]].
