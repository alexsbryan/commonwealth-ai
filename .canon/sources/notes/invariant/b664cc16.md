P0 — alternation_grammar=true traps every tool-caller in an endless tool-envelope loop (never escapes to text); disable it. Tool-calling 0/30→24-30 on search-gym.

Tool-calling P0 (found+fixed 2026-06-08). `~/.sovereign/config.toml` had `alternation_grammar = true`. That flag (→ env `SOVEREIGN_ALTERNATION_GRAMMAR=1`, propagated by `daemon_cmd.rs:359`) routes tools-bearing requests through llguidance's `text | tool_envelope` Lark grammar with an injected `done` virtual tool (`inference_adapter.rs:423-472`, `build_tool_alternation_grammar` at `llguidance_constraint.rs:415`). **Its integration is incomplete (the notes flagged it "deferred to next session") — the model can never reach the `text`/`done` escape, so it emits a tool envelope EVERY turn and never terminates. Effect: every tool-using chat (mobile/desktop/agentic + the gyms) loops forever. search-gym = 0/30, all fixtures "exceeded MAX_TURNS=4 — looped on tool calls"**, even trivial skip-search ones.

Root-cause method (A/B): `SOVEREIGN_MTP_DISABLE=1` → still 0/6 (MTP NOT the cause — the gate at `model_slot.rs:2124` already skips MTP when `request.tools` is set, so MTP wasn't on this path). `SOVEREIGN_ALTERNATION_GRAMMAR=0` → 24/30 (80%), model searches once then synthesizes, and skips search on definitions (clean judgment + termination). Inspect via the search-gym transcript `tool_calls` names + `final_message` (empty=looped). The model emitting `{"name":"search","arguments":{...}}` as content-JSON is the alternation ENVELOPE shape (working as designed), not free-form — a red herring.

FIX (applied): `alternation_grammar = false` in `~/.sovereign/config.toml` (the repo DEFAULT is already false, `setup_config.rs:498` — only this box had it on). Config-driven restart (no env override) → search-gym 6/6. This is the "env cocktail that got lost" the operator recalled.

ESCAPE WIRED + VALIDATED + REVERTED (2026-06-08) — keep OFF permanently; DON'T re-attempt this lever. The root cause IS the unwired escape: `inference_adapter.rs:436` routed a pure `inject_done_tool(envelope)` JSON schema (leading `{` → `from_json_schema`, no plain-text escape) instead of `sovereign_inference::llguidance_constraint::build_tool_alternation_grammar` (the Lark `body: tool_envelope | plain_text`; a wired working copy ships in `recipe_author.rs:725`). The one-line fix (wrap `schema_json` through `build_tool_alternation_grammar`) compiles and repairs the trap (search-gym 0/30 → 18/30, escape reachable) — but is STRICTLY DOMINATED: it regresses search-gym vs grammar-off (0.60 < 0.80) AND agent-coding vs FORCE_TOOL_CALLS (3/27 < 9/27 — given a text escape the IQ4 model takes the lazy path: ~100 tokens, no tool calls, clean exit, no solving). Gyms prefer grammar-OFF; agent-coding prefers FORCE_TOOL_CALLS. Reverted. agent-coding's gap is model ENGAGEMENT, not output format — the next lever is the FORCE_TOOL_CALLS write-test loop (raise `SAME_PATH_WRITE_THRESHOLD=3` in `runners/shared_detectors.rs`) or prompt nudging, NOT this grammar. Full dominance table in `sovereign/bench/CI_GATE_HANDOFF.md` Step 2 #1 (commit 94cb9ace).
