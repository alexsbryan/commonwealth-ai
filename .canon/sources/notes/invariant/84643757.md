DESKTOP LAYOUT IS TOKEN-DRIVEN — `app.css` owns it, components must not re-declare it (2026-07-27).

THE HOST CONTRACT (this is the part that keeps getting violated): every full-width surface host in sovereign-desktop is a bounded, CLIPPING box — `.library-surface`, `.settings-surface`, `.nb-body`, `.app-chrome-content` are all `height:100%` + `overflow:hidden`. That is deliberate (pinned headers, no window scroll). The cost: a page body mounted into one MUST establish its own scroll container or its content past the fold is clipped with NO scrollbar and no way to reach it.

PRIMITIVES (global, NOT Svelte-scoped, in app.css):
- `.page-body` — flex:1 1 auto + min-height:0 + height:100% + overflow-y:auto + `var(--gutter-top) var(--gutter) var(--gutter-bottom)`. Works both as a flex child and as a block child of a position:relative host, because BOTH host shapes exist here.
- `.page-measure` — max-width: var(--measure); margin-inline:auto; width:100%.
- `.page-header` — flex-shrink:0 + padding-inline: var(--gutter) + bottom border.
Tokens: `--gutter` 28px, `--gutter-top` 22px, `--gutter-bottom` 40px, `--measure` 920px, `--measure-prose` 68ch.

DO NOT re-declare padding / overflow / max-width on an element carrying `.page-body` — Svelte scoping compiles `.foo` to `.foo.s-hash` (specificity 0,2,0) and silently BEATS the global `.page-body` (0,1,0). The override wins and you get the old bug back with no warning.

WHY THIS EXISTS — two P0s found by measurement, not by reading CSS:
1. `ConflictsPanel` set `overflow-y:auto` on an AUTO-HEIGHT block. That can never scroll (the box just grows), and it mounted bare into `.nb-body{overflow:hidden}` while every sibling tab got a `.pad` wrapper. Measured with 12 open conflicts: 2,442px of governance decisions unreachable, no scrollbar.
2. `AddSheet`'s `.add-body` had zero padding and all three sections it hosts supply zero too — `LocalKnowledgeSection`'s `embedded` prop sets `padding:0` because a `.lk-embed :global(...)` override in SettingsPanel used to compensate. SettingsPanel stopped importing it and `.lk-embed` no longer exists ANYWHERE, so the opt-out outlived its host. Measured body gutter 0/0; the third source card was clipped off-window.

Before: gutters of 0/16/18/20/24/28/30/32px and columns of 760/860/920/64rem across one surface. After: chrome 28 everywhere, all notebook-detail tabs agree.

REGRESSION GATE: `tests/e2e/specs/library-layout-audit.spec.ts` drives every Library route, measures COMPOSITED geometry (not CSS), and fails on (a) content clipped with no reachable scroller, (b) a body inside the gutter. It carries a `bigGovPayload(n)` fixture because ONE conflict fits on screen and hides the bug — the failure only reproduces with enough content to overflow.

STILL OPEN (deliberately not fixed): `.explore-surface` (overflow-y:auto) still nests `.atom-scroll`/`.member-scroll`. Mitigated by giving those a `min-height: 240px` FLOOR instead of 0 — at 0 the virtualized list could collapse to a zero-height viewport and render rows into nothing (blank panel, no scrollbar, under a "Showing 200 of 4,312" label). Collapsing to one scroller would break AtlasCorpusView's windowing, which binds clientHeight.
