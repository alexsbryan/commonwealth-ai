COLD PRIMARY-SLOT LOAD IS THE DOMINANT LATENCY TERM IN A DEEP TURN (2026-07-27). Supersedes b62c77d0, which contained a WRONG invariant — see the correction at the bottom.

REPORT: canonical 'Is free will compatible with determinism?' took 180.9s in the desktop app; the verification Counter sat inert ~112s. Provenance read '4.3 tok/s', which looks like a slow model and is NOT — that number is wall-clock / output tokens, so it buries load cost inside a throughput-shaped figure. Decode was healthy: 722 tok in ~16.5s = ~44 tok/s.

MEASURED (live daemon, identical 4-token request): cold 57.51s vs warm 0.44s/0.39s = 130x. A later cold load with warm page cache and no memory pressure was 15.6s. So cold load spans ~15-95s depending on page cache + RSS. NEVER show an ETA for it.

TURN BUDGET (~/rpcdiag/probe-20260727-074409.log): ~12s retrieval + ~112s synthesis (of which 95s was 'loading lazy slot', ttft=95145ms) + ~66s gate (~12 claim audits x ~3s) = ~190s vs 180.9s reported.

ROOT CAUSE: ~/.sovereign/config.toml had primary_idle_secs=60 (code default 300, setup_config.rs:960) and extras_idle_secs=30 (default 0). The slot's idle window was SHORTER than its own load time, so any think-pause over a minute re-paid the full 18.5GB load. Loaded 7x in one day, mostly for background wl-housekeep (every 30s) / wl-judge jobs; at 18:49:23 it unloaded and reloaded 1s later. Fixed to 1800 / 0.

CORRECTION TO THE SUPERSEDED NOTE: it claimed '/status.inference.resident[] lies — it said resident:true while the slot was idle-unloaded.' THAT IS FALSE. Verified directly against a freshly-restarted daemon: a cold primary reports {role:primary, resident:false, size_bytes:null, transitioning:false}. /status is honest. The original observation was a misread — the slot was genuinely loaded at the moment of that query.

THE REAL TRAP (verified, and it is a different one): InferenceProvider::resident_slots() is SYNC and returns [] for any provider that owns no local weights. The attach-mode desktop runs its Runtime IN-PROCESS against oicp_client::SplitInferenceProvider ('routing inference to the daemon over HTTP — no local weights loaded'), so residency read through resident_slots() is empty there and any check built on it is a silent no-op in exactly the configuration users run. Added async InferenceProvider::primary_slot_status() (traits.rs, default derives from resident_slots()) with a SplitInferenceProvider override that GETs the daemon's /status.

ALSO VERIFIED: ResidentSlot::size_bytes is the RESIDENT footprint and is null whenever resident=false (engine.rs ~1841). Any UI keyed on a cold slot must degrade to the model id — do not promise a GB figure.
