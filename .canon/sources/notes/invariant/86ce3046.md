# INVARIANT: enrichment (and ingest) cannot be starved by foreground yield. YieldHook::should_yield() is a LEVEL predicate — it must never be…

INVARIANT: enrichment (and ingest) cannot be starved by foreground yield. `YieldHook::should_yield()` is a LEVEL predicate — it must never be parked on without a `corpus_engine_yield::DeferralBudget`.

## The bound
`corpus-engine-yield/src/lib.rs` — `MAX_FOREGROUND_DEFERRAL = 300s` (five whole 60s default windows; half the desktop's 600s enrich-once client timeout at `local_corpus_commands.rs:545`). NOT an env flag, NOT config. `DeferralBudget::with_cap_at_most` CLAMPS to it, so a caller can only tighten, never weaken.

`corpus-engine/src/engine/yield_gate.rs` owns the wait loop, the 5s poll and the three events. The `warn!` override (`yield: deferral cap reached`, carrying `deferred_secs` + `cap_secs` + `checkpoint`) is emitted INSIDE the helper so no checkpoint can adopt the bound and forget to announce it. `YieldExit` is an enum, so "resuming — foreground idle" cannot be printed after a cap override. Both ingest checkpoints (`ingest.rs` embed + enrichment) go through it.

## The prober, NAMED (was the open question in note 3a295d81)
`sovereign-server` in mobile-host mode, config `~/.svrnmesh/mobile-host-server.toml`, `[[inference.backends]] type="remote" endpoint="http://127.0.0.1:9741/v1"`. `sovereign-server/src/main.rs:216` → `HybridProvider::start_health_loop(30)` → `hybrid.rs` probe `prompt:"ping", max_tokens:Some(1), Speed::Fast` → `oicp-client/src/lib.rs:722` POSTs `/v1/chat/completions` → `routes_inference.rs:43` `bump_foreground_active()`. 30s < 60s window ⇒ starvation. Confirmed empirically 2026-08-18: PID 8194, up 5 days, ESTABLISHED 127.0.0.1:62867->127.0.0.1:9741. It is PRODUCT code, not harness — every mobile-access user has it.

## The probe fix
`HybridProvider::health_sweep` now probes ONLY backends the tracker has marked unavailable. Real traffic already feeds the same tracker (`hybrid.rs` complete() record_success/record_failure), so a healthy backend needs no probe; the loop's remaining job is REPAIR (3 consecutive failures take an entry out of the selector's candidate set and only a probe can bring it back). Given up, stated: a silently-dead backend carrying zero traffic is no longer pre-detected — nothing consumes that while there is no traffic, and complete() already retries twice.

## One decider
`AppStateInner::foreground_yield_remaining_secs` (state.rs) is now the ONLY implementation of the predicate. It was three copies (the hook, `should_yield_to_foreground`, `seconds_until_foreground_idle`) and they HAD diverged on the backwards-clock case, so `/internal/daemon/foreground_state` could report the opposite of what ingest was doing. Reconciled toward yielding.

## STILL OPEN — escalated, not fixed
`/v1/chat/completions` marks foreground for EVERY caller. There is no signal distinguishing a liveness probe from a person, and adding one is a contract change (order seam). The bound is what makes misclassification survivable.
