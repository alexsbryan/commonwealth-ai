# Qwen MoE family (qwen3moe/qwen35moe/qwen36moe arch) has prefix cache architecturally disabled in sovereign-inference because Gated DeltaNet…

Qwen MoE family (qwen3moe/qwen35moe/qwen36moe arch) has prefix cache architecturally disabled in sovereign-inference because Gated DeltaNet recurrent layers can't survive partial KV-cache keep.

`is_recurrent_arch` at `sovereign/crates/sovereign-inference/src/embedded.rs:7262` returns true for any gguf arch matching `qwen*moe` (qwen3moe, qwen35moe, qwen36moe). That gates `prefix_cache_safe` to false → `lcp = 0` → `cache_hit_tokens = 0` regardless of how much the new prompt shares with the cached one.

Why: Qwen MoE families carry Gated DeltaNet layers in the gguf attention stack. Same recurrent-state hazard as Mamba — partial-keep prefix-cache returns -1 on tail decode.

How to apply: When tuning Phase 1b throughput on FINAL-Bench / Qwopus / any Qwen3.5-MoE-class model, do NOT spend cycles on prefix-cache optimisations (prompt layout, CONCURRENCY=1, conversation_id plumbing). They are correct on pure-attention models (Llama, Qwen2.5-Dense, Mistral) but no-op here. Spend the budget on shortening generations instead — that's what bought the 33s/batch on multi-wide vs 50s on multi-tiny.

Verification: `grep "MTP candidacy decided" daemon.err | grep arch=` — if `arch=qwen*moe`, prefix cache is dead by design. Compare with `prefix_cache: prefill scope` log — `cache_hit_tokens=0` with non-zero `raw_lcp` confirms the gate is firing.

Escape hatches:
- Switch enrichment model to a non-MoE GGUF (loses any tuning that was MoE-specific).
- Wait for llama-cpp upstream to implement Gated-DeltaNet-aware partial keep.
