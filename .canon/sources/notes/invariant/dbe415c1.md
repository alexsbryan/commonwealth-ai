THE SURGICAL FIX PATH WAS COLLAPSING PARAGRAPH BREAKS, ON EXACTLY THE INPUT SURGERY EXISTS FOR. Found 2026-09-02 while building out surgical.rs coverage; the test that found it was written to pin the module's own stated promise ('keeps every verified sentence VERBATIM and touches only the failed spans') byte-for-byte rather than by contains().

MECHANISM. split_sentences is LOSSLESS, which means the whitespace separating a sentence from its predecessor lives on the FOLLOWING element: "A.\n\nB." splits to ["A.", "\n", "\nB."] — five elements for a three-paragraph draft, with each paragraph break split across a standalone "\n" element and a leading "\n" on the next sentence. The fix path overwrote the whole element (sentences[idx] = format!("{new} ")), so a repaired sentence lost its leading break and merged into the paragraph above it; the unconditional trailing space then landed BEFORE the next break, giving '... household. \n\nDmitri'.

WHY NOTHING CAUGHT IT. The DELETE path is immune — it blanks the element but the standalone "\n" survives, so the break holds — and every pre-existing fix-path test used a single-paragraph draft. Surgery only ever runs on longform answers, i.e. the multi-paragraph case, so the defect was live on precisely the input the module exists for. It damages readability without touching a claim, so no grounding or fabrication metric reports it: hallucination, grounding and CONFAB all stay flat while the answer visibly degrades.

FIX. Re-attach the original element's own leading and trailing whitespace around the trimmed replacement body, and scope the anti-fusion space to the case that can actually fuse (original ended flush AND the next element does not open with whitespace). repaired_spans still carry the bare trimmed body — the incremental re-audit judges content, not structure.

GUARD: surgical::tests::a_repaired_paragraph_keeps_its_break (two paragraphs, one fix) plus repaired_spans_are_the_new_prose_in_document_order (three paragraphs, two fixes) which asserts the full output string. Watched: reverting to format!("{body} ") reddens both.
