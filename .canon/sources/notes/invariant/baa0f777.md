PER-USER SOVEREIGN PATHS MUST COME FROM `sovereign_contracts::rebrand` — `dirs::home_dir()` is banned workspace-wide by clippy.toml (path-SSOT, center-of-mass P2, 2026-07-30). A hand-rolled `dirs::home_dir().join(".sovereign")` misses BOTH the `~/.svrnmesh` rebrand and its populated-legacy fallback, so it silently reads/writes a different directory than every other subsystem.

The accessors: `svrnmesh_root()`, `data_dir()`, `mesh_data_dir()`, `projects_json()`, `work_atlas_toml()`, `drift_dir()`, `journal_dir()` (added 2026-08-07), `state_db_path(dir)`. `rebrand.rs` itself carries the single `#[allow(clippy::disallowed_methods)]`. Outside sovereign-*, `sovereign_cli_shared::dirs` wrappers are the other sanctioned route. Adding a new per-user directory means adding an accessor THERE, not joining in the consumer.

ENV VARS ARE THE OPPOSITE CASE — do not "fix" them. Plain `std::env::var("SOVEREIGN_X")` is correct and house-standard: `rebrand::promote_legacy_env()`, called from each binary's `main()` before the runtime is built, mirrors SOVEREIGN_*/SVRNMESH_* in BOTH directions, so a read under either prefix sees a value set under either. It prints "svrnmesh: bridged N legacy SOVEREIGN_* env var(s)" when it promotes, which looks like a warning about your code and is not. `quality/env-flags.toml` declares flags under the SOVEREIGN_ prefix (73 shipped rows), so a new flag matching that is consistent, not stale. `rebrand::svrnmesh_env(suffix)` is for library reads of vars that are `set_var`'d AFTER main().
