# A WORKER THAT IS BUSY DOING OUR WORK LOOKS DEAD, SO EVERY MODEL WHOSE CHILD NEEDS >120 s TO LOAD IS UNRUNNABLE DISTRIBUTED. Found…

A WORKER THAT IS BUSY DOING OUR WORK LOOKS DEAD, SO EVERY MODEL WHOSE CHILD NEEDS >120 s TO LOAD IS UNRUNNABLE DISTRIBUTED. Found 2026-08-02 on the DeepSeek-V4-Flash-0731 run (RuggedFox + BeefyMac); stopgap knob is live in 40-toolbox.conf and will be deleted with it, hence this note.

MECHANISM. ggml's RPC server accepts ONE connection at a time (ggml-rpc.cpp:1750-1761: `while(true){ accept(); rpc_serve_client(...); }`). While it serves the compute child's model connection it CANNOT accept our liveness probe — so the busier the worker, the deader it looks. In `evidence_for` (worker_eligibility.rs:340-378) the only thing vouching for a busy peer is `warm_alive_at`, and it stops vouching after `absence_grace` (default 120 s). The worker is graded Absent 120 s after the warm completes, the eligible set empties, and RETIRE_GRACE (discovery_policy.rs:76) fires 90 s later — the supervisor SIGTERMs a perfectly healthy child MID-LOAD with "no eligible RPC workers".

MEASURED. The 4B split test warms->serves in 26 s and passes. The 284B took >223 s and was killed at 19:22:34. The failure is a function of LOAD DURATION, not of model or worker health — which is why it presents as "big models don't work distributed" rather than as a timeout.

STOPGAP (live now): `SOVEREIGN_RPC_WORKER_ABSENCE_GRACE_SECS=900` on the ExecStart env prefix in ~/.config/systemd/user/sovereign.service.d/40-toolbox.conf. With it the run got materially further than any prior attempt — the child reached real prefill (`prefix_cache: prefill scope ... new_prefill_tokens=15`, 19:37:47) before dying on the separate worker-drops-shard bug at ggml-rpc.cpp:498.

REAL FIX: treat a child that is warming or serving against an endpoint as liveness evidence for that endpoint, the same way `warm transfer succeeded — treating this peer as alive` already does. Until then the grace knob must be raised for any model whose load exceeds ~2 min.
