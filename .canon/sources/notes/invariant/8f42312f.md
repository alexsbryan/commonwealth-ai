# The desktop real-mode e2e harness runs TWO binaries, and its global-setup must build both.

The desktop real-mode e2e harness runs TWO binaries, and its global-setup must build both.

`tests/e2e/real/global-setup.ts` built only `-p sovereign-desktop`, but managed mode (the default) also launches `target/debug/sovereign-cli-daemon`, and THAT process owns ingest+enrich. Consequence observed 2026-07-24: a corpus-engine bug fixed in the working tree reproduced verbatim on the next run, with an error message quoting source that no longer existed — because the stale daemon binary was serving the ingest. Fixed by building `-p sovereign-desktop -p sovereign-cli-daemon` in one cargo invocation (one feature resolution for the shared deps; two narrow builds thrash the target dir).

Generalisation: when a real-mode failure's error text doesn't match the source you're reading, check WHICH binary produced it before doubting the fix. "daemon ingest+enrich failed (500 …)" in the harness log means the daemon, not the desktop.

Also: run the suite from `sovereign/crates/sovereign-desktop` with the operator daemon stopped (`sovereign daemon stop`) — managed mode needs :9741 free — and start it again afterwards. Note the sovereign MCP tools are served by that daemon, so they are unavailable for the duration of the run.
