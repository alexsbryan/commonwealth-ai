LocalCorpusManager::enable_enrichment errors (glassbox) when tiered deps unwired — it must NEVER fall back to a sovereign-cli enrich subprocess

`LocalCorpusManager::enable_enrichment` (sovereign-tools/src/local_corpus/manager.rs) routes ONLY through the in-process tiered driver (`start_tiered_build`, gated on `enrichment_driver.is_tiered_ready()`). When tiered deps are NOT wired it stamps `EnrichmentRuntimeStatus::Failed` + returns `Error::Execution("in-process tiered enrichment is not available…")`.

**Do NOT re-add a `sovereign-cli enrich` subprocess fallback here.** The old fallback (`EnrichmentDriver::start_build` → `run_enrich_build`) exited 127 in deployments that don't bundle the CLI (the desktop's embedded daemon), silently wedging builds at "Preparing to build the map". A loud error is the intended behavior — the fix is always daemon-side: wire the tiered provider + GliNER extractor at boot via `set_tiered_deps` (desktop does this via `sovereign_tools::enrichment_bootstrap`; standalone daemon in sovereign-cli-daemon).

`EnrichmentDriver::start_build` still exists as an unreachable, tested library primitive (doc-marked "NO LONGER WIRED"). Don't re-wire it into any user-facing enable path. Part of [[project_desktop_cli_enrich_shellout_sweep_2026_07_16]].
