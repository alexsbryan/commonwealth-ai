DAEMON HOT-RELOAD DROPS EXTRA SLOTS — do not "fix" ConfigDiff by adding models.extra (found 2026-08-23).

`ConfigDiff::diff` (`sovereign-mesh/src/admin_http.rs`) compares models.primary / models.fast / models.embed and several daemon fields. Two model fields were MISSING, so `is_noop()` short-circuited the rebuild and the change silently never applied while the CLI reported success (§18.3):
- `models.context_size` — `svrn model context 65536` wrote the config, printed "no config changes detected — nothing to reload", and the daemon kept serving 32,764 until restarted by hand. Cost an hour before it was noticed.
- `models.code` — same shape: `svrn model set code <file>` on a running daemon was a no-op reporting success.

Both are genuinely HOT-RELOADABLE, not restart-required: `sovereign-cli-daemon/src/daemon_cmd/provider.rs:37-66` `build_provider` reads `cfg.models.effective_context_size()` and `cfg.models.code` and rebuilds every slot from scratch. FIXED — both arms added, plus `reload_applies_a_context_size_change_without_a_restart` and `reload_applies_a_code_slot_change_without_a_restart`.

THE HAZARD, left unfixed and deliberately so: `build_provider` installs NO `[models.extra]` slots, no extras memory budget, and no extras idle monitor. The cold-start path does all three (`daemon_cmd/build/inference.rs:167-185`). So ANY hot reload — including one triggered by a primary/fast/embed change today — silently drops every extra slot, the 122B included.

DO NOT add `models.extra` to `ConfigDiff` until `build_provider` mirrors the cold-start extras install. Adding it alone would make the drop MORE frequent, not less: it would turn "extras vanish when you change primary" into "extras vanish when you change extras". Fix the provider first, then the diff.
