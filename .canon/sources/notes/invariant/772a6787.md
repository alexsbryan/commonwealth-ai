# sovereign drift detect --output ~/.svrnmesh/drift/latest.md DESTROYS THE REPORT IT JUST RENDERED — 0 bytes, exit 0, success banner. Hit…

`sovereign drift detect --output ~/.svrnmesh/drift/latest.md` DESTROYS THE REPORT IT JUST RENDERED — 0 bytes, exit 0, success banner. Hit live 2026-08-03 after a 61-minute rebuild.

MECHANISM. The orchestrator renders to `--output`, then mirrors that
file to the canonical path (drift_cmd_orchestrator.rs, the
`canonical mirror` step ~:560). When `--output` IS the canonical path,
the mirror is a SELF-COPY: the destination is opened truncating while
it is also the source, so both `latest.md` and `latest.md.json` end up
zero-length. The run still prints

  ✓ wrote .../latest.md (50 findings rendered)
  ✓ canonical mirror: ~/.svrnmesh/drift/latest.md
  ✓ drift report ready

and exits 0. Nothing in the output suggests the artifact is empty.

WHY IT IS EASY TO HIT. The canonical path is the natural thing to pass
— it is where `drift_posture` reads from, it is what the previous run's
`.fingerprint` records as `output_path`, and the 2026-05-30 run used
exactly that value. Passing it is the obvious way to avoid the OTHER
papercut (the default `--output` writes `./drift_report.*` into the
REPO ROOT, over committed files).

WHAT IS NOT LOST. Only the rendered report. The atlases, the
archaeology and rough-edges artifacts all survive, and with the
source-hash provenance in place a re-run takes the cached branch and
re-renders in ~3 minutes instead of re-doing the LLM extraction. So
the recovery is: re-run with `--output` pointing ANYWHERE ELSE (a
scratch path is fine — the mirror will then copy correctly into
`~/.svrnmesh/drift/`).

THE FIX, not applied: skip the copy when `output_path` and the
canonical destination resolve to the same file (compare canonicalised
paths), or refuse the invocation. A no-op is the correct behaviour —
the file is already where it needs to be.
