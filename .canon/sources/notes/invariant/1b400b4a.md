# chat_template lookup must retry on BuffSizeError up to ~256KiB or modern HF templates (>8KiB) silently fall through to plain-text concat

chat_template lookup must retry on BuffSizeError up to ~256KiB or modern HF templates (>8KiB) silently fall through to plain-text concat

`sovereign-inference/src/llama.rs::chat_template()` calls
`model.get_chat_template(buf_size)` which can return:

- `Ok(template)` — template found and fits
- `Err(ChatTemplateError::MissingTemplate(_))` — gguf has no chat_template key (legit None)
- `Err(ChatTemplateError::BuffSizeError(needed))` — buffer too small, retry with `needed`
- `Err(ChatTemplateError::Utf8Error(_))` — encoding garbage

Pre-2026-05-19 the call was `model.get_chat_template(8192).ok()` —
`.ok()` flattened all three error variants to `None`, masking
buffer-size failures as missing-template failures.

Why: Gemma 4 E4B-it's gguf carries a ~12 KiB Jinja2 chat template
(it ships native tool-calling macros: `format_parameters`,
`format_function_declaration`, `strip_thinking`). The upstream
`llama-cpp-4` wrapper docs the buf size as "longest known template
~1200 bytes" — true for llama.cpp's pre-tool-calling era, false for
HF-grown templates that routinely cross 10 KiB. The 8 KiB cap silently
returned None, which dropped Gemma 4 chat to plain-text concat
(`{system}\n\n{user}`) — no `<|turn>` markers, no `<|tool>`
declarations, no stop discipline. Model generated until inference
deadline (~14k tokens of role-play). Codex gym scored 0% on every
fixture in this state.

How to apply: when adding a model family with non-trivial template
features (tool-calling, multi-modal markers, channel-thinking),
verify `chat_template lookup returned None` does NOT appear in
daemon.out for that model. If it does and the gguf's `strings` output
contains `tokenizer.chat_template`, the buf size is the bug — not
the model. Same retry pattern as `token_to_piece_bytes` in
`json_constraint.rs:2439-2447`.

Related: [[minijinja-method-shim]] is the sibling — once the template
loads, minijinja still needs Python-shape methods (`get`, `split`,
`startswith`, `upper`, …) to render HF templates without falling
through to the next tier.
