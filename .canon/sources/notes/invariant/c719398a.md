# A crate RENAME can silently retire live debt and blind live ratchets. Learned twice on branch domains-1-empty-the-commonwealth-directory…

A crate RENAME can silently retire live debt and blind live ratchets. Learned twice on branch domains-1-empty-the-commonwealth-directory (commits 904145b64 domains-1, cd9250aab domains-2). Before renaming or moving any crate, check BOTH halves:

1. GRANDFATHERINGS KEYED BY THE OLD NAME. quality/ARCH_LAYERS.toml [[forbid]] and [[exception]] match on crate-name strings. Rename the subject of a live [[exception]] and the row goes stale, the gate tells you to DELETE it, and the debt disappears from the burn-down without anyone paying it. domains-1 wrote a `tracking` field on the commonwealth-test-harness -> sovereign-api exception saying exactly "delete it when `from` stops matching" — that was the wrong removal condition. The right move is to TRANSLATE both rows to the new name and rewrite `tracking` to name the condition that actually discharges the debt (here: the harness simulating a node against oicp-types alone). Precedent for translating rather than deleting is already in the file — sovereign-{serving,grants,meshapp-registry} kept their `to = "sovereign-*"` forbid rows through domains-1 with the reason rewritten to say the PROPERTY is unchanged.

2. PATH-KEYED AND NAME-KEYED BASELINES. domains-1 renamed four crates and updated none of these, and nothing went red in a way that named the cause. The misses surfaced a commit later as invented growth: size-gate reported the four as "new and unbaselined" (+18,005 / +16,431 / +1,217 / +563 …), reading as 37k lines this branch never added and hiding all future growth in them under one accept; arch-gate reported TEN "NEW oversized file" findings in sovereign-api for files baselined for months. The files to rekey: quality/baselines/lines.tsv (size-gate, `<path>` and `<path>::tests`), quality/baselines/oversized.txt (arch-gate, per-file paths), quality/baselines/clock_reads.txt (per-file paths), quality/baselines/clippy_counts.tsv (keyed by CRATE NAME, not path). Also non-baseline path keys: sovereign-core/tests/main/f26_egress_census.rs, quality/sabotage/all.toml, quality/conformance-specs.toml.

PROVE THE REKEY NEUTRAL BY SUMMING BOTH SIDES, never by --update-baseline on a working tree — the latter absorbs everyone else's growth along with your rename. domains-2 did: lines.tsv 898,500 == 898,500 across 6 keys; oversized.txt 376,106 == 376,106 across 10. After those two rekeys size-gate went 18 keys -> 12 and arch-gate 12 findings -> 2, and everything remaining was provably main's, not the branch's.

docs-gate is the third surface and it DOES go red, so it self-reports: it resolves inline code spans by suffix match, so `commonwealth-test-harness/tests/integration.rs` resolved against the old path and stopped resolving after the move. When the citation is HISTORICAL (a byte-identical-at-commit-X claim), allowlist it in corpus-engine/xtask/doc_path_allowlist.txt rather than rewriting the path — rewriting makes the claim false.
