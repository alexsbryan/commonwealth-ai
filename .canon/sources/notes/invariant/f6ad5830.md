FAN-OUT GATING: workers run TARGETED tests; the SEAT runs ONE definition-of-done sweep when they all return. Operator direction 2026-08-20: "when you spawn three you should just run a single definition of done sweep when they all return upward (they can do targeted cargo tests)".

THIS IS A CORRECTNESS RULE, NOT AN EFFICIENCY ONE, and that is why it is an invariant. `scripts/sovereign-test.sh` exits 5 on UNATTRIBUTABLE RESULTS by design: concurrent nextest runs overwrite the shared JUnit report, so the counts are not yours. N concurrent workers each running the unscoped suite therefore either collide into exit 5, or — the bad case — one of them reads a green summary that belongs to a peer. A parallel fan-out where every worker runs the full suite is a fan-out that cannot report an honest verdict.

THE SHAPE:
- Workers: `./scripts/sovereign-lint.sh --human` (scoped), `./scripts/sovereign-test.sh --human --package <crate> | --changed | --filter <test-name>`. Cheap structural gates like `cargo xtask layer-gate` stay with the worker — they are the proof their specific move landed.
- Worker verdicts report the full suite as "not-run-by-design, deferred to the seat's sweep" — NOT as passed, NOT as failed. That is a fifth honest state alongside §18.1's four, and it exists because the run was deliberately not theirs to make.
- Seat: after all workers return, ONE `./scripts/sovereign-lint.sh --human --full` + ONE unscoped `./scripts/sovereign-test.sh --human`. That is the definition of done for the whole fan-out.

Still true inside the targeted forms: gate on EXIT CODES, never a summary line; a zero-test run exits 4 and is NOT green (`--filter` matches the TEST NAME, not the file, so a typo verifies nothing).

Corollary for the seat: if the sweep goes red, attribution is the seat's problem, not a worker's. Diff-by-worker before assigning blame — and check first whether the failure predates the fan-out at all.
