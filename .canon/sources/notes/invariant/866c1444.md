A DEFECT-INJECTION HARNESS THAT PATCHES THE WORKING TREE MUST NEVER RUN WHILE A COMMIT IS BEING PREPARED. Cost 2026-09-07, cw-lift 4a: scripts/../scratchpad/inject.py applies each defect to commonwealth-rail/src/lib.rs, runs the suite, and restores at the end. A backgrounded re-run happened to have D2 applied (`>` for `>=`, which deletes the seal that IS the floor) at the moment `git add` ran, so the INDEX took the defect while the worktree was restored to correct seconds later. `git status` looked normal; `git diff` showed the defect as an UNSTAGED fix, which reads like leftover noise. Only .claude/hooks/commit-smells.py blocking the commit for an unrelated reason forced the second look that found it. Two rules: (1) never background an injection run, or point it at a scratch copy of the crate, not the tree you commit from; (2) before every commit, diff the INDEX against the intended content (`git show :<path> | grep <the invariant>`), not the worktree — `git add` snapshots a moment, and on this repo the tree moves under you.
