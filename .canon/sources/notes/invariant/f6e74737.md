Daemon eager-loads fast 9B + embed 0.6B at startup (~8GB baseline RSS) regardless of usage. Mixing primary 35B + fast on 64GB host overshoots macOS jetsam at ~44GB. Bench must pick one slot or accept OOM risk.

`EmbeddedLlamaCpp::start` at `sovereign-inference/src/embedded.rs:4830` synchronously calls `ModelSlot::load` on the `fast` slot (and the `embed` slot a few lines later). These slots are never lazy — they pin their GGUF files into the process from daemon-start onward.

**Empirical RSS trajectory measured 2026-05-21 on a 64GB-RAM box, daemon just restarted, single trivial primary ping (`max_tokens=5`):**

| t | observation | RSS |
|---|---|---|
| 0 | daemon idle, /status reports `loaded_models: []` | 32 GB |
| +8s | primary 35B mid-load + decode | 46 GB (jetsam SIGTERM at ~44GB) |
| +16s | KV cache freed, primary still resident | 36 GB |
| post | fast still pinned, primary mostly evicted | 22 GB |

Why: vmmap shows `Qwen3.5-9B-Claude-4.6-HighIQ-INSTRUCT.Q6_K.gguf (6.8G resident)` + `qwen-embedding-0.6b.gguf (1.1G resident)` from boot. `/status.inference.loaded_models` is hardcoded `Vec::new()` at `sovereign-mesh/src/capabilities.rs:139` — a reporting lie. The slots ARE loaded; the field LIES.

**Fix landed 2026-05-21 evening (config-only): omit `fast` from `~/.sovereign/config.toml`.** `setup_config.rs::ModelsSection::fast_path()` already subsumes to primary when fast is unset (the underlying support was already wired). When `fast_path == primary_path`, the embedded daemon's `primary_is_alias` branch (`embedded.rs:5020-5054`) constructs the primary slot as an alias of fast's `Arc<LlamaModel>` — one model load, two contexts (separate KV caches). Measured baseline RSS dropped 32GB → 5.8GB; peak during single primary inference 46GB → 6.1GB on the 64GB Mac. Jetsam risk eliminated.

How to apply:

1. Bench runs: do NOT mix slots. Use `--model commonwealth/primary --judge-model commonwealth/primary` OR `--model commonwealth/fast --judge-model commonwealth/fast`, not cross-slot. (Less critical now alias is in effect, but still good hygiene.) The `fast` alias resolves to primary too, so both flags route to the same loaded model.
2. OOM diagnosis: when daemon emits `peak RSS suggests possible jetsam/OOM trigger ... rss_mb=4400X SIGTERM`, the cause is structural, not a leak. Three signals to capture: (a) `vmmap <pid> | grep -E "TOTAL|gguf"` for actual resident model bytes, (b) `/status.inference.loaded_models` (lying — always `[]` until capabilities.rs:139 fixed), (c) RSS trajectory via `ps -o rss` over the request lifecycle.
3. Production fixes (alias-mode is the actual fix; rest deferred):
   - LANDED — config-only fix: omit `fast` from config.toml, alias kicks in automatically (one model load, separate KV).
   - F-OBS (still wanted): `/status.loaded_models` is still a lie even with alias mode; new endpoint `/internal/runtime/slots` should expose actual embedded daemon inventory. ~1h.
   - F-LAZY (deferred, lower urgency): defer slot construction entirely until first chat request. Useful if user wants ZERO model loaded at idle. ~4h.
