Desktop document upload: upload_document_asset MUST call DocumentAssetManager::prepare (mints+persists the Pending asset id) then spawn run_ingest(prepared, ...) — NOT ingest(). prepare-returned id == the id every IngestProgress fires under == the id the UI banner subscribes to. The old path created an asset id in the command AND let ingest() mint a second internally; the banner watched id #1 while events fired under id #2, so it sat on "Queued…" for the whole ingest while a duplicate record reached Ready unseen. Pinned by functional test ingest_emits_progress_under_the_prepared_asset_id.
