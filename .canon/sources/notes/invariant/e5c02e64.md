THE VERIFIER EVAL HARNESS SCORED CORRECT ANSWERS AS FAILURES, AND FOR THE 0.8B IT PRODUCED NO MEASUREMENT AT ALL. Measured 2026-08-02, M2 Max, `research/verifier-v0/runs/m1-evalleg-probe/`.

| protocol | BAcc strict | BAcc tolerant | hit token cap | throughput |
|---|---|---|---|---|
| thinking ON (the committed baseline protocol) | 0.00 | 0.00 | 55/55 | 7.3 items/min |
| thinking OFF (--no-think) | 10.88 | 55.03 | 3/163 | 83 items/min |

DEFECT 1 — REPETITION LOOP. At temperature 0 with no repetition penalty the 0.8B reaches a correct answer in ~200 tokens then repeats (`Is "in County Clare" supported? Yes.` x N) until max_tokens, never leaving <think>. 55/55 items capped, zero verdicts. Same failure gave the 4B baseline its 7.6% parse-fail rate — it scales INVERSELY with model size, i.e. worst exactly where the 0.8B lane lives. Tried on 4 items: repeat_penalty 1.1 fixed 1/4; temp 0.6/top_p 0.95 fixed 0/4; disabling thinking fixed 4/4 at 78-101 tokens.

DEFECT 2 — ALL-OR-NOTHING PARSER. `ANSWER_RE` demanded a fully well-formed <answer> block. The 0.8B emitted `<classification>GROUNDED</classification>` then `</justivation>` (typo) with no `</answer>`; with thinking off it emitted a JSON body inside <answer>. Both correct, both discarded. Only 31/163 rows (19%) were strictly well-formed. Strict BAcc 10.88 is BELOW CHANCE by design — a parse failure scores as the WRONG label, so BAcc goes to 0 not 50. Read a sub-50 strict BAcc as "no measurement", never as "worse than a coin".

FIXED, additively (parse_verdict stays strict so BASELINES.md stays reproducible): added parse_verdict_tolerant (strict -> <classification> tag -> "classification": JSON key, reporting which path hit); results.jsonl gains pred_tolerant/cls_tolerant/parse_mode; summary.json gains subsets_tolerant, macro_avg_bacc_tolerant, a parse block, and the PROTOCOL (sampling overrides) so a --no-think run can never be silently compared to a thinking run. Tolerance still reads only after the last </think>, so a model reasoning about the categories cannot leak a verdict — pinned in scripts/test_eval_grounding.py (9/9).

ROOT GLASSBOX FAILURE: results.jsonl stored only the PARSED verdict, never the raw text. Quantifying defect 2 against the committed 4B baseline therefore needs a 6-hour re-run for what should be a 2-second offline re-parse. eval_grounding.py now writes responses.jsonl by default. IF A RUN CANNOT BE RE-SCORED WITHOUT RE-RUNNING THE MODEL, IT IS NOT INSTRUMENTED.
