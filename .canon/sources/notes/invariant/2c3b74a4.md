PER-SLOT KV WINDOWS + THE GUARD THAT COULD NOT FIRE (2026-08-25). Acts on RuggedFox's measurements in note 05cbffed; three code changes, one deliberate non-change, one correction to that note.

=== 1. PER-SLOT CONTEXT WINDOWS (the "ours to fix" item) ===
`Runtime`-side nothing; this is all sovereign-inference.

`SlotWindows { primary, fast }` replaces the bare `context_size: u32` scalar threaded through `load_full_inner` into EVERY `ModelSlot::load`. New config key `[models].fast_context_size`, resolved by `SlotWindows::from_models`.

WIRING (verify before assuming): `from_models` at daemon_cmd/provider.rs, daemon_cmd/build/inference.rs, desktop state/config.rs. `SlotWindows::uniform(..)` at sovereign-server main.rs x2 (its own ServerConfig has no per-slot key) and at load_dual / load_single_distributed (compute children — one slot IS the only slot; `uniform` NAMES that rather than leaving it indistinguishable from a host that forgot).

SHIPPED UNSET AND WHY. `fast_context_size` unset resolves to the primary's window = byte-identical to before. Pinned by `an_unset_fast_window_is_the_primary_window` (sovereign-contracts). NOT set to a value because the FAST SLOT IS THE OVERFLOW PATH — `pick_slot` routes any prompt too large for FastShort's 2048-token per-sequence budget to `fast`, so its window must cover the largest prompt that LANDS there, not the typical one. Nobody has measured that. Guessing trades a known memory cost for an unknown `NoKvCacheSlot` at decode. DEFAULTS_LEDGER.md row carries the flip condition + review-by 2026-09-25.

PRECEDENT (§19): the `[edit]` section ALREADY had its own context_size for exactly this reason. The mechanism was never missing, just never extended to the slot costing the most.

=== 2. PER-CONTEXT KV PRICING (glassbox) ===
`sovereign-inference/src/embedded/kv_budget.rs`. Computes 2 x n_ctx x n_layer x n_kv_head x head_dim x dtype from gguf metadata; emits one `kv budget: slot context built` line PER CONTEXT at load. Removes the need to raise llama.cpp's log level + reboot to get the per-slot split.

`ModelSlot::load` and `from_existing_model` now take `slot: &'static str` as their FIRST arg — a context cannot be built without naming which slot spent the memory. Labels: fast / fast_short / primary / primary_sibling / primary_alias / extra.

IT IS A CEILING, TWICE OVER — the field is `kv_ceiling_mib`, not `kv_mib`, on purpose:
  (a) LAZY ALLOCATION. RuggedFox measured the 27B at ~6.6 GB KV despite 2x the layers of the 4B set — wrong way round for an eager allocator. NOT root-caused. So this is what a full window COSTS, not what is committed now. For "what is resident", read GTT/RSS from the OS.
  (b) HYBRIDS. n_layer is TOTAL block count; Mamba/RWKV/deltanet/jamba blocks are not uniformly attention layers -> `upper_bound_only` flag.
Missing metadata returns None and logs "cannot price this slot" — never a plausible wrong number (§18.3).

=== 3. THE RSS GUARD COULD NOT FIRE — memory_watch now watches headroom ===
`sovereign-cli-daemon/src/memory_watch.rs`. RSS is the WRONG NOUN: kernel killed at anon-rss 36.4 GiB vs 36.0 GiB steady state (no separation), `=auto` resolves to 85%/65% of RAM. Exhausted resource was GTT, which RSS does not count. Six kills, guard silent through all six. §18.1: a guard that cannot fail is worse than none.

ADDED: `host_available_mb()` — MemAvailable on Linux; free+inactive+purgeable on macOS. `SOVEREIGN_HEADROOM_SOFT_MB` (warn, DEFAULT ON, max(4096, 15% RAM)) and `SOVEREIGN_HEADROOM_HARD_MB` (graceful self-SIGTERM, DEFAULT OFF — same supervisor rule as the RSS hard limit). Both declared in quality/env-flags.toml; docs/ENV_FLAGS.md regenerated.

15% IS DERIVED, NOT CHOSEN: pre-restart daemon sat at 19.1 GB MemAvailable on a 125 GB box (15.3%) — the regime the kills happened in. Test `the_headroom_warning_fires_where_the_rss_limit_could_not` replays those exact numbers.
TEST TRAP: assert the RATIO, not a literal limit — HARD_PCT is platform-conditional (85 Linux / 65 macOS), so a hardcoded ~108 GB expectation passes on Linux and fails on macOS while testing nothing. Caught by that failure.
THE LOG LINE SAYS IT IS NOT AN ACCUSATION: headroom is shared (gnome-shell held 12.55 GB on the measured host); the daemon exits because it is the process that can come back cleanly, not because it is the culprit.

=== 4. DELIBERATE NON-CHANGE: hardware.rs detect_gpu ===
`hardware.rs:129` returns `false, // discrete GPU — not unified memory` for EVERY non-Apple GPU. Strix Halo IS unified. Consequence traced: `is_unified_memory` -> `effective_vram_gb()` (unified => system RAM; discrete => the Vulkan device's reported memory_total) -> `select_profile()` thresholds; also the "unified "/"Apple Silicon" strings in desktop setup_flow.rs:748 and setup_cmd.
NOT FIXED, ON PURPOSE. Whether the PROFILE comes out wrong depends on what Vulkan reports for memory_total on a Halo, which cannot be determined from a Mac. A blind change to the code deciding memory posture, on the box that is OOMing, needs the hardware in front of it. Needs a real APU signal (DRM sysfs mem_info_vram_total vs mem_info_gtt_total), not a flipped constant.
