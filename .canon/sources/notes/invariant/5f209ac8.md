ACQUISITION DIAGNOSIS (2026-08-24, measured off the drb1-t1 replay harness — 843 recorded rows across 9 DRB-I tasks, plus a live run today).

THE BINDING CONSTRAINT IS K=5, NOT THE SCORER. `acquisition.rs` `DEFAULT_CODE_SET_K = 5` + `DEFAULT_EPS_QUOTA = 0.1`. The code says it plainly at acquisition.rs:612 — `below-cut` is "a rank boundary, never an exclusion". So the admission score only RANKS; K cuts. Every anomaly follows from that one fact:
  - admit score range 0.100-0.769 OVERLAPS skip range 0.000-0.583 (n=110 admit / 733 skip). A row at 0.100 is admitted when it is top-5 in a weak field; 0.583 is skipped at rank 6 in a strong one.
  - identical scores get opposite decisions in the same task+round (task 56 r1: 0.556 rank 8 ADMIT, 0.556 rank 9 SKIP, 0.556 rank 15 ADMIT, 0.556 rank 17 SKIP).
  - ~6 rows admitted per task+round, every task, regardless of field quality.

MEASURED CONSEQUENCES:
  - Pool utilization 4.4-15.5% of DISTINCT candidates (task 83: 4 of 90; task 62: 6 of 91; task 56 best at 15/35).
  - 11 of 110 admitted rows (10%) are DUPLICATE URLs — the ranking does not dedup by url, so the same source lands twice inside K. Task 56 r1 admitted 8 rows covering 5 distinct urls (37% of that round's budget wasted).
  - `charter.evidence_window_max_chunks = 20` while admission delivers 4. Our own declared window is 3-5x larger than what acquisition feeds it.

THE SCORER BUG IS ALREADY FIXED — do not re-diagnose it. The logged t7a flight has `logged_score == 0.0` on 843/843 rows (the production web port recorded a constant 0.0; named at acquisition.rs:263-266). drb1-t1 fixed it; the replayed scorer zeros only 22/843, median 0.191, max 0.769. `.sovereign/features/drb1-t1/order.md` is still `status: open` but items 1-3 shipped (harness at research/deep-research/arms/replay/: admission-rows.csv 843 rows, admission-labels.csv, admission-summary.json, fetch-*.csv, run.sh).

LABELS ARE THE MISSING INPUT: admission-labels.csv has only 9 gold rows of 843. The tight-iteration loop the operator wants (pure function over recorded rows) exists and works; it has no ground truth to optimize against.

A SECOND, DISTINCT SYMPTOM on the CORPUS source path (live run dr-1787551476, today): every skip-ledger row scores 0.028 median / 0.030 max — two orders of magnitude below the web rows' 0.191 median in the replay. 100% skipped. Not the same bug as the 0.0 web bug; worth its own instrument pass before assuming it is the same fix.

AIQ CONTRAST (aiq-teardown.md §1.3, §3): the DRB-II ranking IS the InfoRecall ranking — Presentation is saturated (>90 for most entries), so the 22.95-60.35 InfoRecall spread decides placement. nvidia-aiq scores 49.23 InfoRecall, beating o3 (39.98), Gemini-3-Pro (39.09), Gemini-2.5-Pro (34.91) and Perplexity (33.05). Its recipe is per-sub-question CONCURRENT dispatch (max_research_concurrency 6), a budget of up to 20 research queries and 100 source-tool calls per job, and writer separation. The teardown's own words: "none of them is a scorer trick — they are structural breadth decisions." Each AIQ worker returns a structured `evidence_judgment` {0-100 usefulness, confidence, rationale} — a narrow, well-defined role, which is exactly the shape a small local model can fill.

OUR BUDGET vs THEIRS: ~6 admissions/round x 2-3 rounds = 12-18 sources, serial, 10% duplicated. Theirs: 20 queries, up to 100 source calls, 6-way concurrent. The gap is a config constant and a dispatch shape, not a model capability.</content>
