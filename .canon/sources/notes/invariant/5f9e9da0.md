# Recurring failure-mode triad for Phase 1b-style enrichment passes on new corpora — cap-bump rambling, schema-mask pathology, and…

Recurring failure-mode triad for Phase 1b-style enrichment passes on new corpora — cap-bump rambling, schema-mask pathology, and structured-output as the lone clean fix. Tuning rules and the sequence to apply them.

Every new corpus or enrichment-flow shake-out hits the same triad of LLM-output failures. Capturing the rules and the sequence so future-me stops re-deriving them.

Failure mode A: parse failures climb as the prompt enumerates more fields. Symptom: `entity_extraction: parse failed batch=N error=EOF while parsing a list at line M column 5` at 25-66% of batches. Root cause: model's natural JSON output overflows `max_tokens`; output truncates mid-array; parser sees unclosed list. Observed on enron-sample-multi-wide 2026-05-29 — the BusinessEmailDomain alias-emit prompt pushed mean output from 1341 → 2200+ tokens.

**Failure mode B: bumping `max_tokens` is a trap.** The model uses every token available. Bumping 2048 → 4096 dropped cutoffs from 66% to 60%; bumping to 8192 dropped to ~20% but added 100-200s of wasted decode on the un-cut batches. There is no `max_tokens` setting that makes a rambling LLM emit terse JSON; the model expands until it fills the budget.

Failure mode C: structured-output grammar is the only clean fix — but the grammar can pathologically lock the sampler. Wiring a full JSON Schema with `["string", "null"]` unions + `required` + `additionalProperties: false` per entity kind caused llguidance to spend 300s producing 5800 tokens of mostly-stalled output before the deadline aborted each batch (`pathological JSON-Schema mask state`, observed batches 80 and 81 of enron-sample-multi-wide). A maximally permissive schema — just `{type: object, properties: {key: {type: array, items: {type: object}}}}` — gets 95% of the parse-failure benefit (top-level array boundaries close cleanly) at near-zero mask cost. Field-level enforcement belongs in serde, not in the grammar.

Why: The whole problem chain — rambling, cutoffs, mask explosion — repeats every time a new domain prompt adds richer per-entity fields. The substrate is supposed to evolve without re-learning this each round.

How to apply: Standing sequence whenever a new corpus or domain prompt is shaken out:

1. Don't ship with `max_tokens` as the only output discipline. Even on a clean run today it will rot the moment the prompt grows.
2. The moment cutoff rate > ~5%, jump to structured-output grammar. Don't cap-bump past 4096 unless you've already gone to grammar.
3. When authoring the grammar schema, start lean — but match the downstream parser's *required* fields. The full schema variant (per-field type unions like `["string", "null"]`, `additionalProperties: false`, distinct shapes per kind) exploded the mask sampler at 300s/batch on enron-sample-multi-wide. The zero-constraint variant (just enforce top-level arrays of objects) swung past usable in the other direction — the model omitted serde-required fields (`missing field 'name'`) and 100% of batches failed parsing. The middle path that actually worked: enforce only the *required-on-the-Rust-side* fields per entity object (`{type: object, properties: {name: {type: string}}, required: ["name"]}`), leave everything else free-form, let serde's `Option<T>` + `#[serde(default)]` soak up the optional variants. One mandatory key per item is well under the mask threshold that exploded the rich schema. Don't add a constraint without grepping the Rust struct to confirm it's load-bearing.
4. If a batch hits the `inference deadline exceeded ... pathological JSON-Schema mask state` warning, the schema is too complex for the model. Strip back to the minimal shape; the deadline is the canary.
5. Carry the schema lever through `InferenceFn`'s optional second arg (added 2026-05-29). Each domain owns its own schema; phases that haven't authored one pass `None` and get the free-form path. The grammar pathway is per-call, not global.
