# Desktop document:progress events MUST all carry asset_id. The frontend listener (documentIngestion.svelte.ts) drops any event without one:…

Desktop document:progress events MUST all carry asset_id. The frontend listener (documentIngestion.svelte.ts) drops any event without one: `if (!p.asset_id) return`. But IngestProgress::Indexing{done,total} and BuildingSkeleton{done,total} do NOT embed asset_id (only Started/RagAvailable/MultiHopReady/Ready do). So every per-batch progress tick was silently dropped — the desktop banner never showed "Indexing N%"/"Building structure N%" and the ETA sat on "estimating…" the entire embed phase (no sub-progress signal), jumping only between milestones. Fix (2026-05-27): upload_document_asset injects asset_id into every emitted event at the Tauri emit boundary via serde_json (or_insert preserves ids the milestone variants already carry) — keeps the wire protocol clean for server/CLI consumers that do not use the listener. Do NOT rely on the IngestProgress variant to carry asset_id on the desktop path.
