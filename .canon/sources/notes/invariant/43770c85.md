NEXT-EDIT OUTCOME TELEMETRY — the four rules that hold regardless of how the journal layer is factored (restated because note 107d3c1a, which first carried them, was superseded by the abstraction split b146cf12).

1. NO `unknown` ON THE WIRE. `NextEditOutcome` has exactly four variants; an episode nobody resolved is the ABSENCE of an outcome line, counted at read time as `JournalStats::unknown`. A wire that could say "unknown" lets a client turn a never-ran into a verdict. The outcome route 400s an unrecognized string rather than defaulting it (ARCH §18.3) — one mis-spelling coerced to `dismissed` corrupts the only number this subsystem exists to produce.

2. `acceptance_rate()` IS OVER `accepted + dismissed` ONLY, and returns `None` — never 0% — when that is zero. `diverged` (the developer typed on) and `superseded` (a newer prediction replaced it) are not judgements and are never folded into dismissals. `diverged` DOMINATES in practice because `clearSurface("diverged")` fires on every manual edit past a live proposal; that is honest, not a bug. `svrn journal` also prints `reported_coverage` and labels anything under 20 judged an early signal.

3. THE DEBUG-VALUE ALLOWLIST IS NAMED AND CLOSED. `commonwealth-api::next_edit_journal::episode_from` reads exactly `reason`, `skipped`, `dropped`, `region_bytes`, `suppress_thinking`, `timings_ms.inference` from the model lane's `dbg` JSON. The code-bearing keys — `needle`, `verify_hunk`, `rule_find`, `rule_replace`, `region` — are simply not named, so a NEW debug field is invisible to the journal until someone adds it here. Backed structurally: `NextEditEpisode` has no `serde_json::Value` and no free-form string field, so there is no channel even if a caller tried. Canaries: `no_code_bearing_field_can_reach_a_line` (contracts), `debug_extraction_carries_no_code` (api), `no_bundle_field_can_carry_code` (cli, iterates the view registry).

4. ZERO USER-VISIBLE SURFACE (operator's hard requirement, note 09599af1). No command, keybinding, prompt, status-bar state, or error reaches the developer from telemetry. `reportOutcome` is fire-and-forget with a 2s deadline and swallows 404 (older daemon), 500, unreachable, and timeout; `record` on the daemon side drops its join handle so an append can neither delay nor fail a request. Four vitest cases hold it. `episode_id` is on the response body UNGATED (not under `debug`) because reporting must work on an ordinary production request; absent it, `reportOutcome` posts NOTHING rather than an id no journal could join.

WHERE THE FOUR OUTCOMES COME FROM: `nextEdit.ts`'s `clearSurface(outcome?)` takes the outcome so every teardown site must classify — manual edit / undo / Tab-on-moved-document → `diverged`; Esc → `dismissed`; first successful apply → `accepted` (once per queue, not per Tab); a new prediction replacing a live one → `superseded`; editor switch and dispose → UNREPORTED. The `Option` is the point: omitting it means "we genuinely do not know".
