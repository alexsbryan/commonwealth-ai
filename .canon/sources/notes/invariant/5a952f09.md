1. `corpus install my-coins.toml` answered "No registry entry for corpus 'my-coins.toml'". The ontology-v1 template headers tell an author to run `recipe validate <path>` and then `corpus install <path>` on consecutive lines. The first took a path; the second took an id and needed the file to already sit at `~/.svrnmesh/recipes/<id>/recipe.toml`. Nothing in the shipped chain put it there. Fixed in ce7b9a583 — install takes a path, registers it, prints where.

2. A relative `[acquire] path` was resolved against the DAEMON's working directory, not the recipe's. It failed 20s later inside the daemon as `Local source not found`, in a log the author never sees. Same commit: resolved at registration against the recipe's own directory, and refused THERE when it resolves to nothing.

3. `enrich build --full` died at step 1 of 9 with "5 failure(s), none of them retriable". All five were `Skipped` — phase 1's own 40-word floor declining short sections. The pipeline treated its own decision as a fatal build failure. Twenty lines below, the post-retry branch faced the identical predicate and CONTINUED. One predicate, two opposite verdicts, chosen by whether a retry happened to run (§10.6). Fixed in b540b5fd2 with `after_extract(retriable, extracted)` as the single decider; the one genuinely fatal case (nothing extracted at all) was not being tested for before.
