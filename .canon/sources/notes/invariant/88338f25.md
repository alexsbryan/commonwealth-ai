FLIPPING A DEFAULT-OFF ENV FLAG TO DEFAULT-ON: audit every place that derives "off" from UNSET, before you ship the one-line change.

2026-08-11, SOVEREIGN_NATIVE_GROUNDING went default-ON (directive 7aa64f29, commit d4647468). The flag reader is one line and one place. The HAZARD was nowhere near it: four separate instruments encoded the off-arm as "just don't set the variable", which the flip silently converted into a second ON-arm.

  sovereign/bench/calibration/ab/run_ab.sh:51           on => export =1, off => unset   -> A/B compares on vs on
  sovereign/bench/calibration/loop/run_full_conversion.sh:29   `unset ... SOVEREIGN_NATIVE_GROUNDING` as the "defaults" baseline
  sovereign/crates/sovereign-desktop/tests/e2e/scripts/p1-desktop-render.sh:62   films two on-arms, labels one "off"
  .../tests/e2e/real/native-grounding-p1.real.spec.ts:51   a FLAG_ON mirror whose comment claimed "same default-off as admission.rs"

Failure shape: the A/B still runs, still exits 0, still renders a scorecard, and reports a null delta — which reads as "the flag changed nothing, ship it." A green result from an experiment with one arm.

THE FIX PATTERN, both directions: state the flag EXPLICITLY on BOTH arms (=1 / =0). Never let either arm inherit the default, because the default is exactly the thing under test.

THE PREDICATE PATTERN: make the new predicate a MIRROR of the old, not an inversion. Old: on iff v in {1,true,on}. New: off iff v in {0,false,off}; everything else (unset, empty, unrecognised) follows the new default. That way every string that turned it off before still turns it off after, and only non-instructions change meaning. Also means a typo'd opt-out is not silently honoured (ARCH §18.3).

grep -rn for the flag name across .sh/.mjs/.ts/.py, not just .rs — the Rust reader is the one place that is easy to find and the least likely to be wrong. Also note: chaos.mjs contains non-UTF8 bytes, so `file` calls it "data" and PLAIN GREP SILENTLY RETURNS NOTHING on it. Use grep -a.
