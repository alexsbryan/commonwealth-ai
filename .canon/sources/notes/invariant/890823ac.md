# --loose-source-judge IS SILENTLY IGNORED UNDER --prod-pipeline. THE FLAG PARSES, THREADS, AND IS THEN DROPPED — NO ERROR, NO WARNING, EXIT…

`--loose-source-judge` IS SILENTLY IGNORED UNDER `--prod-pipeline`. THE FLAG PARSES, THREADS, AND IS THEN DROPPED — NO ERROR, NO WARNING, EXIT 0, WALL TIME UNCHANGED. Found 2026-08-02 while trying to decide whether a 3-source regression was material.

THE EVIDENCE. `svrn eval run --bank sovereign/bench/obsidian/questions.toml --prod-pipeline --loose-source-judge` produced output BYTE-IDENTICAL to the same command without the flag (only search-latency jitter differed): sources 8/12, facts 58/68, all twelve per-question rows the same. Zero judge output in 461 lines of log.

WHY THAT PROVES IT DIDN'T RUN, RATHER THAN RAN-AND-CREDITED-NOTHING. The text renderer DOES print the loose score when present — `eval_cmd/report.rs:232` and `:278` both gate on `if let Some(l) = r.loose_source_score.as_ref()`. A blank output therefore means the field was `None` for every question, not that the judge credited zero.

WHERE IT IS LOST. The live judge call is `eval_cmd/runner.rs:1771`, guarded by `if loose_source_judge && !q.expected_sources.is_empty()` — the guard is satisfied (every question in this bank has exactly one expected_source). But three sites hardcode `loose_source_score: None` (`runner.rs:1193`, `:1265`, `:1303`) and the `--prod-pipeline` path returns through one of them without reaching 1771. Same shape applies to `--essay-judge`, which is computed adjacently at "3c" in the same function.

WHY IT MATTERS BEYOND THIS ONE FLAG. `--prod-pipeline` is the BENCH-PROD PARITY mode — the one whose whole purpose is to measure the pipeline production actually runs. Judges that work in the default raw-index mode and silently no-op in parity mode mean the parity surface has strictly less instrumentation than the mode it replaced, and nothing says so.

CONSEQUENCE FOR THE MOTIF/GLiNER WORK (note 3f47d12e). The open question "is the gliner-off 3-source drop material or a rigid-string artifact?" CANNOT be answered with this flag today. Two routes: (a) fix the wiring so --prod-pipeline reaches 1771, or (b) use `--synth` + the instructor judge, which exercises synthesis and is the batch/larger-model run that question wanted anyway. Do NOT settle it by running --loose-source-judge in the DEFAULT retrieval mode — that is a different retrieval path, so its numbers are not comparable to the three configs measured on --prod-pipeline.

A FIX SHOULD FAIL LOUD, NOT JUST WIRE THROUGH: an opt-in LLM pass that produces no output and no score is indistinguishable from one that ran and found nothing.
