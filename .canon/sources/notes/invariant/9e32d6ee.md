THERE IS A THIRD NAMED-DISPATCH PATH, AND IT IS NEITHER GATED NOR OBSERVABLE. Found 2026-08-06 while running the MESH_N4 Phase-B instrument acceptance check.

So: the streaming path records routing decisions; the non-streaming path records NOTHING, ever.

BUDGET IS SPENT BUT NEVER READ. `build_request` (oicp-client/src/lib.rs:317,335,356) calls
`decremented_for_forward()` on every forward including this one, so the counter does go 1->0.
Nothing on this path ever READS `may_forward`, so a node receiving a budget-0 request
decrements a saturated zero and forwards again. The ping-pong M1 was written to close is
therefore still reachable via non-streaming named requests. NOT YET REPRODUCED end-to-end
(needs two nodes with mutually stale manifests) — this half is derived from the code, not
