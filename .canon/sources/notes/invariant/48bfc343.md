THE EMBASSY RELEASE PATH, TRACED AND CLOSED (order grounding-footguns, operator-directed addendum, 2026-09-05).

THE QUESTION: `absent-embassy-country` released "Mr Vladimir is employed by the Russian embassy in London" while the bench's own oracle scored `asserted_value_grounded: false`. Which exit released it — the decline chain, a rescue path, or the drafter's GK rider bypassing the veto?

THE ANSWER: NONE OF THOSE. The value-presence mechanism NEVER RAN. `verify_grounding`'s whole value branch sat behind `entity_anchored`, and `entity_anchored` is a GAZETTEER LOOKUP — `evidence_loop::anchoring::question_is_entity_anchored` asks whether the question's keywords hit `atlas_entity_names(corpus_id)`, the corpus's ENRICHMENT ATLAS. `chaos-secret-agent` declares `[enrichment] enabled = false` in its recipe ON PURPOSE (a RAPTOR summary had asserted "the Russian agent Vladimir" and broken the bank's "country never named" premise). So the corpus built to catch this failure is the one corpus on which the countermeasure is structurally off. `anchoring.rs`'s own comment already names the shape for catalog corpora: "catalog corpora carry NO atlas, so that check returns false and the exemption stays open."

EVIDENCE, from the instrument rather than from reading: `entity_anchored = false` on ALL 141 rows of `~/.svrnmesh/journal/grounding-2026-09-05.jsonl` for that session, chaos turns included. The embassy turn's journal row: `action=released, verdict=supported, violation_prob=0.2897, claim_audited=true` — the CONFIRMATORY per-chunk loop cleared it at max_support 0.71, doing exactly what judge.rs:256's comment says it does ("a small forced-choice judge has a yes-bias: it grounds … a partly-true claim ('the Russian embassy')"). The turn's own retrieved window contained no "russian" at all.

THE FIX (ce6768224): the VETO is unconditional; only the POSITIVE SHORT-CIRCUIT keeps the flag. Refusing needs no gazetteer — "the answer asserts a specific that appears nowhere in the evidence" is corpus-agnostic and costs one 24-token extraction plus a substring test — so it runs on every gated turn. `Present` off the flag means only "not refused", the confirmatory loop runs exactly as before, and NO probe call is made because its verdict would be discarded. Pinned by `an_absent_specific_is_refused_on_a_corpus_with_no_gazetteer`, which drives a real `gate_answer` over a fixture with `entity_anchored: false` and a judge told to support EVERYTHING.

MEASURED, before/after, same probe, same corpus (daemon restarted 07:14:47Z on the after arm, running binary verified by lsof):
  before  gate=released           "Mr Vladimir is employed by the Russian embassy in London."
  after   gate=abstained          "I couldn't confirm an answer to this against the 12 passages your sources turned up…"

THE COST, MEASURED IN THE SAME RUN AND NOT EXPLAINED AWAY: `present-killer-weapon` went `released` -> `abstained` too. The answer ("carving knife") is CORRECT and scores the bank's gold keywords, and the value is absent from the retrieved passages in BOTH arms — retrieval did not return the stabbing scene, and the model answered from parametric memory. Before, the gate had no mechanism that could notice; now the veto refuses. Whether that is a win or a loss is a product call, not a bench call: the gate's contract is "answer from the sealed evidence or abstain", so the abstention is CORRECT by the gate's own rule and reads as TIMIDITY on the bank's competence axis, which scores against gold keywords rather than against the evidence. Anyone re-measuring competence on chaos after 2026-09-05 is measuring a stricter gate, not a worse model.

SECOND FINDING, same trace: `located == 0` on 8 of 8 `citation_grounded` turns is NOT a defect. `located` counts quotes carrying a SECTION HEADING, joined out of the corpus's `governance_view` enrichment (`grounding::gate_evidence_locators`); the chat-ask fixture and the chaos corpus are both ingested with no enrichment, so it is structurally 0 there. `openable` is the field that says a quote can be opened, and it was 2/2 and 1/1 with every quote carrying a `(corpus_id, chunk_id)` target. The chat-ask lane's old `gate outcome` row failed on `located == 0` and was reading the wrong field; the `gate outcome honest` row asks `openable`.
