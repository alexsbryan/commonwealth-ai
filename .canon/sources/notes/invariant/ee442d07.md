WORK-ATLAS COORDINATION IS ONLY CORRECT AGAINST THE DAEMON STORE — CLI SURFACES MUST PROXY, NOT OPEN THEIR OWN (root-caused + fixed 2026-07-31).

The split-brain that made declare_scope ack success while no reader could see the claim had THREE stacked causes. (1) STORE SPLIT: the daemon work-atlas rides an IN-MEMORY MeshStore (bootstrap.rs ~2178, deliberately — it is also AppState mesh_store), while CLI paths opened repo-local .sovereign/mesh.db; two stores, zero overlap, so CLI claims were invisible to MCP/gossip/peers and daemon observations invisible to CLI. (2) IDENTITY SPLIT: daemon resolves node id from the ROOT data dir (~/.svrnmesh/node_id = b882…), but tools_cmd/registry.rs and claim_cmd derived it from <root>/indexes, minting a SECOND id (c034…, still on disk at ~/.svrnmesh/indexes/node_id — leave it, other consumers may hold it). (3) TOKEN CONVENTION SPLIT: claim list --mine matched only sessions tokened cli:<node>, but tools-path sessions carry token None — your own claims were never "mine".

FIX SHAPE: declare_scope/release_scope/work_in_flight and all svrn claim subcommands go DAEMON-FIRST via sovereign_cli_shared::mcp_client (feature mcp-client); local repo store is a loud daemon-down fallback only; a daemon REJECTION never falls back (that would fake success into a store nobody reads). work_in_flight gained include_self (default false) because the self-exclusion made "list my own claims" inexpressible. Node identity: use sovereign_mesh::persist::resolve_self_node_id(root) everywhere — never load_or_generate against a subdirectory. --mine is node-scoped now.

REMAINING KNOWN LIMIT: daemon restart drops all claims and observations (in-memory store). Spec-tolerable (claims are ephemeral live-state) but surprising; if it bites, the fix is a dedicated persistent work-atlas store, NOT file-backing the shared mesh store (that store also carries gossip/mesh runtime state).
