# Daemon-first MCP calls (declare_scope, release_scope, work_in_flight, resource_may_i via tools_cmd and claim_cmd) resolve their target…

Daemon-first MCP calls (declare_scope, release_scope, work_in_flight, resource_may_i via tools_cmd and claim_cmd) resolve their target through ONE accessor: sovereign_cli_shared::urls::daemon_base_url() — SOVEREIGN_DAEMON_URL, fallback SVRNMESH_DAEMON_URL (canonicalizes to the declared SOVEREIGN_DAEMON_URL in quality/env-flags.toml), default http://localhost:9741. The sandbox lane (cli-journey-sandbox.sh) points it at its isolated daemon; do not reintroduce a hardcoded port in the client. Root cause fixed 2026-08-11: mcp_client::daemon_tool_call hardcoded :9741, so in the sandbox netns the coordination tools silently fell back to the repo-local store — the work-coordination journey had been proving only the fallback path.
