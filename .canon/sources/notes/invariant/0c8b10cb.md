=== WHAT MOVED ===
`ServerEvent` (was sovereign-server/src/approval.rs:29) was ONE enum on TWO transports. It is now two types in two crates:
- `sovereign_contracts::types::TurnFrame` — Token / Complete / StreamError / Narration / QueuePosition. Per-turn, down the ONE socket that asked.
- `sovereign_contracts::types::TurnRequest` — the inbound half (was the private `ClientEvent` in ws.rs). Message / Approve / UserReply, kept as ONE enum on purpose: inbound has one connection and one reader, so there is no invariant to split on. Split where a state must become unrepresentable, not for symmetry.
- `sovereign-server/src/approval.rs::ExecutorEvent` — StepDone / ApprovalReq / UserInput. Genuinely fan-out; stays in the host that owns an executor (Decision 1: shell/approvals are scoped OUT of the daemon profile).
`projection.rs` moved WITH them to `sovereign_contracts::types::projection` (git mv, history preserved), so REST and WS project a message's metadata through one library function a daemon can also call.

=== THE STATE MADE UNREPRESENTABLE ===
One tenant's tokens on the fan-out broadcast — an answer delivered to every OTHER connected client. Before, `event_tx.send(ServerEvent::Token { .. })` COMPILED; the only guard was a doc comment on the enum. Demonstrated once as `expected ExecutorEvent, found TurnFrame`, then reverted (§10's demonstrate-then-delete rule). ARCH §7: structural, not remembered.

=== HOME IS CONTRACTS, PER NOTE d91de4b1 ===
Decision 4 of TOPOLOGY §10 already settled it. NOT a new crate: contracts already owned every payload type but StepSummary (ActionPreview in types/ui, EpistemicState in types/epistemic, NarrationPhase in types/narration). Principle 11 — the inventory outranks the plan.

=== FIVE THINGS NOT TO UNDO ===
1. `projection` is `pub mod`, NOT re-exported into `types::*`. It owns a `Provenance` that is NOT `epistemic::Provenance`; two types of one name at one path is the §10.6 smell. Callers write `projection::Provenance`, which says which one they mean.
2. Both halves gained `Deserialize` (+ `#[serde(default)]` on every skip_serializing_if field). A frame only one side can parse is not a protocol — that was the actual defect, and it is what lets 5c's surface read frames from a daemon.
3. `TurnFrame::Narration.phase` is `NarrationPhase`, not `serde_json::Value`. The server carried the Value because it could name NarrationPhase but this enum was not a type it shared with anyone. Wire-identical — same derive, same bytes; pinned by the falsifier.
4. Falsifier `sovereign-contracts/tests/turn_wire_form.rs` pins each variant's LITERAL JSON, not a json! round-trip (value-to-value passes when both sides move together). rustc is exhaustive over types and blind to encoding. SABOTAGE-VERIFIED: `#[serde(rename = "messageId")]` on Token.message_id -> FAILED naming both byte strings.
5. ws.rs serialises INSIDE each select arm now, because the two channels no longer share a type. Do not "simplify" it back to one `serde_json::to_string` after the select — that requires one type on both channels, which is the defect.
