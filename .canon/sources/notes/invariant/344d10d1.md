A MOVED BLOCK LEAVES ITS IMPORTS BEHIND, AND IT COST A GATE ROUND EACH TIME. Three independent instances on 2026-09-01 during the ontology-v1 wave, in three different crates, by three different agents:

- `corpus-engine/src/enrichment/pipeline/atlas_extensions.rs` — `RelationSketch` (extension structs moved out of `atlas.rs`).
- `corpus-engine/src/enrichment/pipeline/pipelines/parse_policy.rs` — `ParsePolicy` re-imported with a PRIVATE `use` in `ontology_parse.rs`, so re-exporting it did not reach two call sites (E0603, not E0433 — the same hazard one step further along).
- `sovereign-tools/src/typed_extension/harvest.rs` — `AtomId`, `EnrichmentDepth` (left in `typed_extension/mod.rs` when `build_person_seed_entities` moved).

Under the shared build lock each instance costs minutes, because the compiler is the only thing that catches it and a gate round is serialized behind other workers.

CHEAP PRE-COMPILE CHECK, and the two things that make it work:
1. Collect names used as a path root in the moved block that are neither defined nor imported within it.
2. Run it as a DIFFERENTIAL — before the move vs after — and report only newly-appearing names. A crude scanner has systematic false positives (enum variants, associated types like `Output`, generic params); they appear on both sides and cancel. Measured on `bootstrap.rs`: raw mode 12 names, all noise; diff mode 0.

VALIDATE THE SCANNER BEFORE TRUSTING IT (§18.4). A first draft that stripped comments before strings let one unbalanced quote make the string regex swallow code across line boundaries: `atlas_dispatch.rs` collapsed 275 lines → 84, which HID a `pub enum EnrichRoute` definition and then FABRICATED `EnrichRoute` and `Atlas` as missing names. A tool that invents findings and hides definitions is worse than no tool. It was caught by instrumenting the stripping stage, not by reasoning about the false positives. The rewrite needs real lexing: nested block comments, raw strings with hash counts, char-literal vs lifetime disambiguation. Validated by stashing the known fix, re-running against the actual broken tree, and confirming it reported EXACTLY `AtomId, EnrichmentDepth`.

Deliberate: the compiler is the authority, this only buys back gate rounds (a workflow cost of the three-worktree/one-lock topology, not a product one), and a lexical Rust scanner that has already fabricated findings once must not be shared without its own tests. If the pattern outlives this program, land it in `scripts/` WITH the collapsed-`atlas_dispatch.rs` case as a regression fixture.
