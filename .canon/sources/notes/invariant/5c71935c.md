# The inner-chaos harness must seed the conversation with the inner-work surface tag before turn 1, or it is not testing the witness path at…

**The inner-chaos harness must seed the conversation with the `inner-work` surface tag before turn 1, or it is not testing the witness path at all.** (Found 2026-07-26 by instrumented probe; fixed in `inner_chaos/runner.rs::run_thread`.)

`inner-work` is `activation_kind = "workspace"`. Since the 2026-07-15 regression fix, workspace ownership is a CREATE-TIME surface declaration, never a dispatch-time inference: `SkillRegistry::background_skill_id_for_conversation` explicitly filters out workspace skills, so `handle_message`'s auto-tag stanza (turn.rs:43) can never tag a conversation `inner-work`.

Chain when the tag is missing: conversation row keeps `skill_id = NULL` → `resolve_active_mode` returns `None` (it reads `conv.skill_id` and requires `ActivationKind::Workspace`) → `policy_for(intent, register, active_mode=None)` gets `declared_register = SkillRegister::default()` (Factual) → `apply_witness_intent_override` returns on its first line → the relational register is never pinned. Turns reach the witness handler only when the router happens to classify EXPRESSIVE on its own.

Measured on a `reflective_control` thread before the fix: turns 1–2 classified EXPRESSIVE (witness, ~8s), turns 3–4 classified REASONING → dispatched `DeepQuery` (~40s, 900-word coaching essays with markdown headers and numbered action plans) with `active_mode=None` on all four. After seeding the tag: `active_mode=Some("inner-work")` on all four, `intent_policy: forcing ExpressiveQuery … original_intent=DeepQuery` fires on turn 2, all four turns on the witness path at uniform ~6–10s.

Production is NOT affected — the desktop's `create_conversation` command persists `surface_skill_id = Some("inner-work")` at create time (`sovereign-desktop/src-tauri/src/commands/conversation.rs:43`). This was harness-only.

Consequence for the record: every inner-chaos number produced before 2026-07-26 — the 83.3% baseline, the 95.8%/97.2% validation run, the per-persona convergence in CHAOS_HARNESS.md §6 — was measured with the register unpinned. The 2026-07-08 fix loop's headline conclusion ("closing the register to ONE witness path cleared clinical_overreach + privacy_leak + retrieval_leak") was verified through `apply_witness_intent_override`, which those runs never executed; the classes likely cleared because the *classifier* stopped sending those personas to DeepQuery, not because the override caught them. Re-baseline before citing those numbers.

This is the THIRD harness-validity bug of the same shape in this harness, after (a) brain+judge silently running on the 4B fast slot instead of the 35B and (b) the `turn_register()` pre-routing guard that left embed recall dead on every e2e witness run. The pattern: a harness that reaches the right code path *by luck of classification* rather than *by construction*. When adding a surface to this harness, assert the path — don't assume it.
