THE PHASE-1 GRAMMAR IS ENFORCED, AND A FALSE COMMENT SAYING OTHERWISE COST A DAY OF PROMPT ARCHAEOLOGY. Verified 2026-09-02 by direct probe, not by reading code.

`ontology_schema.rs:39` says "the grammar-constrained sampler is a known no-op", and `parse_policy.rs` carries a hand-written recovery for `"1.29 g"` where the schema says `number`, justified by it. Both rest on a false premise.

THE PROBE that settles it — one curl at the live daemon, system prompt "Reply with the coin name only", `response_format: {type: json_schema, strict: true}` requiring name+weight+metal:

    { "name": ..., "weight": 1.21, "metal": "silver" }

`weight` came back a NUMBER, the enum was honoured, and all three required fields appeared DESPITE the prompt asking for one. Constraint beats prompt. `wire.rs:133` does attach the schema (`prompt.response_schema` → `response_format`, mode `JsonSchema` by default for OpenAI-compat); it is not dropped.

WHY THIS MATTERS: `phase1_schema_for` sets `required` to `["content","claim_kind"]` on a claim sketch and NOTHING on the entity sketch's `attributes`. `attach_attributes` uses `set_property`, never `set_required`. So `attributes` and `subject` are OPTIONAL properties, and a strict grammar happily omits an optional object. Every measurement this session — declared attributes 0/14, grade 28 -> 2 when `subject` arrived, four prompt variants all landing near zero — is the behaviour of fields nothing OBLIGES the model to produce. It was never an attention budget; the "capacity trade-off" reading was wrong.

THE FIX, and it is small: put the `attributes` OBJECT in `required` while leaving its own properties optional. The model must emit the object and may emit `{}` when the text supports nothing — no fabrication pressure, because the keys inside stay optional. §7.6 exactly: never ask a model to guarantee what code can enforce.

CAUTION on `subject`: requiring it is NOT symmetric. An attribution genuinely about no coin would be forced to name one, which is fabrication. Require the attributes object first; leave `subject` a prompt request (already 46/48) or make it nullable in the schema so "no subject" stays expressible.

METHOD LESSON, twice over in one hour: I concluded "nothing reads `response_schema`" from a `grep | head -12` whose first twelve hits were tests — absence inferred from a truncated list. And I took the no-op comment as fact. §11 says cite, don't recall; a 30-second probe against the running daemon beat two rounds of code reading.
