ROOT CAUSE, TWO INDEPENDENT DEFECTS:
1. `gate_local` (rpc_distribution.rs:1263) is the ONLY caller of `local_fit_reserve_bytes` (:1222), whose doc comment literally reads "the desktop compositor's GPU allocations (the 2026-07-27 casualty)". It is reached from exactly two sites, :1463 and :1485, BOTH `PlacementDecision::LocalOnly`. The distributed split path never consults it — the host's share of a split is apportioned with NO reserve for the OS or compositor. A guard written for this failure does not cover the door the failure came through.
2. `spawn_gate_verdict` (discovery_policy.rs:188-211) asks exactly one question: is any pinned worker still reachable? BeefyMac was reachable, so the verdict was Allow and the supervisor re-armed a 100+ GB load unattended. The gate has no memory question at all. There is no "did the last child die 7 s ago" question either — `SpawnGate` (supervisor.rs:211-229) is the right seam for both and is already plumbed.

THE FIX SEAM IS THE SPAWN GATE, NOT THE SUPERVISOR. `SpawnVerdict::Hold` parks the run loop WITHOUT burning crash-loop budget (supervisor.rs:213-215) — exactly the semantics wanted for "wait for the machine to have headroom".
