# A metric built from FAILURE receipts is structurally blind to the SUCCESS it is supposed to measure. scripts/inner-work-witness-atlas.py…

**A metric built from FAILURE receipts is structurally blind to the SUCCESS it is supposed to measure. `scripts/inner-work-witness-atlas.py` scored the witness's curious-read rate at 0.0% while the journal was full of curious reads.** (Found 2026-07-26, iteration-2 inner-work tuning; fixed in the same commit.)

What happened. Iteration 2 of `RELATIONAL_EXPRESSIVE_SYSTEM_PROMPT` teaches the witness to voice a psychological read as a QUESTION instead of a verdict ("stay curious at the edge and ASK it"; "Is it that…?" never "You're doing this because…"). To measure it deterministically — the Tier-1 judge being untrustworthy per note 0ac4b6da — I harvested `INTERPRETIVE_PATTERNS` from the iteration-1 receipts the judge had flagged `diagnosis_lite`, then scored that one pattern set twice: matches in declarative sentences = `verdict_rate`, matches in question sentences = `curious_read_rate`.

The declarative/interrogative split was right. The pattern SOURCE was not. Every pattern came from replies that ASSERTED, so the set is made of declarative interpretive verbs — `suggests`, `you're treating`, `I'm inferring`, `reveals`, `a deep \w+ need`. A well-formed curious read uses NONE of them:

  "Is it that moving forward would mean abandoning the safety of this specific error?"
  "Is the shield up because he's protecting himself from seeing your worth, or are you stepping out of that role to protect yourself from needing him?"

So `curious_read_rate` could only ever catch the clumsy hybrid ("I'm inferring … is it X?"). First iteration-2 run: 0.0%, against a journal where the taught form fires constantly. I nearly reported "the curiosity direction did not take — the witness just went quiet about the why," which would have been exactly backwards and would have driven iteration 3 to re-loosen a brake that was working.

Numbers before → after the instrument fix (identical journals, same paired legs — the deltas are pure instrument):

| metric | legB iter-0 | legB2 iter-1 | legB3 iter-2 |
|---|---|---|---|
| verdict asserted (unchanged by fix) | 4.1% | 20.2% | 11.5% |
| read ASKED — BEFORE fix | 1.2% | 1.2% | 0.0% |
| read ASKED — AFTER fix | 10.5% | 4.9% | 24.8% |

The real iteration-2 result: reads voiced went UP (25.2% → 36.4%) while the share ASSERTED rather than asked fell 80% → 32%.

The fix. A second, separate pattern set (`CURIOUS_READ_PATTERNS`) keyed on the FORM the prompt teaches rather than on the failure it replaces — `^is it\b`, `\bis it that\b`, `\bor is it\b`, `^is the \w+`, `(is|are) (it|that|the \w+) …because`, `what would (that|it) (feel|be|mean) like`. Applied to question sentences only, so it can never inflate the verdict count.

The generalisable rule — apply to ANY prompt-tuning instrument. When you build a detector to measure a behaviour change, you need patterns for BOTH poles, harvested from BOTH sources: the failure receipts you already have, AND the target form as the prompt literally words it. A pattern set mined only from what went wrong will report the fix as a null result. Sanity check before trusting any such metric: grep the journal by hand for the exact phrasing the prompt teaches, and confirm the detector's count is in the same ballpark. Here the prompt's own literal example string — "Is it that…?" — was sitting in the source the whole time and would have caught this in one grep.

Second-order caution recorded honestly: the fix was authored AFTER seeing a disappointing number, which is the classic shape of motivated measurement. Mitigations that make it defensible: (a) the new patterns are derived from the prompt text, which was written and committed BEFORE the run; (b) the corrected instrument was re-run over ALL legs including both pre-tune baselines, so the comparison stays paired and the baselines moved too (1.2%→10.5% on iter-0); (c) receipts are attached per turn. Anyone re-reading these numbers should apply the same test.
