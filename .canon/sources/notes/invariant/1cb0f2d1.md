Watched folders share ONE LocalCorpusManager with one-shot folders (appear in both lcList + lcWatchList); source_type is an externally-tagged union so watched≠DocumentFolder mislabels as vault; removal MUST go through lcWatchRemove (deregisters scheduler), not lcRemove

Desktop Local Knowledge surface facts (learned fixing a 2026-07-15 user bug: watched
folders all showed as "Obsidian vault" + a stuck errored folder gave a giant overflowing
error with no way to delete it).

One manager, two lists. `WatchedSubsystem::install(..., lc_mgr, ...)` is passed
`state.local_corpus`, so `watched_folder_runtime::manager()` === the LocalCorpusManager that
`require_manager` (lcList/lcRemove) uses. Therefore a watched folder appears in BOTH
`lcList()` (manager.list → "Folders"/LocalKnowledgeList) AND `lcWatchList()`
(manager.list_watched → "Watched folders"/WatchedFolderList). The Folders list must FILTER
OUT watched sources (they own a dedicated section) — `LocalKnowledgeSection` now derives
`folderCorpora = corpora.filter(c => !isWatchedSource(c))`.

source_type is an externally-tagged serde union. `LocalCorpusSourceType` →
`"DocumentFolder"` (bare string) | `{ObsidianVault:{...}}` | `{WatchedFolder:{...}}`. The old
`source_type !== "DocumentFolder" ? "Obsidian vault"` mislabeled EVERY watched folder as a
vault AND lit the vault-only "Organize" button. Discriminate by checking the object key, not
`!== "DocumentFolder"`.

Removal: use the right door. `lcRemove` (LocalKnowledgeList) → `manager.remove` wipes
index+config but does NOT `registry.deregister` the sweep scheduler. The correct watched-folder
removal is `lcWatchRemove` → `DELETE /internal/corpus/watch/{id}` → `remove_handler`
(`registry.deregister` THEN `manager.remove`). `remove_corpus_everything` is idempotent pure
`remove_dir_all` so it tolerates a missing `_corpus_meta.json`. WatchedFolderList already uses
lcWatchRemove; the errored-folder banner (WatchedFolderBanner) now also offers Remove (was
Retry-only, futile when initial ingest never finished — the sweep worker guard at
`sovereign-tools/local_corpus/watched/worker.rs:458` sets Errored on missing meta forever).

Immediate unblock without rebuild: `curl -X DELETE http://127.0.0.1:9741/internal/corpus/watch/<corpus_id>`
(internal routes are localhost-gated, no token).

Fix verified: desktop npm run check 0/0, vitest 311 pass (+7: LocalKnowledgeList label 3,
WatchedFolderBanner 4). Frontend-only. See [[feedback_treat_bugs_as_product_ux]],
[[feedback_desktop_check_and_vitest_gate]].
