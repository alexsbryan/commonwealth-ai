# Why installed_indexes() dedupes by corpus_id and prefers the canonical-named dir; reproduced 2026-05-03 by Garth Brooks misroute

Why installed_indexes() dedupes by corpus_id and prefers the canonical-named dir; reproduced 2026-05-03 by Garth Brooks misroute

`(corpus_id, chunk_id)` is the system's citation handle. `chunk_id` is a
LanceDB row id scoped per physical index. Retrieval (`search_corpus_indexes`
in `sovereign-core::runtime`) emits this pair on every `ScoredChunk`, and
the reading-surface HTTP layer (`/internal/corpus/{c}/chunks/{id}` in
`sovereign-mesh/reading_http.rs`) dereferences it via
`engine.open_index_for_corpus(corpus_id)`, which always opens
`<index_dir>/<corpus_id>`. The pair is therefore only stable when at
most one on-disk directory advertises a given `corpus_id`.

Why: Reproduced live on 2026-05-03 — a SEP-objectivism question
surfaced a chunk tagged `(corpus_id="wikipedia", chunk_id=454732)`
sourced from a stranded `wikipedia-partition-node-*` shard. Clicking the
citation opened `~/.sovereign/indexes/wikipedia/` (the canonical) and
displayed a Garth Brooks chunk that happened to live at row 454732 in
*that* index.

How to apply:
- `installed_indexes()` in `corpus-engine/src/engine/mod.rs` enforces the
  invariant at runtime via `dedupe_by_corpus_id()`. Don't remove it
  unless `ScoredChunk` is also changed to carry a per-physical-index
  instance id end-to-end (~30 callers — explicit decision to defer in
  the linked decision note).
- `corpora_with_colliding_indexes()` is the doctor surface (mirror of
  `corpora_with_stranded_partitions()`).
- Operator escape hatch: rename a stale physical index to `<name>.retired`
  (any `.` in the name) and `is_out_of_band_index_name` filters it.
- Tests pinning this:
  `engine::tests::installed_indexes_dedupes_corpus_id_collisions_preferring_canonical`,
  `engine::tests::corpora_with_colliding_indexes_finds_canonical_plus_lingering_partitions`.
