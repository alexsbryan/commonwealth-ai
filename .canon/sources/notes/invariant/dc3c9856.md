DO NOT WIRE `run_baseline_benchmark` BY ADDING A CALL SITE — it is dead code whose obvious revival is a measured quality regression (2026-07-27, SCHEDULER_QUALITY.md §4.5 / F10).

It LOOKS like a pure win: the probe exists and works, `capabilities.rs` has a `benchmark: None` waiting for it, two doc comments used to claim the wiring already existed, and the Tier-1 arm says an honest rate card is worth −32% mean latency on `mixed-hubs` with 0% cost on five other fleets.

THE TRAP: this probe measures the `Speed::Fast` slot. It stamps a ~4B / ~2.5 GB model into `baseline_model_id` / `baseline_size_gb`, and `throughput_factor` then extrapolates from that to whatever model is actually being scored by scaling LINEARLY on the size ratio (`oicp-types/src/scoring.rs:384`). Decode is bandwidth-bound, so real scaling is sub-linear and the linear law under-states every large model. The term clamps to `[FLOOR, 1.0]`, so that error is ONE-SIDED — it can only push big candidates down.

MEASURED (SimConfig::probe_baseline_size_gb / probe_sublinearity, rate ∝ size^-β; β=1 is the code's own assumption and is an exact identity):
  β=1.0 → −32% latency, 0 downgrades, 31.2 declined upgrades
  β=0.7 → −56% latency, 0 downgrades, 67.0 declined upgrades
  β=0.5 → −57% latency, 3.0 downgrades, 67.0 declined upgrades
The extra latency is BOUGHT WITH CAPABILITY, not earned. Latency alone reads this as a doubling of the win.

THE CORRECT FIX: benchmark the model being SCORED, so the size-ratio extrapolation stays inert (ratio 1.0 — which is the only regime the Tier-1 numbers cover; asserted in `mesh_sim_scoreboard::what_the_scorer_loses_by_never_measuring_anyone`). Eliminate the extrapolation; do NOT tune β, and do not add a tolerance constant.

RELATED, same session: this also blocks §4.1's predicted-time objective. `PredictInputs::from_candidate` reads the advertised benchmark and nothing else, so with `benchmark: None` everywhere `predict` returns `Err(Unpredictable::NoThroughput)` for every candidate. Unhardcoding `RankObjective::Product` at `peer_inference.rs:1288` without a rate card exposes a policy that cannot rank.
