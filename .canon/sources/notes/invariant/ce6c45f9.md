# A NARROW --filter / --package ON scripts/sovereign-test.sh CAN PRODUCE A BUILD FAILURE THAT LOOKS LIKE AN UNATTRIBUTABLE-RESULTS EXIT 5,…

A NARROW `--filter` / `--package` ON scripts/sovereign-test.sh CAN PRODUCE A BUILD FAILURE THAT LOOKS LIKE AN UNATTRIBUTABLE-RESULTS EXIT 5, AND ITS BANNER BLAMES THE WRONG THING (measured 2026-09-01, ontology-v1 program).

Repro: `./scripts/sovereign-test.sh --human --filter forward_every_manifest_command_is_documented`.
The filter's git-grep resolved the build scope to `-p sovereign-cli` alone; the script then passed its whole feature contract anyway, and cargo refused:

  error: the package 'sovereign-cli' does not contain these features: sovereign-mesh/dst, sovereign-mesh/mesh-sim
  error: command `cargo test --no-run ... --package sovereign-cli --features corpus-engine/treesitter,sovereign-cli/dev-tools,sovereign-cli/code-intel,sovereign-cli/awareness,sovereign-mesh/mesh-sim,sovereign-mesh/dst` exited with code 101

Cargo cannot apply `<pkg>/<feature>` for a package outside the selected set, so ANY scoped run whose resolved package set excludes `sovereign-mesh` (or `corpus-engine`) hits this. The run then exits 5 and prints the "unattributable results / concurrent nextest overwrote the shared junit.xml" banner with two `absent:` paths — which sends triage at a phantom concurrency problem. The junit file is absent because the BUILD never produced a test binary, not because anything raced.

Read it as ARCH §18.2 NEVER-RAN, never as a pass, and never as the junit race the banner names. Check the log for `does not contain these features` before believing the banner.

Workaround until fixed: run the full workspace, or scope with `--package` to a set that owns the contract's features (`--package corpus-engine` works — it owns `treesitter`). `--engine cargo` does NOT help; the failure is cargo feature resolution, upstream of the junit path.

Real fix: the script should intersect its feature contract with the resolved package set before passing `--features`, and a build failure in the scoped path should report as a build failure (the 2026-07-28 rule) rather than falling through to the exit-5 attribution banner.
