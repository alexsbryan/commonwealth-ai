TWO SILENT-SUBSTITUTION BUGS IN THE SCORING PATH, both found scoring M3's rung 1, both fixed and verified (errors 3 -> 0 on the same 550 items). Measured 2026-08-05.

BUG A — `-c` IS THE TOTAL KV POOL, NOT THE PER-REQUEST LIMIT. llama-server divides n_ctx by --parallel, so `-c 32768 --parallel 4` gave each request 8192. The failure is a per-item HTTP 400 that the eval records as an error and DROPS, so the card comes back SHORT rather than wrong — harder to notice than a bad number. The earlier verdict "raised CTX to 32768, errors 0" (frame 5662460c) was WRONG: it was verified on an 88-item slice containing no long documents, and the per-slot division was never what got fixed.
  MEASURED on the full 29,320-row LLM-AggreFact bank (doc+claim, chars/3.5):
    p50 ~600 tok · p99 ~5,062 · max ~34,408
    over  8,192 tok: 136 rows (0.46%)  -> predicts exactly the 3/550 seen at rung 1
    over 32,768 tok:   4 rows (0.014%) -> the named residual
  FIX: CTX now means PER-SLOT and the pool is derived (`-c $((CTX*CONCURRENCY))`), printed as "ctx 32768/slot x 4 slots = 131072 total KV". COSTS NOTHING: llama-server RSS 8.9 GB at a 131,072 pool vs 9.3 GB at 32,768 — Qwen3.5-4B is a hybrid, so most layers carry constant SSM state instead of growing KV.

BUG B — `toolbox run` DOES NOT INHERIT THE CALLER'S ENVIRONMENT. Measured both ways:
    FOO=bar toolbox run -c sovereign-vulkan bash -c 'echo $FOO'      -> empty
    toolbox run -c sovereign-vulkan env FOO=bar bash -c 'echo $FOO'  -> bar
  So the form CLAUDE.md documents (`VAR=x toolbox run -c sovereign-vulkan ./scripts/…`) silently drops EVERY env knob and runs the defaults. score_checkpoint.sh's entire interface is env vars (PER_SUBSET/BASE/CTX/THRESHOLD/PORT), so `PER_SUBSET=50 toolbox run …` ran the 200/subset full card — 6 hours where 90 minutes was asked for. ALWAYS: `toolbox run -c sovereign-vulkan env VAR=… ./scripts/…`.
  THE BANNER IS WHAT CAUGHT IT. score_checkpoint.sh prints every resolved value, so the header said `per-subset 200` when 50 was asked for. This is the §18.3 case in both directions — a silent substitution producing a plausible, well-formed, wrong result — and printing the resolved config is the only reason either bug was visible.
