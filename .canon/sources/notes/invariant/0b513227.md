SCIP graph carries STRUCT FIELDS keyed by owning type — use it, never grep, to count fields.

`DescriptorKind::Field` rows are `…path/Type#field.`, so the owning type's qualified name is the prefix through the LAST `#`, which equals `converge::TypeDef.qualified` exactly. That lets a field census join to a type census with no second parse. `roles::type_fields` is the one implementation (2026-08-20).

WHY THIS IS AN INVARIANT AND NOT A TIP: a `grep -E '^\s*(pub )?name:'` over `.rs` files does NOT count field declarations. It counts struct-literal INITIALIZERS, JSON keys and comments too, and in this repo it over-counts by 6.6x. Measured 2026-08-20 on the freshness family: bare substring grep 175, decl-or-init grep 76, actual field declarations in first-party production code 26. `NOUN_CONVERGENCE.md` §10.1 shipped "172 hand-written freshness fields in 13 spellings" on the substring number; four of those thirteen spellings (`age_days`, `freshness`, `lags_graph`, `commits_behind`) name no field anywhere in the workspace.

Validation that settles which instrument is right, cheaply: pick one struct, compare its declared fields to `select qualified_name from symbols where qualified_name like '%/Type#%'`. Did this on `RegistrySnapshot` — 4 declared, 4 rows, exact.

SECOND TRAP, same section: §10.2's "8,882 first-party production types" counted ENUM VARIANTS as types. Types + variants = 8,764; top-level type definitions (what `converge::type_defs`, `converge census` and `converge roles` all use) = 5,139. If a type count is near 8.8k it is the variant-inclusive one and is not comparable to any census row.
