# THE COMPOSE SWEEP OOM-KILLS THE DAEMON AT THE WIDE BUDGETS, AND ONE CRASH USED TO COST FOUR ARMS (measured RuggedFox 2026-08-27).

THE COMPOSE SWEEP OOM-KILLS THE DAEMON AT THE WIDE BUDGETS, AND ONE CRASH USED TO COST FOUR ARMS (measured RuggedFox 2026-08-27).

WHAT HAPPENED. A 5-arm compose_replay sweep (8:3, 28:5, 16:4, 44:6, 60:8) on the frozen bed dr-1787807617. Arm 8:3 flew clean in 10.6 min. During arm 28:5 the kernel OOM-killed the daemon:

  Out of memory: Killed process 864776 (sovereign-cli-d)
  total-vm:126299660kB  anon-rss:61525352kB   (= 58.7 GiB ANON)

systemd restarted it 25s later (Restart=on-failure). Arms 16:4, 44:6 and 60:8 then each failed INSTANTLY against the dead/reloading socket:

  section draft: draft ask: Inference error: Remote API request failed:
  error sending request for url (http://127.0.0.1:9741/v1/chat/completions)

ONE crash, FOUR arms lost — 36 minutes of compute for one usable point.

WHY 58.7 GiB. Weights are ~29 GB (27B 25.9 + 4B 2.6 + embed 0.6) yet anon RSS was double that — models are not file-backed. On top of it, the KV budgets the daemon logs at load: slot="fast" n_ctx=65536 kv_ceiling_mib=8448 (8.2 GiB), slot="fast_short" 2112 MiB, plus the primary's own 64k KV. This host's wall is ~55 GiB (note 0b7eb9f3), so the wide arms' larger per-section prompts only had to add a little.

THE TWO CONSTRAINTS PULL OPPOSITE WAYS (with note b061819c). Deep research REQUIRES fast_context_size unset/large — its round budget is a hardcoded ~96,000 chars — but unset means n_ctx=65536, costing 8.2 GiB of KV instead of 2.1 GiB at 16384. One config breaks the flight; the other feeds the OOM. Nothing reconciles them.

WHAT LANDED. sweep-compose.sh now flies ONE ARM PER `cargo test` INVOCATION, skips an arm whose markdown already exists, waits for the daemon between arms (up to 10 min — a 27B reload is not instant, and an arm fired into that window fails for a reason unrelated to its budget), and optionally restarts the daemon between arms (RESTART_BETWEEN=1). merge_replay.py accumulates the per-arm reports, since a single-arm invocation overwrites compose-replay.json with only its own row. A crash now costs ONE arm and the re-run resumes.

CONFIRMED FIXED: a daemon restart no longer respawns the ~12 GiB `rust-analyzer scip` child (0 rust-analyzer processes across three restarts today), so the compounding cycle in 0b7eb9f3 is broken.

THE HARNESS BEHAVED CORRECTLY. compose_replay records a failed arm as ms:null/out:null with the error text — never a zero — so the curve showed ONE honest point instead of four fabricated ones (§18.3).
