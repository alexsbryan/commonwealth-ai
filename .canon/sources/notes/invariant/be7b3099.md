# investigation enrichment now has per-chunk resume checkpoint + retry — it had regressed vs the atlas pipeline's default resumability

investigation enrichment now has per-chunk resume checkpoint + retry — it had regressed vs the atlas pipeline's default resumability

The investigation enrichment pipeline (`corpus-engine/src/enrichment/investigation/`)
originally had no resume/checkpoint — `run_investigation` accumulated all
extractions in memory and wrote graph JSON only at the very end, so any crash
discarded the entire multi-hour 35B pass. This was a regression: the mature
atlas pipeline (`enrichment/pipeline/runner.rs`) has had append-only
`_checkpoint.jsonl` resume as a default for ages.

Fix (2026-06-04): added `investigation/checkpoint.rs` mirroring the atlas
pattern — per-chunk append-only `investigation/_phase1_checkpoint.jsonl`
(`ChunkCheckpointEntry::{Success{chunk_id,extracted:ExtractedChunk},Skipped{chunk_id,reason}}`),
read→`processed_ids`→skip-on-resume, `collapse_successes` (last-write-wins,
success beats a later skip) seeds the accumulators, cleared on successful
completion so a *fresh* re-enrich starts over. Plus per-chunk
retry-with-backoff (4 attempts, 0.5/1/2s) so a transient fault retries instead
of aborting; a chunk is skipped only after retries exhaust. `ExtractedChunk`
gained `Serialize/Deserialize` for the checkpoint.

Root cause of the crash that surfaced this: the daemon's primary model is
`Qwen3.6-35B-A3B-UD-MTP-IQ4_NL` (MTP speculative decode). On `has_schema=true`
calls it intermittently (~sub-1%) throws `MTP process(verify) failed: Process`
→ 503; the daemon *survives* (per-request fault), but the old client treated
the 503 as fatal. Retry handles the transient; the checkpoint handles a true
crash. Daemon-side root cause (route schema/grammar calls around MTP, à la the
tools-bearing gate at `embedded.rs:701`) is a separate, deferred follow-up.

Caller: `sovereign enrich investigation build <corpus_id>` →
`enrich_cmd/investigation.rs:306` passes the stable `~/.sovereign/indexes/<id>/`
dir; chunk_id from the corpus index is stable across runs, so resume is sound.
