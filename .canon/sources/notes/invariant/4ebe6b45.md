TRACE VERDICT (2026-08-07, branch fix/recipe-domain-gate, commit 4065d20b, full writeup docs/TRACE_ENRICHMENT_ENABLED_FLAG.md):

IndexMeta.enrichment_enabled is written in EXACTLY ONE place in the whole workspace — corpus-engine/src/index/create.rs:231, where it is written `false`. There is no setter (contrast set_dedup_by_source index/mod.rs:982, set_display index/mod.rs:1125). Every other mention is a read. So the flag is a permanently-false constant, while its doc comments (index/mod.rs:409-411, types.rs:346-347) claim "True if the enrichment pipeline has been run at least once."

CONSEQUENCE, and this is the real defect: sovereign/crates/sovereign-tools/src/enrichment_checker.rs:47-49 opens its loop with `if !info.enrichment_enabled { continue; }`. Because the flag is never true, that `continue` fires for EVERY corpus, so the entire body — LowEnrichmentCoverage (missing field-model tables) and StaleEnrichment (leftover checkpoint) — is unreachable in production. The standing health check that exists to report "enrichment was requested here and never completed" cannot report a single issue for any input. That is why the 2026-08-07 literary-domain failures had no second surface: the ingest-time report was correct and loud, the standing surface was structurally silent.
