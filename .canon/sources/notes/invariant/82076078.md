knowledge-gym: a replay the daemon REFUSED is could-not-judge, never a failure (2026-09-05, order check-cost-structural addendum; supersedes the behaviour note c11fefdd describes).

THE DEFECT. `ReplayReport::passed()` (sovereign-cli-llm/src/knowledge_gym_cmd/runner.rs) was `runner_error.is_none() && predicates.all(passed)`, and `pass_count`/`pass_rate` counted everything else as a failure. So three replays that 503'd under a peer's load scored `0/3` — byte-identical at the lane to three real predicate failures, and `all-zero tally` is a HARD row in `svrn quality check`. ARCH §18.3: an `Err` collapsed into a success-shaped value, except here it collapsed into a FAILURE-shaped one, which is worse because it manufactures a finding.

THE FIX, three seams:
- `ReplayReport::errored()` split from `passed()`; they are no longer complements. `error_reason()` carries the runner's own text.
- `FixtureReport`: `errored_count()`, `judged_count()`, `first_error()`; `pass_rate()` returns `Option<f32>` — `None` when nothing was judged, because returning 0.0 there IS the substitution.
- `AggregateSummary.per_fixture` went from a positional `(String, usize, usize, f32)` to a named `FixtureRollup { slug, passed, errored, replays, pass_rate }`. The errored count has no honest slot in a 4-tuple and appending a fifth cell is identity-from-position (ARCH §7.5). Top-level gains `total_errored`; `pass_rate` is now over JUDGED replays. `bench_cmd/gate.rs:773` reads only `total_passes`/`total_replays` and is unaffected.
- `bench_lane.rs::census_gym` reads the named fields, contributes NO tally for a fixture with zero judged replays (so it cannot be scored-zero), scores a partially-refused fixture on what ran (1 pass of 1 judged, not 1 of 3), and pushes a new `Census.never_ran` that `rows()` renders as a could-not-judge row `replays that ran`.

Tests: `gym_replays_that_never_ran_are_could_not_judge_and_never_a_zero_tally` and `gym_partial_refusal_scores_only_the_replays_that_ran` in bench_lane.rs.

THE TWO FULL RUNS IN NOTE d596639c ARE CLEAN. Checked the persisted stdout for runs 20260904-212228, 20260904-204439 and 20260904-194300: all three report `01_corpus_definitional 3/3`, `05_noresults_honesty 0/3`, `06_fabricated_id_blocked 3/3`, and NO stderr line carries `RUNNER ERROR` (the human render prints one per errored replay). The old aggregate JSON had no `runner_error` field at all, so the check could not have told either way — the evidence is the stderr. So d596639c's finding 1 stands: `05_noresults_honesty` 0/3 is a real predicate failure (the model answers without calling `knowledge_lookup`), not a 503, and the two 3/3 controls are real.

SEARCH-GYM DOES NOT SHARE THIS RUNNER. `search_gym_cmd/runner.rs` and `score.rs` are separate; `Scored` already carries `runner_error` as its own field on the wire, so a consumer can distinguish. It is also not a `svrn quality check` lane (zero occurrences in quality/check-lanes.toml). Left alone.
