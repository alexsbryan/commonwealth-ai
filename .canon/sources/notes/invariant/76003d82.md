# The native runner's prompt preamble must stay bounded by the CALLER's workdir scale, and the daemon's 16,384 context is a config default,…

The native runner's prompt preamble must stay bounded by the CALLER's workdir scale, and the daemon's 16,384 context is a config default, not a model ceiling. Both measured 2026-08-18 while standing up sovereign/bench/external/swebench.

WHAT BROKE. `agent-bench swebench --agent native` on a real pylint checkout sent a 39,251-token prompt into a 16,000-token slot and Crashed before the planner's first call. Two independent causes, both confirmed by measurement, neither guessable:

(1) PREAMBLE. Measured on the pylint-dev__pylint-4661 checkout via the env-gated probe `runners::native::tests::probe_preamble_sizes_on_real_checkout` (set NATIVE_PROBE_DIR):
  - summarize_workdir      56,510 chars / ~14,127 tok / 1,122 lines  <- UNBOUNDED
  - render_workdir_anchors 54,015 chars / ~13,503 tok / 1,257 lines  <- budget working
  - preamble total         ~27,630 tok of the 39,251
  The issue text was 268 tok — 0.7% of the prompt.
  `collect_workdir_entries` had NO skip-list and NO cap (unlike its sibling `collect_source_files`), so it walked `.git/` and the full test tree to depth 3. Invisible on an agent-coding scaffold (1-3 files); fatal on any repository.
  FALSIFIED EN ROUTE: I first hypothesised outline mode was unbudgeted. It is not — the 1,200-line anchor cap held at 1,257 lines. Measure before fixing.

(2) CONTEXT. `capacity.rs:304 primary_ctx = cfg.models.effective_context_size()` -> `setup_config.rs:641 default_context_size() = 16384`. The loaded model's GGUF says `qwen35.context_length = 262144`. The daemon runs it at 6% of trained capacity, at a default nobody chose. STILL UNCHANGED — raising it is an operator call on a shared daemon.

FIRST PRINCIPLES (operator steer, and it changed the fix). The agent's allowlist is read/write/bash/find/grep/ls, so every enumeration token buys what one tool call fetches. A listing is orientation, not an inventory. Measured listing cost on the same checkout: root-only 174 tok · depth1 581 · depth2 2,266 · depth3 2,384. Floor for a repo = issue (268) + root (174) ~= 440 tok against the 27,630 that was being sent.

AS BUILT. Two knobs on `AgentRunContext` (runner.rs), both defaulting to today's values so agent-coding is bit-identical:
  - `anchor_budget_lines`     default DEFAULT_ANCHOR_BUDGET_LINES = 1200; 0 renders no source at all
  - `workdir_listing_depth`   default DEFAULT_WORKDIR_LISTING_DEPTH = 3
  `cli/swebench.rs` sets `.with_anchor_budget(0).with_listing_depth(0)`.
  Plus MAX_WORKDIR_ENTRIES = 200 as a hard cap and the ANCHOR_SKIP_DIRS skip-list applied to the listing.

GATES. Regression test `workdir_listing_is_bounded_on_a_repo_scale_tree` caught an off-by-two in my own fix (each recursion frame appended its own truncation notice; the notice now lives in `summarize_workdir_to_depth`, the single caller). `zero_anchor_budget_renders_no_source` pins the 0 case. Full suite 10,081 pass / 0 fail, lint 0 errors.

THIRD FIX, same run. `verify_cmd` defaulted to `python -m pytest` — unwinnable in a bare checkout with no installed env, and the agent burned its whole budget on it (VerifyStuck at 3 identical failures, 187s). Now a syntax check on changed files. Full-suite verification belongs to the grader's per-instance image, not to generation.

RESULT ON THE INSTANCE, same model (Qwopus3.5-4B), four runs: Crashed/0B -> NoProgress/0B -> VerifyStuck/3,875B -> NoProgress/4,076B. Plumbing proven end to end. The patch itself is junk — the 4B rewrote `.copyrite_aliases`, an unrelated file, and never touched the issue. Capability finding, not a harness one: the arm comparison needs a larger resident model before any delta means anything.
