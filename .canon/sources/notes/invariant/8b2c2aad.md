NEXT-EDIT HARDENING INVARIANTS (2026-07-30, uncommitted). Four rules that are easy to re-break; each cost a real bug. Full record: NEXT_EDIT.md §9a.

1. A TIMEOUT CANCELS NOTHING. Engine dispatch is spawn_blocking (engine.rs:2447) and dropping a JoinHandle DETACHES — llama.cpp keeps decoding and keeps slot.context's lock. So the one-in-flight permit MUST ride INTO the tokio::spawn (try_acquire_owned + drop(permit) inside the task), not live in the handler scope. Releasing it on timeout meant every timed-out consult left a live generation while the next request sailed through try_acquire — the budget stopped bounding anything exactly when the slot was most contended. Any future cancel/timeout work here must preserve this. Test: a_consult_in_flight_holds_the_slot.
   NOTE (engine-side, NOT fixed, out of scope): the extras branch binds `let _permit` OUTSIDE its spawn_blocking closure (engine.rs ~2437) while the primary branch moves it IN (`let _permit = _permit;` ~2560). So on the extras path the slot's OWN inflight permit releases on future-drop while the blocking task still holds the context lock. Worth a look if extras-slot contention ever misbehaves.

2. GUARDS RELATIVE TO THE REGION BOUND NOTHING IF THE REGION IS UNBOUNDED. REGION_LINES caps LINES; one minified line made region = whole 512KiB file, so MAX_GROWTH_BYTES/MAX_LINE_DELTA became no-ops (measured: a 3000-byte reply → one hunk deleting 521,288 bytes). Region is now capped in BYTES (MAX_REGION_BYTES 8KiB, line-budget shrink in select_region) and blank/marker-bearing/over-budget regions are declined by name. A blank region is the pure case: every returned byte is invention with nothing to measure it against.

3. SHRINK NEEDS TWO BOUNDS, AND REPAIR IS NEVER SAFE. Growth cap was one-sided — a truncated completion is SMALLER than the region and diffs as "delete the rest". Bound absolutely (2048) AND proportionally (50%: 20 lines gutted to `//` loses <2KiB with line-delta 0), plus drop finish_reason=="length". Never repair suspicious output: the old marker-stripping repair silently DELETED a real file line that happened to BE a marker and rewrote every line ending. Fences must wrap the WHOLE reply and close on the FIRST fence (rfind swallowed chat commentary as file content). CRLF regions must be normalized before diffing or the line-LCS collapses to one whole-region hunk AND faithful echoes stop registering as noop.

4. ONE RULER FOR THE WIRE CONTRACT. Daemon caps unit fields in UTF-8 BYTES; the client capped in UTF-16 CHARS, and fixed-offset context slices could emit a lone surrogate serde_json rejects. Either 400s the WHOLE request, and the offending unit STAYS in the history window — so it poisoned every later prediction until it aged out, behind a green status bar (4xx was swallowed). Contract now lives in packages/vscode-sovereign/src/wireLimits.ts (bytes/sliceWhole/unitFitsWire); a 4xx clears history and warns once. Do not re-introduce a second measurement.

Also: already_applied was quadratic per-site (re-derived find's offsets in replace at EVERY site) — crafted 512KiB request = 23s blocking CPU on one tokio worker, on the ALWAYS-ON rule lane needing no model_lane opt-in. Alignments computed once per rule; MAX_RULE_BYTES/MAX_ALIGNMENTS/MAX_SITE_SCAN bound the rest.
