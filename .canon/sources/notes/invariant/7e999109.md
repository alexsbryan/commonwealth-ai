release-all CLI linux podman leg MUST cap CPUs via taskset (like the desktop leg) or it deadlocks on the qemu glslc shader build at \"Compiling llama-cpp-sys-4\

Cutting v0.3.0 (2026-07-17) the local release (`scripts/release-all.sh --publish`)
STALLED: mac aarch64 (18m) + x86_64 (17m) legs finished, then the **CLI linux
podman leg hung** — watchdog killed it at 1200s (VM load 0.09, no compile).

ROOT CAUSE: `release-cli-local.sh`'s linux leg ran a plain `cargo build` in the
`--platform linux/amd64` container. Under qemu-x86 emulation on the arm64 Mac,
llama-cpp-sys-4's ggml-vulkan build script parallel-spawns `glslc` sized to the
visible CPU count and deadlocks at "Compiling llama-cpp-sys-4" (glslc zombies,
VM idle). `build-desktop-linux.sh` already guards this with `taskset` (serial
shader gen, SOVEREIGN_LINUX_BUILD_CPUS default 1) — but the CLI leg never got the
guard, AND release-all runs CLI FIRST with a cold shader cache, so it hit it.

FIX (committed to the scripts): `release-cli-local.sh` linux leg now runs
`taskset -c 0-$((LINUX_BUILD_CPUS-1)) cargo build` in the container, matching the
desktop leg. VALIDATED: linux-leg-only build ran to completion in ~60m (serial C++
+ shaders under emulation is slow but WORKS — no deadlock), packaged
sovereign-x86_64-unknown-linux-gnu.tar.gz (192M). Also improved: the release-all
stall watchdog now dumps a `<log>.stall.txt` on hang (in-flight crate, last 25
log lines, VM process tree = glslc/cc1plus/zombies, load+memory) so a future hang
self-explains instead of just "no output 1200s".

KEY OPS NOTES:
- The ~60m cold shader build is a ONE-TIME cost — the shader cache
  (target-container-linux) persists, so subsequent release-all runs find it WARM
  and SKIP shader gen. A re-run after a validation build is fast on the linux legs.
- release-all runs CLI before desktop; both build llama-cpp-sys-4 in the same
  container image, so whichever is first pays the cold cost, the second is warm.
- The stall watchdog correctly distinguishes serial-compile-busy (VM load ~1.0,
  cc1plus pegged) from deadlock (VM load ~0.02, glslc zombies) — a naive
  log-size-only monitor false-flags the long silent C++ compile; always check
  VM load (`podman machine ssh 'cat /proc/loadavg'`) before calling a hang.
