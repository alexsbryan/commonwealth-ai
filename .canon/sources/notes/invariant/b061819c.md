SETTING [models].fast_context_size BREAKS EVERY DEEP-RESEARCH FLIGHT, AND THE ERROR NAMES A TOKEN COUNT RATHER THAN THE CONFIG KEY (measured RuggedFox 2026-08-27).

WHAT HAPPENED. The Flash-Next workstream added `fast_context_size = 16384` to ~/.sovereign/config.toml (its own frame says "KEEP that"). The next deep-research flight died ~60s in:

  round draft: evidence bounded ... chars_used=95889 budget_chars=96000
  drafting leg dispatched leg=Round speed=Fast prompt_chars=98936
  503: local inference failed: Prompt too long: 21014 tokens already meets
       or exceeds the context window of 16380.

WHY IT IS STRUCTURAL, NOT A TYPO. deep_research routes BOTH volume legs to the fast slot — port.rs:1107 `DraftLeg::Round | DraftLeg::Section => Speed::Fast`. The round evidence budget is a hardcoded constant (synthesize.rs:1448, ROUND_EVIDENCE_TOKENS * CHARS_PER_TOKEN ~= 96,000 chars ~= 21k tokens) and NOTHING derives it from the slot it will be sent to. Two deciders, no conversation (ARCH 10.6). setup_config.rs:722 `effective_fast_context_size()` falls back to `effective_context_size()` (65536) when the key is ABSENT — so the working configuration is the one that does not set it at all.

THE THREE RETRIES ARE NOISE. `inference shed (503) — honoring Retry-After` fires 3x before the real error surfaces. The prompt cannot get shorter on retry, so the backoff only delays the diagnosis.

WHAT TO DO. For any deep-research flight, `[models].fast_context_size` must be unset (or >= ~24000). config.toml.pre-flashnext.bak is the known-good deep-research config. Verify from the daemon's own log, not the file: `journalctl --user -u sovereign | grep 'slot="fast" n_ctx='`. Note `slot="fast_short"` is a SEPARATE 16384 companion slot and is not the one that matters.

GUARD LANDED. research/deep-research/arms/bed/mint-compose-bed.sh refuses when the fast slot reports n_ctx < 24000, naming the config key. Verified to fire at 16380 and pass at 65536.
