A WIRE DIALECT WRITTEN FROM A MODEL CARD AND NEVER RUN AGAINST THE WEIGHTS IS A 100% SILENT FAILURE. Found 2026-08-05 by the first zeta-2 bakeoff arm.

WHAT HAPPENED: `build_prompt_zeta2` / `parse_rewrite_zeta2` were built from a prose model-card description and emitted `<|marker_1|>` / `<|marker_2|>` sentinels. Zeta-2's ACTUAL canonical `sample.prompt` (published in the `zed-industries/zeta-2` repo itself) brackets the editable region with GIT-MERGE markers:
    <<<<<<< CURRENT\n{region}\n=======\n<[fim-middle]>
and the model resumes with the UPDATED side BARE (no opening marker), terminating with `>>>>>>> UPDATED`.
Against the real weights the old dialect scored 0/30 — 19 `invalid` + 11 `truncated`, a 100% parse failure. Corrected, the SAME arm scores 27/30. NEXT_EDIT.md had claimed this format was "built"; it was built against a dialect that does not exist.

THE GENERAL RULE: fetch the vendor's own `sample.prompt`/`sample.output` before implementing a dialect, and pin the constants in a test naming where they came from (`zeta2_region_markers_match_the_published_sample_prompt`). A format nobody has run is not implemented, it is guessed.

TWO CONSEQUENCES THAT ARE EASY TO RE-BREAK:
- The terminator is ALSO the stop string. llama.cpp CONSUMES a matched stop rather than returning it, so the parser must STRIP `>>>>>>> UPDATED` if present and must NOT require it — demanding it fails every well-formed completion. Unterminated run-ons are already refused upstream by the `finish_reason == "length"` guard in `finish()`.
- The region poison check must refuse `=======`, which also declines Markdown/RST setext underlines and live merge conflicts. That is the CORRECT trade: an ambiguous region boundary corrupts a file; silence costs one suggestion.

AND THE PROCESS LESSON: report this class as could-not-judge, never as fail. Recording zeta-2's 0/30 as a loss would have published a confident, permanent, FALSE verdict about a competitor's model based on our own bug. `scripts/next_edit_bakeoff.py::format_fidelity` now separates protocol-boundary drops (`invalid`, `truncated`) from content drops (`noop`, `inconsistent`) and returns could-not-judge automatically.
