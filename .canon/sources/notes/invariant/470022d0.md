QWEN3.5 ON gfx1151: THE COMPLETE TRANSFORMERS FAST PATH IS MEMORY-INFEASIBLE — INSTALL flash-linear-attention BUT NOT causal-conv1d (measured 2026-08-02, Strix Halo, sovereign-rocm-7.2.4).

Qwen3.5-0.8B is 18 `linear_attention` (gated deltanet) layers to 6 `full_attention`. transformers has a fast path guarded by `is_fast_path_available = all(...)` over four symbols: causal_conv1d_fn, causal_conv1d_update, chunk_gated_delta_rule, fused_recurrent_gated_delta_rule.

MEASURED, ORPO probe, effective batch 32 / seq 4096 / micro 1 / grad-ckpt on:
- no fla at all .................. 231.8 s/it, ~24 GB GTT   (eager torch deltanet)
- fla only (ccc absent) ......... 177.1 s/it, ~25 GB GTT   <- USE THIS
- fla + causal-conv1d (all four) . SIGKILL,   ~100 GB GTT  <- host OOM killer, twice

ATTRIBUTION IS CLEAN: killing the trainer dropped GTT 102,892 -> 21,574 MiB, so the ~80 GB was the trainer's, not a co-tenant's. Two attempts (m0-halo-trl-OOMKILLED-attempt2/3) both died rc=137 with NO Python traceback — SIGKILL from the host OOM killer never produces one, so this looks like a silent disappearance rather than an error. gpu_peak from torch's own counter read only 20.31 GB at the time, because torch.cuda.max_memory_allocated() does NOT see GTT the HIP runtime reserves outside PyTorch's allocator. On unified memory ALWAYS cross-check /sys/class/drm/card1/device/mem_info_gtt_used.

WHY: with all four symbols present the model takes the CHUNKED gated-delta-rule path, whose intermediate states at seq 4096 x 16 heads x 128 key/value dim dwarf the sequential fallback. The partial fast path keeps the cheap torch depthwise conv AND the fast Triton deltanet recurrence, which is the good trade.

DO NOT "fix" the `The fast path is not available because one of the required library is not installed` warning. It fires when ANY of the four is missing and is MISLEADING here: the expensive deltanet recurrence is already on fla's Triton kernels. Chasing the warning to zero is what caused both OOM kills.

BUILDING causal-conv1d IS possible on this box if ever needed (it is NOT a compiler gap — see note about the runtime-only image): `sudo dnf install -y hipcc rocm-llvm hip-devel rocm-device-libs gcc gcc-c++ libstdc++-devel hipcub-devel rocprim-devel`, then `uv pip install causal-conv1d --no-build-isolation` with ROCM_HOME=/opt/rocm and PYTORCH_ROCM_ARCH=gfx1151. It compiles clean. It is the RUNNING of it that is infeasible.
