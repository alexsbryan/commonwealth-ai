  nc-redundant.py #1   exact 196  near 467  lines 14088

TWO DISTINCT DEFECTS, and they need different fixes:

1. THE STAMP IS NECESSARY BUT NOT SUFFICIENT. `exact` moved 196 -> 202 with `indexed_head` and `indexed_at` unchanged, so the index CONTENT changes without the provenance row advancing. Two runs carrying the same stamp are therefore NOT comparable. (Same effect explains the campaign bar's 14162 vs a same-stamp run's 14156 at `d8af5cbf`.) A row stamped only with `indexed_head` is a success-shaped stamp over an unverified claim — ARCH §18.3, the exact thing that stamp was added to prevent.

2. THE NEAR PASS IS NONDETERMINISTIC. Runs 3 and 4 have IDENTICAL group counts (202 exact / 467 near) but differ by 8 redundant lines. Same clustering, different total means the cluster REPRESENTATIVE differs — `unit_lines` is picked from a cluster whose member order depends on thread completion in the `O(n^2)` 12-thread near pass (`dry_report.rs`, contribution = `(members-1) * unit_lines`).

MEASURED BANDS: +/-8 lines at byte-identical index content; +/-77 lines across silent index rewrites at one stamp.

CONSEQUENCE FOR RUNGS: a single run is not a value (ARCH §18.5). Quote n>=2 and the spread, and attribute a delta to a rung only when the index provably advanced to that rung's commit. Deriving the rung's own contribution from the CLUSTER LIST (which clusters disappeared, times `(members-1)*unit_lines`) is exact and index-independent; the headline delta is not.
