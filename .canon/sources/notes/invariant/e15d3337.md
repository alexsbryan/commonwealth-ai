Optimistic-dispatch invariant in ChatView.handleSend / handleNextStep — never re-introduce blocking awaits before SEND_INITIATED

`ChatView.handleSend` and `ChatView.handleNextStep` MUST dispatch `SEND_INITIATED` (and `scrollToBottom()`) BEFORE any `await` to the Tauri bridge — `ensureConversation()`, `sendMessageStream()`, `resumeSession()`, etc.

Why: the user reported a 60-second blank chat window after clicking an onboarding starter chip. Root cause: a cold daemon's `send_message_stream` round-trip can take many seconds, and the original handleSend awaited it before pushing the user bubble or flipping `isLoading`. Result: empty messages region + no spinner = "frozen UI" perception. The fix (April 2026) split `SEND_START` into `SEND_INITIATED` (user bubble + → preparing) and `SEND_START` (assistant placeholder + → streaming). `isLoading` derives from `preparing || streaming || docOpInFlight` so the typing indicator renders the moment the user clicks. Pinned by `tests/e2e/specs/chat-responsiveness.spec.ts` "user sees feedback within 150ms of click even when bridge is slow".

How to apply: when adding a new chat-send path, the order is locked-down:
1. Build `userMsg` (purely local).
2. `send({ type: "SEND_INITIATED", userMessage: userMsg })`.
3. Clear input + scroll to bottom.
4. THEN await Tauri bridge calls.
5. On success: `send({ type: "SEND_START", assistantMessageId: started.message_id })`.
6. On failure: `send({ type: "SEND_FAILED", error: String(e) })`.

`ensureConversation()` uses `CONVERSATION_BOUND` (not `HYDRATE`) to set the new conversation id — `HYDRATE` would wipe the optimistically-pushed user bubble. Don't change ensureConversation back to HYDRATE without first restoring the wipe-safe contract some other way.

Where the latency test lives: `sovereign-desktop/tests/e2e/specs/chat-responsiveness.spec.ts`. It stubs `create_conversation` and `send_message_stream` with 500ms artificial delays and asserts user bubble + loading indicator appear within 150ms. If you change the optimistic-dispatch order, this test will fail.
