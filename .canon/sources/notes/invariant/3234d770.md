serve50-scheduler SECOND GATE: a peer that is yielding to its local user still gossips availability=1.0, so the mesh scheduler keeps selecting it and burns a round-trip per turn.

Measured 2026-08-14 on RuggedFox at N=2 (peer Alexs-MacBook-Pro-2). After the `no_routing_signal` gate was removed, the ranked scorer selected the peer on 421 of 672 dispatches. ALL 421 were refused:
  503 {"error":"local user active","reason":"yielded_to_local","retry_after_secs":2..14}
That is the yield hook at commonwealth-api/src/state.rs:2057 — correct policy, a peer's own user comes first.

THE DEFECT: the peer's scored candidate record reads `availability: 1.0` the whole time. `local_inference_availability` (published by gossip.rs:414, consumed by the scorer) is only ever written by AppState::update_local_availability (state.rs:1757), whose own doc says it is "called by sovereign-server's ActivityReporter". Nothing in sovereign-cli-daemon calls it. So on a daemon-only node the yield state is INVISIBLE to the mesh: infinite selection of a node that refuses 100% of turns.

Follow-on order shape (needs peer-side code + a gossip signal, not measurable from one node): have the yield hook drive local_inference_availability, or add an explicit yielding flag to the manifest/gossip, and have the scorer exclude or heavily penalise it. Until then `serve50-fleet-scaling` cannot go green no matter what the local scheduler does — this is the binding constraint, not the scheduler.

SAME ROOT CAUSE hits corpus locality (doc §9.5): /v1/knowledge/search fans out correctly to peer-only corpora, gets the same 503, logs `corpora_unavailable={maple-house,...}` — and returns confidently-scored results from an UNRELATED LOCAL corpus with nothing in the response body saying five corpora were unreachable. The silent-substitution half is fixable on this node alone: carry corpora_unavailable into KnowledgeSearchResponse.

ALSO: oicp-client's two streaming error paths used to discard the remote body, which is why this was invisible. Fixed (error_excerpt, shared with the non-streaming path, which also had a latent mid-UTF-8 panic at byte 500).
