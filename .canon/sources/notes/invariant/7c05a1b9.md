TEN CLI COMMANDS DECLARED `probe = "help"` DO NOT HONOUR `--help` — found 2026-07-28 by the new journey dispatch replay, fixed in the manifest.

cli_contract_code probes all 157 commands with `--help` and its module doc claims this "is safe across the surface — the help check short-circuits before any daemon probe or side effect". For ten commands that claim is FALSE, and it was invisible because the test deliberately ignores exit codes.

Verified live on RuggedFox, real HOME, 2026-07-28:

TWO CLASSES.
(a) `--help` IS IGNORED AND THE COMMAND RUNS:
  - `corpus status --help`   → prints the real corpus status table, hits the daemon, exit 0
  - `alignment status --help`→ prints "Alignment dry-run", exit 0
  - `recipe validate --help` → "warning: unknown flag '--help' — ignored", then RUNS, exit 1
  - `recipe test --help`     → same
(b) `--help` REJECTED as an unknown flag / missing positional (exit 2):
  - `meshapp`, `tools describe`, `tools call`, `knowledge-gym run`,
    `search-gym calibrate-judge`, `search-gym run`

Class (a) is the hazard: a conformance probe that believes it is asking for help is actually EXECUTING a daemon-touching command 157 times per test run.

FIX APPLIED: all ten rows now carry `probe = "no-args"` in docs/cli-contract.toml with a one-line verified reason each. That is the existing enum's semantics ("assert dispatch reached the handler; exit code ignored") and changes nothing about cli_contract_code's behaviour — NoArgs is still probed with --help there, only the exit code is ignored. It is cli_journey_dispatch that now asserts exit 0 for probe="help" steps, which is what surfaced the drift.

GOTCHA THAT COST ME A CYCLE: `model --help` and `claim --help` are FINE (exit 0, real help). They appeared in the first failure list because I probed the STEP's literal path (`model list --help`) rather than the DECLARED command path (`model`). `model` is deliberately declared subcommand-shaped — help lives on the verb. Probe what the contract declares, not what the journey step types.

STILL OPEN (ledgered, not fixed): `proxy --help` exits 2 because proxy_cmd/mod.rs:29 matches `--help` as a subcommand name. proxy is `hidden = true` so it is outside canonical() and outside every journey — the journey layer does NOT cover it.
