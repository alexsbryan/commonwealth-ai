`session_state` MUST NEVER RETURN A SUCCESS SHAPE FOR A WRITE THAT WROTE NOTHING (fixed 2026-07-29, sovereign-tools/src/code/session_state.rs).

THE BUG. The MCP `execute` read section bodies with `params.get(p).and_then(|v| v.as_str())` and never looked at the keys it did NOT recognise. So a caller reaching for a plausible-but-wrong param shape had every field silently dropped, and `upsert_frame` then happily CREATED the file and returned `{created: true, sections_updated: [], approx_tokens: 96}` — a success-shaped response for a frame with eight empty sections, written over whatever was there before.

EVIDENCE (measured, not inferred). 111 `session_state` calls across the local Claude Code transcripts; 10 used a wrong shape. Two shapes appeared in the wild, both invented independently by different sessions:
  - `sections: [{name, content}]`  (sessions 2efd374f, cbc8c4fb)
  - `section: "Goal", content: "..."` (session ecefb2e5)
Both mirror the crate's internal `FrameUpdate.sections` field, which is why they are the natural guess. On disk, 3 of 56 frames were 385-byte all-sections-empty husks stamped `provenance: self-reported` — ecefb2e5, bed9f7d8, 32b0da98. ecefb2e5 was live in the boot-hook frame index advertising "0 next" and an empty summary to any successor that attached to it. Sessions 2efd374f and cbc8c4fb recovered only because the agent noticed and ran `tools describe`; prior reflection 78be9684 records that recovery costing two wasted calls.

WHY THIS FAILURE MODE IS WORSE THAN AN ERROR. The frame is a write-and-walk-away surface — nobody reads it back in the session that wrote it. The whole value proposition (self-reported frames grade 100% recall vs 17% for distillation) depends on the write landing, and a success-shaped no-op destroys exactly the sessions that were diligent enough to bank state. The damage surfaces one session later, in a different context window, as "the frame is empty" — with no way left to attribute it.

THE THREE GUARDS NOW IN PLACE:
1. `execute` rejects ANY unrecognised key, naming the offending keys and teaching the real shape ("sections are FLAT string params ... there is no `sections` array and no `section`/`content` pair"). `is_known_param` derives from SECTION_PARAMS + META_PARAMS so it cannot drift from the descriptor.
2. `execute` rejects a known param of the wrong JSON type instead of dropping it — `next: ["a","b"]` now says "`next` must be a markdown string, got array" rather than vanishing.
3. `upsert_frame` rejects an update carrying no section, no status and no note_ids, and writes nothing. This one lives in the core function, not the MCP wrapper, so every caller inherits it.
Plus `additionalProperties: false` on the descriptor, so a validating client fails before the round trip.

GENERAL LESSON FOR EVERY TOOL ON THIS SURFACE: `Value::get(k).and_then(as_str)` is a silent-drop idiom. On a WRITE tool it converts a caller's mistake into data loss with a success receipt. Prefer matching on the value and erroring on the mismatch arm.

Tests: session_state.rs — empty_update_is_rejected_and_banks_no_frame, sections_array_shape_is_rejected_not_silently_dropped, section_content_pair_shape_is_rejected, non_string_section_body_is_rejected, flat_section_params_still_write_through_the_mcp_path. 11/11 pass, lint 0 errors.
