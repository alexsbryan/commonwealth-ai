# Release on Fedora: THREE tools straddle the toolbox boundary, not two — and gh is the one that bites

Release on Fedora: THREE tools straddle the toolbox boundary, not two — and `gh` is the one that bites

The frame/doc invariant used to name two: podman (host only, every container
leg) and native cargo (toolbox only, the workspace test gate + router-embed
cache check). There is a THIRD with its own locality, found 2026-08-10 on
RuggedFox:

  gh  — needed by the ENTIRE preflight, every upload, and the publish gate.
        Shipped in the sovereign-vulkan toolbox image. NOT installed on the
        Fedora host.

Consequence before the fix: the release driver was unrunnable from EITHER side.
From the host, `release-all.sh` dies on its first preflight line
(`'gh' is required on PATH`, scripts/release-all.sh:64/90). From inside the
toolbox, every container leg dies because podman is unreachable. The failure
reads like a broken install rather than "this tool is on the other side".

RESOLUTION: install gh on the HOST (`sudo dnf install gh`), do NOT route gh
through the toolbox. The conductor role — draft creation, asset upload, the
publish gate — belongs where podman is, and a `toolbox run` hop per gh call
would put container stderr (e.g. the .bashrc brew warning this host emits) in
the path of output the driver parses with --json/--template.

Auth needs no repeat: the token is keyring-backed and both sides read the same
~/.config/gh/hosts.yml, so a host install inherits the toolbox's session
verbatim. Verified: `gh auth status` on the host shows the same
account/keyring/token with scopes gist, read:org, repo, workflow.

VERIFIED AFTER: `release-all.sh --check` runs the full preflight on Linux and
dies at the correct REAL failure (tag cli-v0.5.0 → 9deb7771 vs HEAD 4ca7298e),
having first printed the right route:
  Host: Linux x86_64 (linux-x86_64) — Apple legs: NO (build them on the arm64
  Mac); container legs: native; native cargo: toolbox run -c sovereign-vulkan

No host-side pnpm/npm is required — all node work is container-side.
