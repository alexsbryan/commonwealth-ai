GIT PATHSPEC COMMIT TRAP, correcting the 2026-08-13 seat invariant "the INDEX is the unit; use git commit -- <paths>". That guidance is right about `git add` not scoping the commit, and WRONG about what pathspec commits: `git commit -- <paths>` commits the WORKING TREE state of those paths, not the index. Watched failing (gate-bigo-prefill-tax worker, same day): pre-A judge.rs staged, land-A live in the working tree of the SAME file -> the pathspec commit swept A in (562 insertions where 185 were staged). Recovery was git fsck --unreachable to refind the pre-A blob, amend, restore. RULE FOR SEAM GUIDANCE IN EVERY ORDER: pathspec commit + a dirty working tree for the same file is a trap. When a file must land in two slices, either stash the later slice (git stash push -- <file>) around the first commit, or commit slice-by-slice with the working tree containing exactly the slice being landed. The pathspec still correctly EXCLUDES unrelated dirty files (that use survives); it does not select among versions of one file.
