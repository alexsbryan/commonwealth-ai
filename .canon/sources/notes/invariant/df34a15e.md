A SLOT ROLE'S ALIASES MUST ROUTE TO WHATEVER OWNS THAT ROLE — INCLUDING A CHILD PROCESS (fixed 2026-07-29, sovereign-cli-daemon build/inference.rs `distributed_primary_model_ids`).

THE BUG. `DistributedPrimaryRoute::claims` (sovereign-compute/manager.rs) matched `request.model_id` against only {shared-model name, GGUF stem}. `commonwealth/primary` — the alias the OpenAI surface documents, `build_self_manifest` ADVERTISES to peers, and `slot_aliases::resolution_alias_keys` resolves locally — was in neither set. On a node whose primary is child-distributed, an alias-named request therefore fell through the facade to the in-process engine, whose primary is deliberately NOT resident in that mode, and was answered by the always-hot 0.8B `fast` slot. HTTP 200, no warning.

MEASURED PROOF (RuggedFox, prompt "Count from 1 to 60, one number per line.", same minute, max_tokens=192):
  commonwealth/primary → completion_tokens=11, output stops at "6", ~111 tok/s
  Qwen3.5-122B-A10B-UD-Q5_K_XL-00001-of-00003 → completion_tokens=170, counts to 60
111 tok/s is impossible for a 122B (~14.8 tok/s local), and mesh_bench.rs's own header already names ~100 tok/s as the fast-slot signature.

CONSEQUENCE — NOT JUST A BENCH BUG. Peers select this node BY the advertised alias, so every peer request for the shared model got the 0.8B. And `svrn mesh bench` sends `PRIMARY_ALIAS = "commonwealth/primary"`, so EVERY measurement ever filed for the 122B is the 0.8B's rate under the 122B's name. RE-BASELINE anything derived from them. The nine guards did not catch it: `primary_is_serving` asserts /status reports the primary RESIDENT, which was TRUE — resident in the child. RESIDENCY IS NOT ATTRIBUTION; that is the general lesson.

THE RULE. Aliases come from `SLOT_ALIAS_POLICY` (sovereign-mesh/slot_aliases.rs), which exists because RESOLUTION and ADVERTISEMENT drifted apart in 2026-05 with nothing enforcing agreement. ROUTING is a THIRD view of the same policy. Never spell alias strings at a routing site — derive them via `resolution_alias_keys(role)`. Test `the_child_claims_the_advertised_primary_alias` fails against the old `vec![stem]`.
