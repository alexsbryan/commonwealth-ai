THE JOIN KEY IS THE SILENT FAILURE, AND IT BIT THE RUST SIDE TOO — 90 MINUTES OF COMPUTE FOR ZERO INFORMATION. Measured 2026-09-01 on the first full GR adjudication (62 candidates, 26 batches, worktree run).

WHAT HAPPENED. Every one of the 62 generated candidates returned COULD-NOT-JUDGE against a CLEAN baseline (11,335 tests, 0 excluded). Cause: scripts/conformance-candidates.py emits `mustFail = ["verbatim_quote_against_evidence_passes"]` — the bare fn name from its own inventory() — while run_suite keys results `f"{classname}::{name}"`, i.e. `sovereign-core::quote_verification::tests::verbatim_quote_against_evidence_passes`. The HAND-WRITTEN seed bank used full keys, which is exactly why the positive control passed and the generated bank could not. Two producers of one key, never reconciled (§10.6).

WHY IT COST ONLY TIME AND NOT TRUTH. The four-verdict rule is the whole reason this was recoverable. A two-verdict adjudicator would have recorded 62 SURVIVED, discarded every candidate, and "proved" the GR family has no coverage — the exact conclusion the previous instrument defect had already tried to sell. COULD-NOT-JUDGE is what made a systematic join failure legible as one. §18.1 earns its keep here.

THE FIX IS IN THE ADJUDICATOR, NOT THE GENERATOR. sabotage.py::resolve_declared now rewrites declared names against the key space of the baseline report IT JUST RAN: exact key first, then unique fn-name suffix. AMBIGUITY IS NEVER RESOLVED BY GUESSING — 99 fn names are duplicated across this workspace (11,186 distinct names over 11,335 tests), and picking one would attribute a kill to whichever crate sorted first; ambiguous and absent both become COULD-NOT-JUDGE with the reason named. The generator keeps emitting bare names ON PURPOSE: the report is the only authority on the key, so there is one deriver, not two.

CARRIED WITH IT: batch runs now pass `-E "test(=<name>) + ..."` built from those resolved names, so a batch executes only the tests it declares instead of all 11,335. The workspace is still BUILT (a mutation must compile in every dependent), only the run is narrowed.

VALIDATED BEFORE RE-SPENDING: seed.toml re-run under the fixed adjudicator returns GR-19 CAUGHT + self-control SURVIVED, resolution "exact 2, resolved 0, ambiguous 0, absent 0", tree restored. One test was red at baseline that run (sovereign-compute::supervisor::tests::brief_healthy_stretches_do_not_reset_the_breaker) and was excluded AND named — the load-sensitive breaker, not a regression.

OPERATOR DIRECTION 2026-09-01 THAT SHAPED THIS: adjudication runs from a `git worktree` (~/dev/wt-sabotage-gr, detached), never the live checkout. sabotage.py resolves everything from ROOT = script parent.parent, so running it from a worktree needs NO code change. Buys three things: the operator keeps working while it runs (the dirty-target refusal no longer blocks them), a SIGKILL/OOM cannot leave a mutation in tracked source (the restore is a `finally`, which hard kills skip), and a peer agent editing the same tree cannot be clobbered by the restore. Costs ~27GB for a second target dir plus one cold build.
