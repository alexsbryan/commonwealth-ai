ARM A's 0.05 HARNESS SCORE IS A CONVERGED MALFORMED TEMPLATE, NOT UNDER-TRAINING. MORE STEPS WILL NOT FIX IT. Corrects the diagnosis in findings/M2_HALO_GRADCHECK.md, which attributes the parse failure to "under-training at 118 of 400 steps" and names format convergence as something more steps would deliver.

Established 2026-08-03 by reading the artifacts, not by re-running anything.

WHAT THE MODEL ACTUALLY EMITS. Every response has the identical shape:
  <answer>HALLUCINATED_INTRINSIC</justification>The document states...
It opens <answer>, skips <classification> ENTIRELY, emits the bare verdict, then closes </classification>. It does this on 2,185 of 2,200 items. A model wandering toward a format produces varied malformations; a model emitting ONE deterministic wrong template has CONVERGED. Training cannot be expected to un-converge it by continuing.

THE THREE THINGS THAT ARE NOT THE CAUSE, each checked rather than assumed:
  * The data is clean. All 74,674 chosen fields in data/orpo-76k/train.jsonl contain every one of <answer>, <classification>, </classification>, <justification>. 1,997/2,000 sampled continue from </think> with exactly "</think>\n\n<answer>\n  <classification>".
  * The prompts match. eval_grounding.build_prompt emits the same json.dumps({"instructions": [...], "document":..., "claim":...}) structure as the training prompt field, instruction lines byte-identical.
  * The think prefix matches. The chat template's enable_thinking=False branch injects "<think>\n\n</think>\n\n", which is the exact prefix the targets continue from. (It injects an EMPTY think block where training always had a full one -- that is the remaining off-distribution candidate, and it is untested.)

THE SCORE GAP IS A RULER FITTED TO THE CONTROL. From the two summary.json parse blocks:
  base    failures_strict 1859   failures_tolerant   57   rescued 1802   tolerant macro 53.19
  arm A   failures_strict 2186   failures_tolerant 2185   rescued    1   tolerant macro  0.05
The tolerant parser (CLASSIFICATION_TAG_RE) requires an OPENING <classification>. Its own comment block enumerates the failure modes it was built to forgive -- all of them the BASE model's. Arm A invented a new one, so the tolerant path rescues 82% of the control and 0.05% of the arm. The 0.05-vs-53.19 gap is mostly parser fit, not model quality: under the same permissive regex applied to both (diagnose_verdicts.py) arm A is +13.96 macro BAcc over base.

THE FIX IS STRUCTURAL, NOT MORE TRAINING (ARCH_PRINCIPLES 7.6). Added ANSWER_GBNF + --grammar to eval_grounding.py: llama-server constrains decoding to the answer schema, so ANY checkpoint emits parseable output. Widening the tolerant parser instead would mean re-fitting the ruler to every future checkpoint's novel malformation -- and a parser that has to be re-fitted per arm cannot compare arms. UNVERIFIED: the grammar has not been run against llama-server yet (no gbnf validator binary on this box; /usr/bin has llama-* but no llama-gbnf-validator). The decisive cheap test is scoring arm A's existing adapter with --grammar on a subset: if BAcc lands near the 68.75 diagnostic with 0 parse failures, the shipping gate is cleared at 118 steps and format convergence stops being a reason to train longer.
