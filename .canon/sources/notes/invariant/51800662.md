# A DEFERRAL ESTIMATE IS ONLY AS GOOD AS THE DESIGN IT PRICED — and the DEFAULTS_LEDGER row for [node] entry (terminal address-keying, order…

A DEFERRAL ESTIMATE IS ONLY AS GOOD AS THE DESIGN IT PRICED — and the DEFAULTS_LEDGER row for `[node] entry` (terminal address-keying, order tn-1-terminal-honesty D5) priced one nobody had to build.

The row deferred per-turn resolution because it "requires a provider type wrapping SplitInferenceProvider", and InferenceProvider carries 27 methods of which 24 are defaulted — including an embed_batch whose default is the per-item loop that once made corpus ingest embed-bound. A wrapper that omits one silently inherits it. All TRUE, and the refusal was correct FOR THAT DESIGN. But `self.endpoint` is read at only 7 sites inside RemoteApiProvider (oicp-client/src/lib.rs: /embeddings x2, /chat/completions x3, daemon_root, warmup_url). Putting the indirection THERE — EndpointRef::{Static,Dynamic} behind an EndpointResolver trait — leaves SplitInferenceProvider with every override intact BY CONSTRUCTION. No wrapper exists, so no default can be inherited. Landed 2026-08-31, lint --full exit 0.

LESSON TO CARRY: when a ledger row says "deferred because the fix is expensive", check whether the price is of the CHEAPEST design or of the first one imagined. The two designs here differed by roughly an order of magnitude in risk and the row recorded only one.

THE FAILURE THE ROW DID NOT SEE. It listed address-keying costs as (a) a moved DHCP lease and (b) no multi-homed candidate chain. There was a third and it was fatal: an ENCRYPTED mesh forces its plaintext client API loopback-only (sovereign-mesh/src/daemon.rs:2718) and routes peers over the iroh acceptor, so a terminal bound to a literal http://host:9741/v1 could reach its entry node NOT AT ALL. Terminals were unreachable on the posture this fleet actually runs, and nobody knew because every test was co-located over loopback. All three were consequences of bypassing PeerTransport; resolving through PeerEndpointSource fixed all three at once.

A SECOND INVERSION ARRIVED WITH THE FIX AND WOULD HAVE BEEN SILENT. serving_locus() derived ForwardsOnBox/ForwardsOffBox by string-matching the endpoint host for loopback (endpoint_is_loopback). A mesh-resolved binding on an encrypted mesh IS an iroh bridge at 127.0.0.1:<ephemeral> whose far end is another machine — so the string test would have answered ForwardsOnBox and started HONOURING local_only for turns leaving the host. Exactly the privacy inversion ServingLocus was introduced to prevent, arriving through the fix for something unrelated. serving_locus is now a STORED fact set by whoever builds the provider (the party that knows), never re-derived from the address. RULE: any future provider whose endpoint is RESOLVED rather than typed must be told its locus explicitly.
