A LONG-RUNNING JOB MUST NOT LIVE IN THE COMPONENT THAT RENDERS IT, AND "NO EVENT" IS NOT A STATE. Found 2026-08-31 by driving the desktop deep-research surface with Playwright (not by reading it — the reproduction is what named the bugs).

THE REPRODUCTION. Start a run, emit round 2, click "Back to chat", let the backend advance to round 3, return. Result before the fix: an EMPTY COMPOSER. `DeepResearchView` is mounted under `{#if view === "deep_research"}`, held the entire run in component `$state`, and attached its own `listen()` in `onMount`. Navigating away unmounted it, ran `unlisten()`, and dropped round, gaps, budget and the question — while the tokio task kept driving the run. `report_ready` then fired into a torn-down listener, so a report that finished while the operator was in chat was never surfaced AT ALL. Note the contrast in the same file: `InnerWorkSurface` is deliberately kept alive with CSS show/hide because its mount is expensive. The longest-lived surface in the app was the one that got destroyed.

THE §18.3 HALF, which was worse than the UX gap. `dr_list_runs` did `manifest.map(terminal_state).unwrap_or_else(|| "interrupted")`. A live run has no `manifest.json` yet, so the shelf rendered the run that was CURRENTLY TURNING as `interrupted` — with a Resume button beside it, and `dr_start(resume_run_id)` had no liveness guard. Pressing it would hand `prepare_resume` a run dir another task was mid-write on. Absence defaulted into a terminal state, and the default was load-bearing on a data-corruption path.

THE FIX, and the shape to reuse. (1) `LIVE_RUNS` — one registry keyed by run id, already implied by the old `ABORTS` map, now the ONE decider for "is this alive": the shelf's `live` flag, `dr_active_runs`, the resume guard and `dr_abort` all read it (§8). `terminal_state` became `Option<String>`; `runStateLabel(live, terminal_state)` names the pair, and "interrupted" is now only said when there is genuinely no manifest AND nobody driving. (2) The run moved to `stores/deepResearch.svelte.ts` at module scope — same shape `corpusProgress.svelte.ts` already used for long installs (§19: the pattern existed, it just had not been applied here).

"NO EVENT" IS NOT A STATE — the part most likely to recur elsewhere. `emit_if_changed` is deliberately quiet, and a deep-research round spends MINUTES inside one model call with nothing on disk moving. So silence on that channel is the normal case, and any surface built only from change events renders a healthy run and a wedged one as the same frozen panel. Two verdicts (running / not running) cannot express the difference. The backend now emits a `heartbeat` every poll tick carrying `elapsed_secs` and `quiet_secs`; the store turns it into four verdicts — starting / working / quiet / no-signal. The load-bearing detail: `no-signal` is detected by a LOCAL clock (age of the last beat we received), because a backend that has gone away cannot report that it has gone away. Correspondingly the elapsed clock is the BACKEND's number and is not extrapolated locally — a local timer keeps counting confidently past the moment the run died, which is exactly the lie being removed.

ALSO ENCODED STRUCTURALLY: one run at a time (the desktop can represent one, so `dr_start` refuses a second rather than orphaning the first), and `WindowEvent::CloseRequested` prevents the close while a run is live and hands the decision to the frontend — closing the app was the last remaining way for a run to end that the operator did not choose.

Proof: `tests/e2e/specs/deep-research-continuity.spec.ts` (24 Playwright tests) + `src/lib/stores/deepResearch.test.ts` (11 unit tests over the pure deciders).
