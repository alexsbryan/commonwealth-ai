`cargo clean` DESTROYS COMPLETED DESKTOP RELEASE LEGS — THE DESKTOP PIPELINE STORES SIGNED DELIVERABLES IN CARGO'S SCRATCH DIR (observed live 2026-07-30, cost ~2h of verified mac build mid-release of v0.4.0).

WHAT HAPPENED. Both mac desktop legs for desktop-v0.4.0 built, signed, and payload-verified. The container legs were deferred ~8h for memory reasons. The operator then ran `cargo clean`. Both `.dmg`s, both `.app.tar.gz`, and both `.sig`s were gone; `target/` was recreated empty.

CARGO IS NOT AT FAULT. `target/` is cargo's scratch space by contract. The defect is ours.

THE ASYMMETRY THAT HID IT — MEASURED:
- `release-cli-local.sh` stages every target into `dist/sovereign-<triple>/`. Its three tarballs SURVIVED the same clean.
- `release-desktop-local.sh` references `dist/` ZERO times (grep -c). MAC_ARM/MAC_X64 point straight at `target/<triple>/release/bundle`; it verifies and uploads IN PLACE.
- LINUX/WINDOWS point at `target-container-{linux,windows}` — a different CARGO_TARGET_DIR that `cargo clean` does NOT touch. 2 of 4 legs are protected BY ACCIDENT, which is why this never surfaced.

THREE COMPOUNDING FACTORS:
1. `--upload-only` is documented as "verify + upload what's on disk" — a durability promise the storage location cannot keep.
2. `scripts/build-bench.sh` runs a bare `cargo clean` programmatically (workspace-cold scenario), so this can fire with nobody typing it.
3. The parity guard `(( MISSING )) && die` requires all four legs to coexist on disk at once, so the longer a multi-leg release takes the wider the window. Ours was ~8h.

THE FIX (not applied yet — two release runs were live, and editing a running bash script is unsafe: bash reads it lazily by byte offset): stage each leg's outputs into `dist/desktop/` immediately after that leg builds, mirroring the CLI's `package()`; verify + upload from `dist/`.

RULE. A signed, verified, shippable artifact must never live ONLY inside a directory a routine dev command is entitled to delete. Stage it out of `target/` the moment it exists.

RELATED SELF-INFLICTED SIDE EFFECT, same session: reclaiming `target/debug` (79GB, for release disk headroom) DELETED the binary behind `~/.local/bin/sovereign`, so the `sovereign` CLI verb vanished mid-session. Repair: `cargo build -p sovereign-cli --features dev-tools -p sovereign-cli-dev -p sovereign-cli-daemon -p sovereign-cli-llm` then re-link. Same root shape: a tool users depend on pointed into cargo scratch.
