# Order is load-bearing in EmbeddedDaemon::start_daemon — Arc::get_mut fails silently and breaks /v1/chat/completions

Order is load-bearing in EmbeddedDaemon::start_daemon — Arc::get_mut fails silently and breaks /v1/chat/completions

`commonwealth_api::state::AppState::with_local_inference` and `with_mesh_mutation_hook` mutate `AppStateInner` through `Arc::get_mut`. `get_mut` returns `None` the moment any other code holds an Arc reference to `inner`, and the installers bail with a tracing warning instead of panicking.

In `sovereign-mesh::EmbeddedDaemon::start_daemon`, two operations clone the inner Arc:
- `AppStateYieldHook::new(app_state.inner.clone())` — for the corpus-engine YieldHook
- `app_state.inner.inference_store.set_local_embed_model(...)` — bumps the strong count via the field access path

Both must run AFTER all `with_*` installers, not before.

Why: if `with_local_inference` fails, `/v1/chat/completions` falls through from Priority 0 (local in-process) to the orchestrator/llama-server path, which 503s with `model_not_ready` because the embedded daemon doesn't run llama-server processes. Every chat request fails until the daemon is rebuilt with the right order. I lost an hour on this debugging an OCR cleanup pipeline (2026-04-28) — the symptom was OCR cleanup HTTP calls returning `model_not_ready`, but the root cause was upstream of OCR entirely.

How to apply:
- When adding a new `with_*` installer to `AppState`, place it BEFORE the YieldHook/embed-model blocks in `daemon.rs::start_daemon`.
- When changing the order of operations in `start_daemon`, grep for `inner.clone()` and `inference_store.` field accesses and make sure no `with_*` runs after them.
- The warnings in `state.rs` are now `tracing::error!` (not warn) and include `strong_count` plus a remediation hint, so the next regression is louder.
- The structural fix (move state to interior-mutable cells so installers don't need `Arc::get_mut`) is a bigger refactor; leave it for a focused PR if this trap is hit again.
