`svrn code index` PICKS FULL-REBUILD FROM A COUNT OF *ALL* CHANGED FILES, NOT INDEXABLE ONES — so a merge that brings mostly DATA triggers an hours-long full re-embed to refresh a few hundred source files. Pass `--incremental` explicitly after any large merge.

MEASURED 2026-09-04 on commonwealth-ai. After merging 21 commits from origin:

    files changed since the index head (47aac21f)   6,476
      of those, source (.rs/.py/.ts/.md/.toml)        850
      brought by the merge alone                    6,424   <- bench baselines, JSONL, fixtures

The tool printed "Full rebuild — 6476 files changed since commit 47aac21f — past
the 500-file mark a rebuild is usually faster (pass --incremental to refresh
them one by one anyway). Every chunk will be re-embedded; this is the slow
path." It then ran 80+ minutes and embedded 71k+ chunks over 79k docs, to
refresh 850 source files. The >500 threshold is a reasonable heuristic against
the WRONG NUMERATOR.

TWO THINGS THAT MAKE THIS CHEAPER TO DIAGNOSE NEXT TIME:

1. THE SCIP GRAPH FINISHES LONG BEFORE THE JOB DOES, and the SCIP graph is what
   the code-intel tools and `scripts/nc-boundary.py` actually read
   (`~/.svrnmesh/indexes/<corpus>/scip_graph.db`). Here it was written at ~51
   minutes; the remaining ~29 was pure Lance chunk re-embedding for semantic
   search. So `ls -la` that file's mtime, and run `python3
   scripts/nc-boundary.py` — its banner names the commit the graph describes.
   If it is current, the rest of the job buys only `code_search` freshness and
   can be stopped.

2. KILLING IT MID-EMBED IS SAFE. Verified: `symbols` kept working and returned
   symbols from commits made that day, and `code_search` returned results with
   its own "Index: aging" banner rather than failing. The rebuild preserves
   scip_graph.db, code_index_state.json and the locks (it lists them as
   "Preserved N entries not owned by the ingest"), and the pre-existing
   `.rebuild.lock` was untouched. No corruption, no new lock.

DO NOT read a `code_search` miss on a symbol minted TODAY as index damage —
an aging chunk index missing today's symbols is the documented behaviour, and
its banner says so. Check an OLD stable symbol before concluding anything.
