# A diagnostic sim arm MUST assert its own wiring before it prints an outcome. A null result is only informative if the knob is proven…

A diagnostic sim arm MUST assert its own wiring before it prints an outcome. A null result is only informative if the knob is proven connected — otherwise "nothing moved" and "nothing was flipped" render identically and you cannot tell which you got.

Both arms added 2026-07-26 follow this shape in tests/mesh_sim_scoreboard.rs:
- Arm::WarmStart asserts (i) arm 0 DOES apply a cold-start penalty somewhere (`any(w < 0.99)`) and (ii) warm-start removes it everywhere (`all(w == 1.0)`).
- Arm::OutboundOnlyLoad asserts the summed published in-flight actually SHRINKS vs arm 0 — otherwise a flat table means "this fleet never served inbound work", not "inbound attribution doesn't matter".

Only then does the test print the latency/offload/share table. Outcome stays REPORTED not asserted (a metric with an unagreed threshold is a flaky test); the wiring check is the part that is genuinely true-or-broken.

Same family as the S0 lesson that a scoreboard denominator must be the set a policy COULD have chosen among.
