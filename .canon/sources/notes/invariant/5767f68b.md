Measured 2026-08-31, corpus 5,170 types (967 enum + 4,203 struct), all with births. Scripts: scratchpad/group_recall.py (E2), clean_test.py (E3). K=10, leave-one-out over known concept groups.

E2 used truth_shape_groups.json (117 groups / 301 members) and gave:
  atemporal  RAW 91.0% (274/301)  ENRICHED 77.1% (232/301)
That reads as "raw wins by 42 items, enrichment is unnecessary". IT IS A CONFOUND. The shape groups are OUTPUT OF THE SHAPE DETECTOR, which matches on overlapping FIELD NAMES; the raw arm embeds declarations, which ARE field names and types. The measurement is largely the detector agreeing with an embedding of its own input.

E3 removes both free rides — ground truth = the 33 NAME groups (independent of shape by construction: "converge shape never compares a name"), and the type name is REDACTED from both arms (19% of summaries contained their own type name):
  NAME groups   atemporal  RAW 59.3% (51/86)   ENRICHED 60.5% (52/86)
  NAME groups   temporal   RAW 55.4% (31/56)   ENRICHED 62.5% (35/56)
  SHAPE groups  atemporal  RAW 94.7%           ENRICHED 70.8%     <- confound persists, and raw IMPROVES when names are stripped, which confirms the mechanism

CONCLUSIONS
1. Retire the 91% as evidence about raw's quality. Never evaluate a detector against ground truth produced by a detector that shares its input representation.
2. On independent ground truth the arms invert: enriched >= raw, and enriched wins the TEMPORAL (write-time / sprawl-prevention) condition by 4 items of 56.
3. True recall for "same concept, different name" is ~60% at K=10, not ~90%. Adequate for WARN, nowhere near a gate — consistent with the standing warn-before-gate decision.
4. Consistent with the independent `svrn code refactor label --model --score` result on the name axis: 10/13 agreed, precision 0.769, ZERO false converges (the costly error), abstention 0.000.

CAVEAT: n=86 atemporal / 56 temporal. Better than the 47/27 that blocked earlier reads, still small. The shape groups cannot be used to fix that — they are confounded for this question.
