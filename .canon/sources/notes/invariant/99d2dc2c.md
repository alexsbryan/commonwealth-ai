# AN INSTRUMENT THAT DIES AT IMPORT REPORTS NO ABSENCE AT ALL — the portability variant of the §18.3 trap.

AN INSTRUMENT THAT DIES AT IMPORT REPORTS NO ABSENCE AT ALL — the portability variant of the §18.3 trap.

2026-08-11, order native-grounding-flip-soak. scripts/flip-soak-verify.py used a nested same-quoted f-string:
  f"{'n/a' if x is None else f'{x:.3f}'}"
That is PEP 701, Python 3.12+ only. Under launchd `python3` resolves to /usr/bin/python3 = Xcode's 3.9.6 on macOS, NOT the 3.13 an interactive shell gets. SyntaxError at import: the verifier printed nothing. A 2h soak could have completed and reported literally zero lines.

WHY THIS IS ITS OWN LESSON, distinct from the daemonRssMb note (50428602): that one is about code that RUNS and reports a misleading value. This is about code that never runs at all. §18.3 discipline aimed at what code REPORTS says nothing about whether it EXECUTES where it lands, and a script that dies at import is strictly worse than one returning a bad number — there is no output to be suspicious of.

THE RULE: a script launched by anything other than your own shell (launchd, cron, CI, systemd, a wrapper) meets a DIFFERENT interpreter and a DIFFERENT PATH. Test with the interpreter it will actually meet:
  /usr/bin/python3 -m py_compile <script>     # the real 3.9 on macOS
Don't reason about version numbers; run the binary. And parse is not run — execute BOTH branches of any conditional formatting, because the branch that crashes is rarely the one you spot-check. Here the "n/a" path worked and the numeric .format path was the broken one.

ALSO EXTRACT AND PARSE INLINE HEREDOC PYTHON (`python3 - <<'PY'`) inside shell scripts — it is a third hiding place that py_compile on the .py files will not cover.

STRUCTURAL FIX for the whole class (flip-soak-run.sh): log which python3/cargo/node resolved (path AND version) at startup, and refuse early BY NAME if any is missing. Otherwise a bare launchd env surfaces minutes later as a failed build or as phases that spawn nothing, which reads as a PRODUCT failure rather than a launcher misconfiguration — a misreading that must never reach a report. Verify such a guard by reproducing the env (`env -i PATH=/usr/bin:/bin bash script.sh`), not by inspecting it.
