DESKTOP-SMOKE ON MACOS: TWO BUGS, ONE DESTRUCTIVE (found + fixed 2026-07-28, verified live on darwin).

(1) scripts/desktop-smoke.sh HAD NEVER RUN ON MACOS AT ALL. run_capped() was a bare `timeout --preserve-status`, and GNU coreutils timeout does not exist on darwin — so EVERY phase exited 127. Worst instance: stop_resident_daemon does `run_capped 60 sovereign daemon stop || true`, so the stop silently never ran, then the 60s port poll blamed the daemon ("still answering"). One missing binary, two misleading symptoms. Fixed: resolve timeout/gtimeout/bash-fallback once into TIMEOUT_BIN, announce it in the start banner. The fallback is bash-3.2 safe (macOS ships 3.2.57) — backgrounds, polls, TERM then KILL, returns 124 on kill else the child status. Unit-checked: 124@3s / 0 / 1 / 42 passthrough.

(2) DESTRUCTIVE: restore_resident_daemon calls ensure_config_primary "$TARGET_PRIMARY", which REWRITES the operator live ~/.svrnmesh/config.toml primary= line. TARGET_PRIMARY defaults to SHIPPED_PRIMARY = sovereign/models/Qwen3.6-35B-A3B-MTP-UD-Q6_K.gguf, which is NOT PRESENT on this mac. Result: the smoke points the daemon at a missing GGUF, the VRAM preflight stats it, the error underflows the size to ~i64::MAX MiB ("required: 9223372036854783653 MiB"), the gate rejects the whole config, and the daemon will not start AT ALL. The box is left with no daemon and the operator sees only "resident daemon didn t return". Fixed: ensure_config_primary now REFUSES a path that does not exist and leaves the existing primary alone. Note phase 6 only reaches restore on non-netns hosts, so the guard covers the exposed case.

(3) wizard-verify.sh IS NOW MAC-COMPATIBLE — 12/12 pass on darwin. Isolation: netns on Linux, CHECKED-FREE PORTS elsewhere (refuses to start unless :9741 and :9745 are free; WIZARD_VERIFY_NO_NETNS=1 forces that path on Linux too). Process identity no longer uses /proc/<pid>/environ — macOS `ps -E` DOES NOT expose another process env (SIP, verified empirically), so it uses a pre-run pgrep snapshot (anything new is ours) plus `ps -o command=` and a NEW assertion that ppid(daemon-child) == the relaunched instance, which is strictly stronger than the old co-existence check. Its default GGUF paths were also stale ($REPO_ROOT/models/... instead of sovereign/models/...) so it exited 2 on every host — now first-existing-of.

(4) PRE-EXISTING LANDMINE, NOT OURS: ~/.svrnmesh/config.toml had [shared_model] role = "anchor" (set 2026-07-27 for the distributed knockout) with NO [compute] section, which a guard added 2026-07-27/28 now hard-refuses ("shared-model HOST but the DISTRIBUTED primary would run IN-PROCESS"). The resident daemon predated that guard and had primary resident=false, so it ran fine and could never have restarted. Operator chose role = "consumer" (what the config own comment prescribes for daily-driver). Also: sovereign/models/Qwen3.6-35B-A3B-MTP-UD-Q6_K_XL.gguf is a DANGLING symlink (HF blob evicted); IQ4_NL resolves.

GENERAL LESSON: a long-lived process can be surviving only because nothing has restarted it. Stopping it is how you discover the config no longer boots.
