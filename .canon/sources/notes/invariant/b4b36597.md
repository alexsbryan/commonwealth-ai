PHASE 2 LANDED SHAPE — EmbeddedDaemon (conv-2, 2026-08-24). Banked BY THE SEAT on conv-2's behalf: its own note writes failed twice against a daemon returning 503 "host busy, ~30000ms predicted wait". Note 258e5319 is the MEASUREMENT (the pair-independence matrix); this is the LANDED SHAPE and the set of things that must not be silently undone.

THE ONE TOTAL CONSTRUCTOR:
  EmbeddedDaemon::new(data_dir, setup_config, services) -> Arc<Self>
was `new(data_dir) -> Self` plus 10 `set_*` and 7 `install_*_router` methods called after construction. 22 fields -> 10. 17 RwLock<Option<T>> -> 2. ZERO set_* / install_*_router remain anywhere in the tree.

THE TWO SURVIVING OPTIONS ARE NOT HOST-SETTABLE — both are derived from the variant: the serving InferenceProvider (swapped only by admin/reload) and, inside the variants, the named-absence types McpSurface / EmbedAdvertisement, whose absence is a disk or probe failure CARRYING ITS REASON rather than a hole (§18.3). SetupConfig stopped being optional entirely: SetupConfig::unconfigured() is byte-identical to the fallbacks the None arm applied, so "no config" was never a distinct state, only an unnamed one.

DaemonServices = MeshAdmin | Desktop | Headless, composed in CONCENTRIC RINGS by what absence costs:
  ServingCore        engine + provider            (absence = cannot serve)
  ServingCapability  mcp + project_http + corpus_watch_http   (absence = can do less)
  ServingProfile.advertise_embed                  (policy)
  HeadlessRails      provider_factory + mesh_store + convergence_recorder  (absence = a surface reports something untrue)
Every field is REQUIRED in the variant that has it.

MUST NOT BE UNDONE:
1. Three of the seven routers — mesh, admin, reading — are pure functions of Arc<EmbeddedDaemon>, so the daemon builds its OWN from a Weak<Self> via Arc::new_cyclic. No host installs them, therefore no host can differ on them. The measured router delta dissolves as a CONSEQUENCE, not as a fix. Re-adding a host-side installer for any of these three reopens the whole hazard.
2. SetupConfig::unconfigured() is deliberately NOT `impl Default`, so `load().unwrap_or_default()` cannot silently substitute for a config that exists but will not parse (§18.3).
3. McpSurface / EmbedAdvertisement carry a reason. Do not collapse them back to bare Option.
4. DeferredDaemon is the ONLY late binding left in the assembly. The inference wiring is genuinely cyclic on BOTH serving hosts (the daemon serves peers through a MeshInferenceProvider that routes through the daemon). DeferredDaemon breaks it, carries NO capability, and before bind answers exactly as a constructed-but-stopped daemon did. It is a named handle, not a hole — keep it that way.
5. tests/daemon_variant_census.rs (3 tests) is the differential falsifier and was WATCHED TO FAIL on real inputs before being kept (a variant nothing constructs; a site naming the wrong variant; a reinstated set_corpus_engine). Per principle 5, a gate never watched to fail is not a gate — do not "simplify" these into shape assertions.

SIGNATURE CHANGES A REVIEWER WILL HIT: EmbeddedDaemon::new 1 arg -> 3 and now returns Arc<Self>; WatchedSubsystem::install lost its `daemon` parameter (5 args -> 4).

THE LIVE SHIPPED BUG THIS FOUND — the highest-value finding of Phase 2, and it was NOT a topology. The desktop's `cli_setup_wiring` gate (state.rs) keyed the ENTIRE HTTP surface on the ConfigSource snapshot taken by bootstrap::detect() at app start. The wizard writes config.toml AFTER that probe and then calls state::bootstrap with the mode still reading Fresh. So on the in-process completion path (maybe_restart_into_supervised returns false: harness, kill switch, or spawn failure) the desktop came up with an engine, a provider, and NO /v1/mesh/*, NO /mcp, and NO registered model slots. bootstrap hard-requires SetupConfig::load(), so a config is on disk on every path that reaches there — collapsing the gate is what made the constructor total. It presented as a fourth column in the variant matrix and was a stale-snapshot bug.

BANKED FOR PHASE 3 (the two serving shapes CROSS rather than nest, and this is the crossing): the desktop mounts /v1/admin/reload while carrying no ProviderFactory, so a models.* reload always fails — it now refuses by NAMING the profile rather than reporting a missing installation; and the CLI daemon still has no state_store while mounting the reading surface, so conversation-history chunks render title-less on a headless daemon. Phase 3 closes the second by giving the daemon the store, after which the lattice nests properly.
