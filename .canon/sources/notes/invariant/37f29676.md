# NER incremental delta must mark chunks PROCESSED (entities or not) via chunk_ner_processed — deriving \"done\" from chunk_entities…

NER incremental delta must mark chunks PROCESSED (entities or not) via chunk_ner_processed — deriving \"done\" from chunk_entities membership re-grinds entity-less chunks forever

The GliNER incremental delta (`GlinerChunkExtractor::extract_delta_for_corpus`,
sovereign-tools/src/conv_tiered_provider.rs) computes "already processed" as the
set of chunk ids present in `chunk_entities`. **But a chunk GliNER finds NO
entities in writes no `chunk_entities` row** (the per-chunk loop only pushes rows
for chunks with mentions). So every entity-less chunk — headers, code blocks,
tables, short lines — looked unprocessed forever, stayed in the delta on every
pass, and was re-NER'd on every boot. On a real vault this was ~11% of chunks
(711/6176 for the Obsidian vault): the phase pinned 2+ cores indefinitely,
`chunk_entities` count never moved, and enrichment never converged past NER.

Fix (2026-07-16): dedicated marker table `chunk_ner_processed (corpus_id,
chunk_id, PK)` written after each note's batch for ALL delta chunk ids —
entities or not — via `record_ner_processed_chunks`. The delta's "already" set
is now `list_ner_processed_chunk_ids` = `chunk_entities.chunk_id UNION
chunk_ner_processed.chunk_id`. The union means corpora enriched before the marker
existed still recognise their entity-bearing chunks (no full re-run); only the
entity-less tail is processed once more, then marked, and the delta converges to
0. The marker table is NEVER read by entity aggregation / subgraph queries, so it
can't leak into the entity views — that's why a sentinel row in `chunk_entities`
was rejected (7 read sites would each need a filter).

INVARIANT: any incremental extraction whose output is sparse (not every input
produces a row) must track "processed" independently of "produced output", or it
re-does the empty inputs forever. Same class as the RAPTOR shared-slot bug — see
[[project_skip_already_built_per_note_checkpoint_2026_07_16]]. Test:
`ner_processed_marker_makes_empty_chunks_converge` in store_tests.rs.
