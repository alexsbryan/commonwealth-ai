MULTI-SHARD GGUF: THE HOST ONLY ADVERTISES SHARD 1, SO A WORKER THAT DOES NOT ALREADY HOLD EVERY SHARD CANNOT BE WARMED (found 2026-07-31 while sizing DeepSeek-V4-Flash-0731, a 5-shard 155GB GGUF).

The 2026-07-19 split-GGUF work (DISTRIBUTED_PILOT_READINESS.md:81-104) made the distribution/warm plane genuinely split-aware: total_model_bytes (model_slot.rs:49) sums siblings; tensor_sizes (rpc_warm_cache.rs:404) concatenates every shard's tensor table; build_manifest (:360) carries per-entry `file` + file-relative gguf_offset; warm_cache_from_ranges (rpc_warm_http.rs:279) routes each tensor to file_urls[file_idx]; resolve_whole_gguf (:434) walks split_sibling_names.

THE BREAK: the servable-file allowlist is installed in exactly ONE place — register_local_model_slots, sovereign-mesh/src/daemon.rs:3438-3451 — from the configured slot paths, with NO sibling expansion. Config names only `...-00001-of-0000N.gguf`, so that is the only file serve_model_file (model_files.rs:246-270) will serve; shards 2..N 404. Whole-GGUF mode (the DEFAULT — byte_range_mode() rpc_warm_http.rs:673 is false unless SOVEREIGN_RPC_SHARD_FETCH=ranges) fails with FetchError::NotAdvertised; range mode fails "range GET failed on all sources" (:349). Failure is never-wedge safe (falls back to local-only), NOT corruption — which is why it is silent, and why for a model that only fits distributed it presents as "won't load".

WHY IT WAS NEVER CAUGHT: every prior acceptance ran with all shards already on every node's disk. No test covers the host serving a sibling shard, and none covers build_manifest across shards.

FIX: expand each slot path through shard_files / split_sibling_names before install_servable_model_files.

RELATED SHARP EDGES FOUND IN THE SAME SWEEP: (1) shard_files (rpc_warm_cache.rs:317-349) detects splits by FILENAME convention only — nothing in the repo reads split.count / split.no / split.tensors.count — and on a missing sibling it silently returns [path], so `svrn mesh plan` will confidently report a ~5x-too-small model with no warning (mesh_cmd.rs:816-836 prints no shard count). (2) The name-parsing logic is duplicated 3x and can drift: model_slot.rs:59-67, rpc_warm_cache.rs:326-333, rpc_warm_http.rs:111-118. (3) estimate_slot_vram (capacity.rs:96) and GgufExpectation::from_size_gb (gguf_validator.rs:76) still read shard 1 only — the latter can reject a split download as TooSmall at setup.
