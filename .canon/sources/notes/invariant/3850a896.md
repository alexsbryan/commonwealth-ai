# A NEW LITERAL tracing TARGET MUST BE ADDED TO DAEMON_TRACING_FILTER IN THE SAME COMMIT, OR THE WHOLE SUBSYSTEM IS DARK IN THE DEPLOYED…

A NEW LITERAL `tracing` TARGET MUST BE ADDED TO `DAEMON_TRACING_FILTER` IN THE SAME COMMIT, OR THE WHOLE SUBSYSTEM IS DARK IN THE DEPLOYED DAEMON — INCLUDING ITS `warn!` PATHS. Instance FIVE, found 2026-08-05.

THE TRAP: `DAEMON_TRACING_FILTER` (`sovereign-cli-daemon/src/lib.rs`) is an ALLOWLIST built with `EnvFilter::new`, which sets an ERROR default for unmatched targets. An event emitted with `target: "foo"` is matched on the LITERAL STRING `foo`, NOT on the module path — so `sovereign_cli_daemon=info` does NOT catch it even when the code lives in that crate. Unlisted means dropped at ERROR: not just debug detail, but every `info!` AND every `warn!`.

WHAT IT COST THIS TIME: the self-healing corpus-maintenance sweep shipped in 92602386 emitting everything under `target: "corpus_maintenance"`, unlisted. In the deployed daemon that meant `sweep armed`, `sweep: maintenance complete`, `sweep: open_index failed` (warn) and `sweep: maintenance failed` (warn) were ALL dropped. A sweep that never ran, one panicking on every corpus, and a perfectly healthy one produced byte-identical logs. This defeats the `spawn_supervised` rationale one layer up: supervision restarts a panic, but nothing surfaces a loop that silently stops ticking.

HOW IT WAS CAUGHT — and why the ARCH §18.1 rule earned its keep: restarting the daemon and WATCHING for the arm line that never came. It had been observed working minutes earlier only because that run set `RUST_LOG=info,corpus_maintenance=debug` explicitly, which overrides the whole filter. Testing observability with RUST_LOG set is testing a configuration no user runs — the launchd plist (`~/Library/LaunchAgents/com.svrnmesh.daemon.plist`) sets NO `RUST_LOG`.

THE FIX: `corpus_maintenance=info` added to the constant, plus BOTH pinning tests extended — `daemon_filter_lists_grounding_targets` (string) and `daemon_filter_enables_custom_target_events` (behavioural, and now probes a `warn!` as well as an `info!`, because "listed" must also mean "its warnings arrive").
