Delta-produced chunks MUST carry doc identity (corpus-engine update/delta.rs stamp_doc_identity, 2026-06-10): CorpusEngine::chunk_document is document-agnostic (source_doc_id=None, title=None), so the delta phases stamp source_doc_id=doc_id (+file-stem title fallback) on every updated/added chunk, and phase_updates is DELETE-FIRST (delete old rows by doc id, then insert) — the old insert-then-delete order would delete the fresh rows now that they share the doc id. Resume-safe: progress log commits after both ops. Without the stamp: every second edit of a vault note duplicated its chunks (delete filter matched nothing), the vault preview/write-back lost the note (keyed on title), and the chunks dropped out of tiered retrieval (tiered_group_key requires source_doc_id). Related: local_corpus extract_stage staged ids are now ROOT-RELATIVE PATHS not basenames (sweep tombstone deletes key on relative paths; nested notes never matched before). Existing corpora with nested notes heal on re-ingest. Pinned by obsidian_live_sync_e2e::vault_writeback_round_trip_via_worker.
