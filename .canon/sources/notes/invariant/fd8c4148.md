# Daemon death update 2026-05-12 PM: rapid file edits to Rust source trigger the LintWatcher+TestWatcher to queue overlapping cargo check…

Daemon death update 2026-05-12 PM: rapid file edits to Rust source trigger the LintWatcher+TestWatcher to queue overlapping cargo check reruns (each ~60s on full workspace). Empirical observation: 4 queued reruns in 25s of edit activity → daemon shutdown at 20:16:47 with clean SIGTERM signature (no panic, no overflow). Hypothesis: macOS sends SIGTERM under memory pressure when cargo recompilation thrashes RAM. Mitigation: when iterating heavily on .rs files, either (a) point SOVEREIGN_WORKSPACE_DIR somewhere else temporarily, (b) batch edits per session, (c) accept the daemon will need periodic restart. Trace-capture works for crash deaths (panic hook in main.rs:385); SIGTERM-from-pressure deaths are graceful so no crash trace is the right behavior. The remaining unknown is whether memory pressure is the cause or if there's a self-shutdown trigger we haven't found.
