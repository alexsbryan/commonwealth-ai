# THE LINK IS PART OF A MEASUREMENT'S IDENTITY. MeasurementKey gained a sixth field, link: LinkClass (2026-07-29,…

THE LINK IS PART OF A MEASUREMENT'S IDENTITY. `MeasurementKey` gained a sixth field, `link: LinkClass` (2026-07-29, sovereign-core/src/mesh_measurements.rs). Any code that constructs a key MUST supply the link the tensor stream actually used, or the number it files is attributable to nothing.

WHY THIS WAS NOT OPTIONAL. The key was probe_version · model_fingerprint · placement_digest · host_hw_fingerprint · n_ctx. None of those changes when the *link* changes. The plan's own week-4 section records that the same 4B distributed decode read 17.35 tok/s over a forced iroh tunnel and ~40 tok/s over direct IP on the SAME two machines — a 2.3x spread from link choice alone, with identical model, identical split, identical hardware. Those two runs shared a key. `lookup` returns the latest, so whichever ran last silently answered for both. That is a larger error than most of what the other five fields guard against, and it is the only key input that can change without anything on either machine changing.

The record already carried `link_rtt_ms` as payload, so the evidence was being captured — it just wasn't keyed on, which meant it could not discriminate.

THE DESIGN, and the three decisions inside it:

1. A SIXTH KEY FIELD, NOT A FOLD INTO `placement_digest`. Folding would have kept the five-field contract but hashed the link, so a reader seeing "not measured" could not tell WHY it missed. `svrn mesh plan --from-mesh --json | jq .speed` is required to be self-explaining; `"link": "tunnel"` in the key is, a changed digest is not.

2. `LinkClass::Unknown` NEVER MATCHES, INCLUDING ANOTHER `Unknown`. `lookup` refuses it outright before touching the records. Two runs nobody could classify are not thereby the same run — treating them as equal infers an identity from a shared ABSENCE of evidence, which is the exact fabrication this module exists to prevent. `near_misses` still returns, so nothing is hidden: the reader is told what WAS measured and that the link differs.

3. ONE DECIDER, TWO CALLERS: `link_class_of_endpoint()`. `mesh bench` classifies the endpoints in the daemon's live PLACEMENT; `mesh plan --from-mesh` classifies the endpoints in the daemon's live DISCOVERY (`/v1/mesh/status` → `rpc_workers[].endpoint`, joined to members by `node_id`). Same strings, same daemon, same function. Two implementations that disagreed on one edge case would file every record under a key the reader can never reproduce — the store grows forever while the plan reports "not measured" for the configuration it just measured. This is the same producer/consumer agreement invariant as note eb592ccb, extended to the link.

THE SIGNAL. A loopback authority is the tell: discovery hands ggml either a routable `host:port` it probed successfully, or `127.0.0.1:<port>` — a proxy socket whose far end is an iroh tunnel. Nothing else legitimately presents as loopback, because a worker on this machine is not a worker, it is the host. Covers 127.0.0.0/8, `localhost`, `::1`. A bare IPv6 literal must NOT be split at its first colon (`::1` would parse to an empty host and classify Unknown instead of Tunnel) — only `[v6]:port` and single-colon `host:port` carry a port unambiguously.

THE IDLE-PEER TRAP, and why `carries_weight()` is shared. A worker apportioned no blocks and holding no output head is dropped from the digest. It must therefore also be invisible to the link — otherwise an idle TUNNELLED peer merely coming online flips a genuinely-direct run to `Tunnel` and silently invalidates every record on that machine. `shards_from_placement` and `placement_link` call the same predicate. Test: `an_idle_tunnelled_peer_does_not_change_the_link`.

SCHEMA_VERSION 1 → 2, so pre-existing records are DISCARDED rather than migrated. A v1 record does not say which link it was taken over and there is no way to recover that after the fact; defaulting them to a concrete LinkClass would assert something nobody measured. PROBE_VERSION deliberately stays at 1 — its doc scopes it to the probe protocol (prompt, token budget, timing formula, guard set), none of which changed. Using it as a generic cache-buster would make it lie about what it means.
