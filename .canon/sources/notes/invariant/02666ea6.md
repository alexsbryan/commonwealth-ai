Measured 2026-08-31. Corpus grown 967 enums -> 2,616 types (967 enum + 1,649 struct), each with a birth commit resolved against CURRENT history. Median prior pool per query: 1,930. Harness, label sets and bar UNCHANGED from temporal_replay.py (scratchpad/temporal_replay2.py).

PRE-REGISTERED BAR: recall>=60% AND false-flag<=10%, both at >=2 hits.

  RAW declaration      recall>=2  66.0% = 31/47   false-flag>=2  7.4% = 2/27   >=3  3.7% = 1/27   PASS
  ENRICHED summary     recall>=2  61.7% = 29/47   false-flag>=2  3.7% = 1/27   >=3  0.0% = 0/27   PASS

BOTH ARMS PASS. But the objective's stated exit condition is "not worth continuing if enriched-summary retrieval cannot beat the refuted raw-code baseline on temporal controls", and on RECALL it does not: raw wins by 2 items of 47. Enriched wins on precision by 1 item of 27 (and is the only arm with zero false flags at >=3).

THE DECISIVE FACT IS POWER, NOT THE CORPUS. Every difference between the arms is 1-2 items. n_pos=47, n_neg=27 — those denominators are the hand-curated FAMILY/NEG name sets and they did NOT grow when the corpus did. Growing the prior pool 2.7x moved enriched recall by exactly ONE item (28/46 = 60.9% -> 29/47 = 61.7%). The prior pool was the wrong dimension to grow.

WHAT THIS RETIRES: calling the raw-code baseline "refuted" is no longer supportable. On this corpus it is the stronger arm on recall and it clears the bar.

NEXT MOVE IF THIS REOPENS: more LABELS (positives/negatives), not more corpus. Nothing about the enriched-vs-raw question can be adjudicated at 47/27.
