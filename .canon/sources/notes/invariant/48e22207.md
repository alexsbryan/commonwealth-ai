# llama.cpp CPU embed throughput on Apple Silicon PEAKS at the performance-core count, not total cores. Going higher REGRESSES throughput.

llama.cpp CPU embed throughput on Apple Silicon PEAKS at the performance-core count, not total cores. Going higher REGRESSES throughput.

Measured on M2 Max (8P + 4E), Qwen3-Embedding-0.6B, 16 sequences × 200 tokens per batch:
  n_threads=1  → 0.44 seq/sec
  n_threads=4  → 1.63 seq/sec
  n_threads=8  → 2.83 seq/sec  ← peak (= P-core count)
  n_threads=10 → 2.76 seq/sec
  n_threads=12 → 2.41 seq/sec  ← 15% REGRESSION vs 8

The E-cores slow P-cores down via cross-cluster synchronization on SGEMM. SMT threads on x86 behave similarly — they don't help matmul.

Rule: `llama_threads_for_host()` in `sovereign-inference/src/embedded.rs` MUST clamp to `[2, 8]`. The llama-cpp-2 default of 4 under-uses; `available_parallelism()` over-uses on big.LITTLE systems. Previous fix set it to 12 and measurably hurt throughput.

Verify before changing: `cargo run --release -p sovereign-inference --example bench_embed -- --model <path> --threads 1,4,8,12 --backend cpu`.
