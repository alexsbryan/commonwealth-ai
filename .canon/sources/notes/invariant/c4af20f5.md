ONE AGENTIC LOOP TAKES A THIN PEER OFF THE MESH — CAUSATION ESTABLISHED BY REPRODUCTION, 2026-08-06 (M6-C finding C1). It fails at the SAME CALL INDEX both times.

Method: 8 sequential streaming calls for Qwen3-4B-Q4_K_M (sole holder: LittleMac, an Intel Mac), each sharing an identical ~3,150-token prefix. Run once, peer died. Operator authorized a full re-run; peer restarted; identical arm re-run ~20 min later.

                        run 1                          run 2
  calls 0-3 TTFT        111.8 143.8 156.6 124.2 s      108.2 103.5 108.0 110.9 s
  call 4                no content, 76.7 s             no content, 50.1 s
  calls 5-7             refused                        refused
  marked Offline        11:29:31 (staleness 74s)       11:48:59 (staleness 67s)

FOUR CALLS OF ~3,150-TOKEN PREFILL, THEN THE PEER STOPS ANSWERING. Twice, same call, 20 minutes apart. The failure signature on the originator: peer-manifest transport errors to the peer's bridge port, then `gossip: peer marked Offline` on a 60s staleness threshold.

WHAT IS STILL NOT KNOWN: the MECHANISM on the far side (OOM / thermal / daemon panic). RuggedFox cannot see it. Closing that needs LittleMac's own logs — the one open thread on this finding.

RUN 2 ALSO CLEANED UP A SECOND RESULT: its first four TTFTs are FLAT (~107.6s mean, 7% spread) where run 1's rose. So run 1's rise WAS the peer degrading, and flat-with-identical-prefix is the honest baseline — the prefix-cache absence (note 5ff2a061) now measured directly on the peer path, not inferred from the local probe.

PRODUCT CONSEQUENCE, independent of mechanism: a named request carries `soft=false`, so when its one holder dies the originator REFUSES rather than degrading — no second holder, no local fallback, no retry. The agentic loop stops. Two directions to price before building either: (a) soft-degrade a named request whose holder dies mid-stream (§18.3 — any substitution must be NAMED, never silent; "the model got dumber" is exactly what M6-A was written to catch), or (b) get a second holder for anything a consumer pins, which also makes the min-inflight balance real instead of decorative.

AND THE PEER HAS NO ADMISSION CONTROL. It accepted work until it fell over. That is the same policy surface as the pending X-Node-Id / `yielded_to_local` decision, and this measurement is the argument for arming it.

OPERATIONAL WARNING FOR FUTURE SESSIONS: do NOT drive a sustained agentic-shaped load at LittleMac. Four calls at ~3k-token prefill is the demonstrated limit; it needs a hand on the machine to come back.
