# The SCIP reindexer is an OOM hazard on this host, and the daemon RESTART is what spawns it — not the project registry.

The SCIP reindexer is an OOM hazard on this host, and the daemon RESTART is what spawns it — not the project registry.

2026-09-12: the kernel OOM-killed the daemon mid-`svrn quality check` (`sovereign.service: Main process exited, code=exited, status=137`; `journalctl -k`: `Out of memory: Killed process 4181040 (sovereign-cli-d) total-vm:77036448kB anon-rss:12565656kB ... global_oom ... oom_score_adj:200`). Three lanes then reported "nothing is listening on 127.0.0.1:9741" and retrieval-prod failed — none of which were quality results.

Driver: `rust-analyzer scip` at 12.0 GB RSS. `~/.svrnmesh/logs/watch-commonwealth-ai-scip.log` shows rebuilds of 317-971s triggered by BOTH `git_poll` (a commit) and `startup` (a daemon restart), running CONCURRENTLY, while `svrn project list` read `commonwealth-ai (never built) [REBUILD FAILING x2]` — a failing rebuild retrying at 12 GB a go.

`svrn project unregister commonwealth-ai` does NOT stop it: a new one started 90s later with the registry empty, and another at the exact second a soak restarted the daemon. Until there is a real knob, a long run needs a reaper loop killing `rust-analyzer scip`.

This is the same failure `.sovereign/sovereign.toml` already documents for the lint/test watchers (disabled 2026-05-31: "spikes 10-15GB of rustc ... jetsam-kills the daemon ... observed repeatedly while running the Enron QA synth bench"). That decision never covered the SCIP reindexer.
