# ONCE AN UPGRADED PEER WITHHOLDS ITS SECRET ON PURPOSE, A ZEROED FIELD ON THE WIRE STOPS BEING EVIDENCE OF AN OLD BUILD — and the code that…

ONCE AN UPGRADED PEER WITHHOLDS ITS SECRET ON PURPOSE, A ZEROED FIELD ON THE WIRE STOPS BEING EVIDENCE OF AN OLD BUILD — and the code that read it as one was written before that was true (found + fixed 2026-08-27, branch mesh-multi-membership, P4b).

The shape, which is general: a field's ABSENCE was a reliable proxy for "peer is on an old build" only while every new build still sent it. The moment an optimization made new builds stop sending it, the proxy inverted silently — absence now meant the OPPOSITE — and nothing failed loudly because both readings are well-formed booleans.

Concretely. `MergeReport::peer_pre_split` was `other.mesh_secret == [0u8; 32]`. P4b then added a conditional outbound send: withhold the raw secret from any peer already `peer_confirmed_post_split`. So two upgraded nodes, after one round each, both stopped sending — and each then computed `peer_pre_split = true` for the other. Consequences, all silent:
  1. `rotate_invite` refused on BOTH sides forever, naming a peer that was perfectly modern.
  2. `observe_peer_split_generation(sender, !peer_pre_split)` flipped the map back to false, so each resumed SENDING the credential it had just stopped sending. It oscillates.
  3. The reply-side redaction (keyed on the same field) started firing for the wrong reason, which masked a second bug: the reply never redacted for a peer that proved possession AND still sent its secret — every upgraded pair's first rounds — so the raw secret kept crossing the LAN every 10s while the request half was congratulating itself for having stopped.

The fix is the general one: DERIVE the generation from the authorization DECISION, not from the payload. `GossipAuthArm { Proof, RawSecret, Legacy, Refused }` is returned by `gossip_authorized_with`, stored on the report, and `peer_pre_split = arm != Proof && !other.has_mesh_secret()`. A valid proof settles it — only a holder of the CURRENT secret can produce one — regardless of what the payload carried. The reply then sends the raw secret on the `RawSecret` arm only.

WHAT TO CHECK NEXT TIME: any time you make a sender stop transmitting a field as an optimization, grep every reader that treats that field's absence as a fact about the sender. `commonwealth-api/src/routes_internal/gossip.rs` and `commonwealth-core/src/mesh.rs` each had one, and they disagreed after the change.

Red-first proof (revert the predicate, watch fail, restore): the reply returned all 32 bytes verbatim as `[42, 42, ...]` to a proving caller, and a proving peer was recorded pre-split. Tests: `gossip_route::{an_upgraded_caller_gets_no_raw_secret_back, a_proving_caller_that_withholds_its_secret_is_recorded_post_split}` and `mesh::tests::a_peer_that_proves_possession_is_never_reported_pre_split`.
