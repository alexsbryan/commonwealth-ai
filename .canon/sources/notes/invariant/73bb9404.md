SOVEREIGN-LINT/TEST ON THE HOST IS NOT A GATE — RUN THEM INSIDE THE TOOLBOX (verified both directions 2026-07-28).

`./scripts/sovereign-lint.sh --human` run on the Fedora HOST exits 101 because llama-cpp-sys-4's build script cannot link (`error: linker 'clang' not found`) — and the cargo-check adapter DROPS that failure from its Tier-2 JSONL, so the stream still ends with `{"t":"pass","n":"<crates>"}` and `{"t":"summary","pass":1,"fail":0,...}`. The same command inside the toolbox exits 0.

CONSEQUENCE: the JSONL summary line is not a verdict. GATE ON THE EXIT CODE. I lost time trusting a `pass:1 fail:0` summary that accompanied exit 101.

Correct invocation for this workspace:
  toolbox run -c sovereign-vulkan ./scripts/sovereign-lint.sh --human
  toolbox run -c sovereign-vulkan ./scripts/sovereign-test.sh --human

Two more sharp edges found the same day:
- `sovereign-test.sh --filter` matches the TEST NAME (libtest substring of the full path), NOT the file name. `--filter named_model` against tests/named_model_*.rs matched nothing and exited 4.
- `--package sovereign-compute` fails outright: "the package 'sovereign-compute' does not contain this feature: corpus-engine/treesitter" — the script's feature-scoping does not know that crate. Use plain `cargo test -p sovereign-compute` there.

Also note the watchers are deliberately OFF in this repo (.sovereign/sovereign.toml, disabled 2026-05-31 because the parallel three-workspace cargo fan OOM'd the daemon under a resident big model), so lint_status/test_status report `watcher_down`/`not_configured` and the full scripts are the intended path.
