THE ATOM-ENUM OVERVIEW SCOPE DOES NOT CONTAIN THE CORPUS THE QUESTION IS ABOUT. Measured 2026-08-05 from the `atom_enum_overview` audit event on `bench sep/summarize --prod-pipeline`, all 14 questions, IDENTICAL every time:

  scope_corpora = chaos-saltgrass, arch-principles, chaos-secret-agent,
                  commonwealth-ai-arch-principles, commonwealth-ai-system-overview,
                  commonwealth, alignment, commonwealth-ai, conversation-history

`sep` IS ABSENT. So is every `sep-*`. Nine corpora, every one a Commonwealth/chaos/personal corpus, on fourteen questions about SEP philosophy entries whose final evidence pools are 175 `sep` + 129 `wikipedia` chunks. The injection is STRUCTURALLY INCAPABLE of contributing on-topic evidence on this bank — every chunk it adds is off-topic by construction, and the correct output for these turns is an EMPTY injection.

WHY IT MATTERS BEYOND THIS BANK. `resolve_atom_enum_scope(None, pool_corpora)` is documented as "the corpora this turn actually reached". It is not. `pool_corpora` (retrieval_pipeline.rs:1150) is built from `st.chunks` at the post-noise-floor stage — measured at 533 chunks, pre_floor 632, i.e. the floor drops only 16% — and that pool is RRF-fused, where EVERY chunk scores ~0.024-0.031. RRF rank-agreement scores do not measure relevance (evidence.rs says grounded answers and hopeless declines both live in 0.02-0.08 on that axis), so ordering the pool by them puts `chaos-saltgrass` and `arch-principles` at the TOP for a question about idealism. The scope is therefore drawn from unranked mush, and which corpora land in it is close to arbitrary w.r.t. the question.

THE STRUCTURAL PROBLEM: the discriminating signal (`reweight_by_query_relevance`, which separates on-topic from off-topic by ~20x — 0.70 vs 0.035) runs LATER in the pipeline than the injection. So at injection time there is no good ranking to scope from, and at ranking time the injected chunks are already pinned by `merge_demand_select` (merge_select.rs:121) and cannot be dropped. Ordering, not logic, is the defect.

THE REAL FIX (NOT DONE — needs its own change): move the injection AFTER relevance ranking, and scope it to the corpora supplying the top of the RANKED evidence rather than the raw pool. Then "no on-topic corpus has an atlas" resolves to injecting nothing, automatically, without any threshold. Until that lands, the corpus-level topic gate (`SOVEREIGN_ATOM_ENUM_TOPIC_GRIP`, default 0.5) is a GUARD, not a fix: it stops the defect from putting private notes into a philosophy answer; it does not make the scope correct.

DO NOT re-derive this from `resolve_atom_enum_scope`'s doc comment — the comment is accurate about what the function does and misleading about what it achieves, which is exactly how this survived `fc84c74e`. Read the `atom_enum_overview` audit event from a real run instead: `RUST_LOG=info,retrieval_audit=info` prints `corpora=[...]` per turn.
