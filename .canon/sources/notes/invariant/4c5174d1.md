THREE HOST DIVERGENCES CLOSED 2026-08-25, found by diffing the other hosts against `sovereign-runtime-recipe` on the day it landed (follows fe88e318). This is the argument for TOPOLOGY Phase 6 stated in defects rather than in principle.

=== 1. THE RERANK CAPACITY PRE-FLIGHT RAN ON ONE OF THREE SURFACES ===
`sovereign_inference::reranker_standalone::load_from_env`'s doc comment said: "One loader for every shipping surface. The CLI, the desktop and the hub server all reach the reranker through here, so 'is a reranker installed?' has one answer per process instead of three (ARCH §10.6)." FALSE. The CLI never called it — `chat_cmd/bootstrap.rs` had its own load path, and that path was the ONLY one carrying the VRAM fit check note b57b0cd5 (the 64GB SIGTERM incident) exists to mandate.

Consequence: the desktop and the hub could each load a rerank slot beside a resident primary with nothing checking whether the two fit, and find out from the OOM killer mid-turn. On the hub that takes every tenant's in-flight turn.

FIX (structural): the pre-flight moved INTO `load_from_env`. Return type is now `RerankLoad::{NotConfigured, Loaded, Refused{message}, Failed{message}}` — four arms, not an Option, because "nobody asked for one" and "one was asked for and refused because it does not fit" read identically through an Option and the second is the one an operator must see (§18.3). `SOVEREIGN_SKIP_VRAM_CHECK` still overrides, loudly.

This is the THIRD "comment asserting a mirror that is not one" (§7.2) this program has found, after SOVEREIGN_RPC_CACHE_DIR and SOVEREIGN_WORKSPACE_DIR. Treat that pattern as a search: a doc comment claiming parity is evidence of the opposite often enough to be worth grepping for.

=== 2. THE DESKTOP NEVER SPAWNED THE ATLAS BUMP-FLUSHER ===
`spawn_bump_flusher` had exactly two callers: the CLI recipe and sovereign-server. NOT the desktop — the one long-lived interactive surface. Without it `AtlasContextManager::record_match` accumulates bumps in an in-memory HashMap that is never written, so adaptive triage (Phase B2) was permanently dead there AND the map grew for the life of the session, while the ledger reported the capability available. Fixed (3 lines in state.rs).

=== 3. GLINER EAGER vs LAZY — DELIBERATELY NOT CLOSED ===
The recipe loads `GlinerExtractor::new_default()` eagerly; the desktop uses `LazyGlinerExtractor::new_default_deferred()` (a ~950ms load on a background thread, handle shared with document ingest via `state.entity_extractor`). The desktop's is better. Folding it into the recipe changes WHEN the extractor is warm for the CLI and the server, which is a retrieval-timing change and therefore a bench question, not a build-only one (§18.4). This is the reason the desktop stayed on `UNSHARED_RECIPES` rather than being converted in this pass — converting it is a Phase 6 order that needs `sovereign-ci-bench.sh`, not a refactor.
