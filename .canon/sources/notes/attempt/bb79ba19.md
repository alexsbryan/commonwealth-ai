DEAD CODE: rustc's dead_code pass uses EFFECTIVE visibility — 'pub' inside a private mod was NEVER a root, so demoting it changes nothing (2026-09-02, commit 3adb6bdac).

FALSIFIED. Hypothesis: rustc reports only 73 dead_code warnings across 1.1M lines because 23,064 bare 'pub' decls make everything a root; demote them and the sweep finds the circular clusters. Pre-registered bar: sovereign-cli-llm 48 -> >200 dead items. MEASURED: 48 -> 48. Zero new. 955 compiler-authored demotions across 211 files, harvest nil. Reverted.

WHY. lib.rs there declares 51 private 'mod' and 1 'pub mod'. The crate was already effectively private and rustc had already analysed all of it — which is exactly WHY 'unreachable_pub' fired on 1,956 spans. Corollary that inverts the obvious targeting rule: a HIGH unreachable_pub count means the crate is already private and there is NOTHING to unlock.

WHAT WORKS. Target crates with a WIDE effectively-public surface (long 'pub mod' chains) AND low cross-crate usage. Loop: SCIP proposes demotions (no cross-crate ref), rustc disposes — a wrong one is a COMPILE ERROR, never a silent change, so the candidate list may be a heuristic. The error code classifies: E0603 with a use site under tests/ = public only for tests; E0364/E0365 = re-exported, no consumer; survives = internal, then dead_code judges it.

MEASURED YIELD, sovereign-agent-bench (1,098 symbols, 2 used cross-crate): 182 candidates, 135 stuck, 26 exposed as test-only, dead_code 4 -> 15 unique, 5 fns deleted. ~1 new dead item per 100 symbols. Across the ~40k symbols in blinded crates that projects to ~400 items — consistent with quality/DELETION.md's measured ~9,800-line ceiling, NOT with a 100k-line bloat story.

NOT trap #2. That trap is a hand-built SCIP closure. rustc's is mark-and-sweep on HIR, so traps #1/#3/#4 are handled by construction. Control: parse_message, collect_body, persist_state (trap #2's wrong kills) are absent from rustc's dead list in every configuration measured.
