SEAT MISS — I READ A FAILED COMMAND'S SILENCE AS A FINDING (2026-08-16, BeefyMac seat, financial-corpora, first ten minutes after re-seating post-/clear).

WHAT HAPPENED. Triaging M1b's uncommitted commit (ii), I ran a grep for `PeriodNotAsAsked|calendar_period_in_question|available_period_ends` with `--include=*.rs` UNQUOTED under zsh. zsh expanded the glob, found no match, and aborted the command: `(eval):1: no matches found: --include=*.rs`. The command never ran. I read the absent output as "no test exists", reported to the operator that M1b's commit (ii) had no test, and staged a ruling on it ("I am not accepting commit (ii) without one"). The tests existed the whole time — corpus-engine/src/enrichment/atlas/analysis/sec_facts.rs:893 `every_period_refusal_names_the_periods_that_do_exist` and :920 `calendar_question_is_read_only_in_the_clear_case`. The worker corrected me.

WHY IT MATTERS MORE THAN AN ORDINARY SLIP. This is ARCH §18.3 — a tool that FAILED and a tool that FOUND NOTHING returned the same thing to me (an empty result), and I collapsed the two into the success-shaped reading. That is the exact failure class this initiative exists to eliminate in the product: the seat committed, against a worker, the error the workers are being held to. It is also §18.1 — I did not have a failing input I could name; I had an absence.

THE FIX IS STRUCTURAL, NOT A RESOLUTION TO BE CAREFUL. In this shell, `grep --include` globs MUST be quoted (`--include="*.rs"`). More generally: a search that returns nothing is only evidence if the search RAN. Check the exit code, or make the tool prove it ran (grep a term you KNOW is present in the same call). Cheapest durable form: prefer `symbols`/`code_search` over shell grep for "does this symbol exist" — they cannot fail into a plausible empty.

SECOND-ORDER LESSON FOR THE SEAT SPECIFICALLY: I relayed an unverified negative to the operator INSIDE the same report where I correctly described spot-verification as the seat's duty. A negative finding ("X does not exist") deserves the same verification bar as a positive one, and is easier to get wrong, because nothing pushes back. The worker pushing back is the only reason this was caught within minutes.
