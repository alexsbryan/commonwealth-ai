NOT DONE, with reason: tagging synthesis "soft-landing continuation" calls with a workload request id (issue #57 rec 3, 2026-09-02). The knowledge-path draft request carries `oicp: None` on purpose (SLOT_POLICY §3.1: envelope-absent = LocalOnly) and `continue_truncated_synthesis` clones it, so continuations log `oicp_request_id=` empty (G1: three untagged calls of 46/34/42 s). The routing log reads the tag only from the envelope, and `oicp_select::pick_slot_for_oicp` returns `Speed::Slow` unconditionally when the envelope is ABSENT but runs `pick_slot_v03` (effective hint + latency-class matching against fast/slow slot profiles) when one is PRESENT — so an id-only envelope on a continuation could move it from the primary to the fast slot mid-answer. A glassbox tag is not worth a silent slot change. The right shape is to give the knowledge-path draft a `Workload::Synthesize` envelope with an explicit latency class (then continuations inherit the tag), which is a routing decision on the turn's main call and belongs with the slot-level order (rec 4), not here.
