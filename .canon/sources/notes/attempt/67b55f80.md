ROOT CAUSE (diagnosed, NOT fixed). `fixture_corpus()` uniquifies its temp dir with a per-process `static SEQ: AtomicU64`, then writes `std::env::temp_dir().join(format!("mf_attribution_unit_fixture_{n}"))`. Under `cargo test` that works — one process, so each test in the module draws a distinct n. Under nextest, which runs each test in its own process, SEQ restarts at 0 in every process, so every test in the module targets the SAME path `/tmp/mf_attribution_unit_fixture_0` concurrently. One test's create_dir_all/write races another's read and build_probes sees an empty atlas.

FIX WHEN SOMEONE PICKS IT UP: uniquify by something process-unique (pid, or a tempfile::TempDir) instead of a per-process counter. Any other test in the repo using a per-process atomic counter to name a shared-filesystem path has the same latent bug — the counter is exactly the wrong uniquifier under a process-per-test runner.
