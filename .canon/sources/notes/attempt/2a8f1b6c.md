SEAT MISS — shared-working-tree commit collision (2026-08-13, RuggedFox seat, order mesh-scale-t1-red). What happened: seat spawned the t1-red worker, THEN noticed the Tier-1 bar declarations were uncommitted, and committed them intending main — but the worker had already checked out its branch in the SHARED working tree, so a6b18cdb landed on mesh-scale-t1-red, not main. The seat then reported "committed to main as a6b18cdb" to the operator — a false claim, corrected in the landing docket. No damage: the commit's parent was main's tip (075be464), the worker's chain built on it, and everything reaches main in the landing ff-merge. CASE LAW (third instance of the shared-tree class — BeefyMac note 5ad3577d is the peer precedent): the seat MUST run `git branch --show-current` before any seat-side commit while a worker subagent is active in the same checkout, and prefer either (a) committing BEFORE spawn (the sequencing that was actually needed here), or (b) worktree isolation for workers that switch branches. The deeper fix is (a): declarations an order depends on are part of the order's substrate and belong on main before the spawn message is sent.
